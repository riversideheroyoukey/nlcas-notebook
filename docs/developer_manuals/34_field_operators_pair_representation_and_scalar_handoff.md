# 34. 場の演算子・対表現・スカラー handoff — そもそも論の記録

**日付:** 2026-07-31
**性格:** 設計議論の記録（実装前）。[33](33_time_dependent_operators_and_green_functions.md) の続き。
**結論の要約:** 利用者の希望（スピン添字付き場の演算子 → 相互作用表示 → 温度グリーン関数）に対し、
(A) 単一 Julia セッションで完結させる道＝**対表現**と、(B) スカラーに到達した時点で
**Maxima セッションへ handoff する道**の2つを整理し、**当面の本線を (B) と決めた**。
(B) は BP-2（SymPy への留数・部分分数移植）を不要にする。

---

## 1. 出発点 — 利用者の希望と、Julia の現状

希望は3段:

1. スピン添字付きの場の演算子（`a_{i,\sigma}(t)`, `\phi_\sigma(x)`）を扱いたい
2. 相互作用表示を経て
3. （温度）グリーン関数を使いたい

Julia/QuantumAlgebra の現状（実測は docs/33 と
julia_backend_handoff.md (reference omitted from the public snapshot) §2）:

- `a_{i,s}`（多重添字、適用なし）は動く。**スピン添字自体は問題ではない**
- `a_{i,\sigma}` は σ→s 正規化が生成器経路に掛かっていないだけ（小口）
- `a_{i,s}(t)` — 適用形が表現できない。QuExpr は callable でなく、
  引数を添字に畳むと δ 代数が付いて異時刻反交換子が δ(t,t') になる（却下済み、docs/33 §4）
- QA は c-number を保持できない（`exp(-im*eps*t)*c(1)` → `exp(0)*cos(...)` に分解）

**壊れているのは「時間（引数）の付いた演算子」であって、スピン添字ではない。**

## 2. そもそも `A(t)` は保存すべき記号ではなく、操作の結果（対表現）

docs/33 §5 の立て直しをそのまま設計にする。物理側の構造:

$$A_I(t) = e^{iH_0t}Ae^{-iH_0t} = \sum_m f_m(t)\, O_m$$

`H_0` が二次形式なら **`O_m` は有限個の QA 演算子で閉じ、`f_m(t)` は純スカラー**
（対角ならスカラー指数、非対角ならモード添字上の行列指数——実測済み）。
相互作用表示という概念の存在理由が、この「演算子部（厳密・QA）とスカラー係数
（再総和・スカラー CAS）の分離」そのものである。

**内部表現は「(スカラー係数, QA 演算子) の対の和」**。`a_{i,\sigma}(t)` はその表示に
過ぎない。`integral_descriptor` / `lattice_descriptor` と同じ
「表示は利用者の記法、実体は遅延評価される構造」パターン。QA に時間を持たせる必要は無い。

この表現なら異時刻代数が構造的に正しく出る:

$$\{c_I(t),\,c_I^\dagger(t')\} = f(t)\overline{f(t')}\,\{c,c^\dagger\} = e^{-i\varepsilon(t-t')}$$

——係数の積 × 等時刻代数。δ(t,t') に潰れる罠（畳み込み案）を踏めない。

係数の置き場所は in-session SymPy 経路（QA は c-number を保持できないため）。
これは BP-4 の一般化であり、JULIA-INDEXED-SCALAR（非束縛 `xi_k` の住処）の答えも
同じ場所に出る。

### 2.1 実装状況（2026-08-22、第1〜2スライス）

**`ad_H` の連鎖が有限個の演算子で閉じる場合を、打ち切りなしで厳密に。** 係数は
`exp(itM)` の第1行——連鎖が線形常微分方程式であることの、そのままの言い換えである。

```
対角 H_0 = Σ_n ε_n c†_n c_n
  c_m   →  e^{-i eps_{m} t} c_m                    （1×1）
2サイト H = w(c†_1c_2 + c†_2c_1)
  c_1   →  cos(wt) c_1 - i sin(wt) c_2             （2×2、教科書どおり）
原子極限 H = U n_1 n_2
  c_1   →  c_1 + (1 - e^{-iUt}) c†_2c_1c_2         （= c_1[(1-n_2) + n_2e^{-iUt}]）
```

| 要素 | 実装 |
|---|---|
| 閉包の歩き | `julia_build_mixin._build_heisenberg_operator` —— `ad_H` を回し、各項から**素の演算子**を作り直して（QuTerm の params を空にして QuExpr を組み直す）基底の同一性を見る。残った数値とパラメータがその成分。上限 `CLOSURE_CAP` まで閉じなければ `NOTCLOSED` |
| 係数 | `pair_exponential_command`（SymPy）—— `exp(itM)` の第1行を**値と LaTeX の対**で返す。表示も SymPy 自身の latex を使う: 同じ量の綴りを2箇所で決めないため |
| 係数の簡約 | `scalar_simplify_command`（SymPy）—— 括弧で同じ演算子に落ちた係数の和をまとめる。`cos(wt)cos(wu)+sin(wt)sin(wu)` → `cos(w(t-u))` |
| 純ロジック | `notebook/runtime/pair_representation.py` —— 判定結果の解釈・λ の綴り・`e^{iλt}` の組み立て・表示・記述子。CAS 非依存で、CAS を起動せずに固定できる |
| 記述子 | `Expression.pair_representation`（`integral_descriptor` と同じ追加型）。**由来をスナップショット**する: どの演算子を、どの H のもとで、どの時間変数で |
| エンジン | `notebook/engine_pair_rep_mixin.py: heisenberg_operator(A, H, t)` |
| NL | `ui/interpret_pair_rep.py`＋`i18n/nl_patterns.json` の `heisenberg_operator_nl`（日英） |
| 断り | 連鎖が閉じない場合は理由付きで拒否（`pair_rep.chain_does_not_close`）。**打ち切った級数は短時間展開であって摂動論ではない**（docs/33 §6.2）ので、黙って返さない |

**閉じても信用しない場合がある（実測 2026-08-22）。** 一般の2体項
`\sum_{pqsn} V_{pqsn} c†_pc†_qc_sc_n` に対して歩きは「閉じた」と答えるが、その基底は
`∑₁ δ(1q) c†(#₁) c(n) c(s)` ——**和の印と自由添字を抱えたまま**で、文字列一致で
1つの演算子と数えていただけである。そのまま係数を組むと別々の行列要素が同じ記号に
潰れ、`c_1 + i V_{1qsn} t c†_q c_n c_s - i V_{} t ∑₁ …` という**誰も書いていない量**が
答えとして返る。`closure_is_concrete` が和の印を見て断る（`pair_rep.chain_is_not_concrete`）。

**踏んだ罠**: 被演算子を `static_index_mode` で生成すると**束縛和の ∑ が落ちる**。
対角ハミルトニアンが単項になり、その交換子は δ を消費できないまま残すので、
判定は永遠に「閉じない」と答える。生成モードを変えて解決（`_src` のコメント）。

**先行条件についての訂正**: この起票は「BP-2 の実測（SymPy 経路に留数・部分分数・和が
あるか）が先行条件——出口が無ければ `heisenberg_operator` を作っても `G(ω)` に
到達できない」としていた。**出口は 2026-08-02 から存在する**（SCALAR-HANDOFF、
係数がスカラーになった時点で Maxima セッションへ渡す）。BP-2 はこの目的では不要に
後退済みで、先行条件は満たされている。

### 2.2 異時刻代数（第1b スライス、2026-08-22）

**この表現が構造的に正しいことの見どころ**が実際に出る。`pair_bracket(kind, A, B)`
は演算子部の代数を**既存の** `commutator` / `anticommutator` にそのまま渡し、
この層は係数を掛けるだけ:

```
{c_m(t), c†_m(u)}  →  e^{-i eps_{m} t} e^{i eps_{m} u}      ← 演算子が消えてスカラー
[c_m(t), c†_m(u)]  →  e^{-i eps_{m} t} e^{i eps_{m} u} (1 - 2 c†_m c_m)
{c_m(t), c†_m}     →  e^{-i eps_{m} t}                      ← 片側だけの時間発展
```

- **反交換子の結果は演算子を含まないスカラー**なので、そのまま SCALAR-HANDOFF で
  Maxima セッションへ渡せる（実測: 渡り、宣言も符号込みで同行する）。
  「表示されたものは使えるはず」——行き止まりではない。
- **和になった演算子部は括弧で囲う**。`e^{…}e^{…} 1 - 2c†c` は別の式として読める。
- **対が持つ演算子は研究者の綴り**（`c'(m)`）であって QA の印字（`c†(m)`）ではない。
  印字形を戻すと `{c(t), c†(t')}` が **0** になった（実測 2026-08-22）——結果は
  入力として読み直せる形でなければならない、という既存の規則がここにも効く。
- **一般操作は対を断る**（`pair_rep.display_only_pair`）。係数はスカラー、演算子は
  QA 側で、CAS はその2つを一緒に持てない。直前まで生の
  `Bracket expressions in Julia must have exactly 2 arguments` が返っていた。

**多項どうしの括弧も通る（第2スライスで解禁）。** 項の組み合わせすべての和を取り、
同じ演算子に落ちた係数をスカラー側でまとめる:

```
{c_1(t), c_1†(u)}  →  cos(w(t-u))     ← 2サイト模型の自由伝播関数
```

**残り**: 場の演算子（§3、∇→ik と直交性縮約）。

## 3. 場の演算子 `\phi_\sigma(x)` — 対表現の一例だが、係数層への要求が増える

$$\phi_\sigma(x) = \frac{1}{\sqrt{V}}\sum_k e^{ikx}\, a_{k,\sigma}$$

モード関数（スカラー）× QA 演算子の**束縛和**。`e^{ikx}` は QA に置けない
（§1 の c-number 分解がそのまま当てはまる）ので、これも係数層が前提。

**`a(t)` と違う点: `x` には微積分が来る。**

- `\nabla\phi` → 係数層で `e^{ikx}` に ∇ が当たり `ik` が降りる
- `\int dx\, \phi^\dagger\phi` → 直交性 $\int dx\, e^{i(k-k')x} = V\delta_{kk'}$ で
  モード添字が縮約され `\sum_k a^\dagger_{k\sigma}a_{k\sigma}` に落ちる

この2操作は閉じた機械的規則で、係数層（SymPy チェーン拡張）に置ける見込み。
実務上も代数は k 空間で行われ、実空間は入口（H の定義）と出口
（`G(x-x') = \sum_k e^{ik(x-x')}G(k)`）にしか現れない——設計もそれに合わせる。

**役割分担の正確な言い方**（誤解しやすいので明記）: 「基底変換するから QA が要らない」
のではなく、**「QA が扱える基底（モード演算子）に降ろしてから QA に渡す」**。
降ろすまでは係数層、降りた後の演算子代数は全部 QA。φ 自身の代数
（$\{\phi_\sigma(x),\phi^\dagger_{\sigma'}(x')\}$）も、展開 → QA が
$\{a_{k\sigma},a^\dagger_{k'\sigma'}\}=\delta_{kk'}\delta_{\sigma\sigma'}$ →
係数層が $\frac{1}{V}\sum_k e^{ik(x-x')}$ を δ の箱規格化表現にまとめる、で出る。

**`x` を添字に畳んではいけない（時間より罠が深い）。** 等時刻の
$\{\phi(x),\phi^\dagger(x')\}=\delta(x-x')$ は QA の添字 δ が**一見正しい答えを返す**。
それでも却下する理由:

1. QA の δ は Kronecker、場の理論は Dirac——`1/V` 規格化が黙ってずれる
2. 添字スロットに微積分はできない（∇φ も ∫dx も死ぬ）
3. 後で時間を付けた瞬間、δ(t,t') 罠に合流する

**決めるべきこと3つ**（単一セッション路線＝PAIR-REP に着手する場合）:

1. **規格化のモデル選択の明示化**: 箱規格化（`\sum_k`・Kronecker δ）を内部標準に。
   連続極限 $\sum_k \to \frac{V}{(2\pi)^d}\int dk$ は利用者の物理選択として
   明示ステップ（No hardcoded modeling choices、BP-4 ③と同じ立場）
2. **モード関数は利用者が決める**: 既定は平面波、descriptor に持たせ差し替え可能に
   （Wannier・調和振動子基底）
3. **係数層の2操作**（∇→ik、直交性縮約）の実装位置

### 3.1 決定（2026-08-22、利用者）

1. **箱規格化を内部標準**とする（上の推奨どおり）。連続極限は明示ステップ。
2. **モード関数に既定を置かない——必ず利用者が指定する。** 上の推奨（既定は平面波）
   より厳しい側を採る。理由は前半のシナリオの立場と揃うこと: あそこでは基底は
   **任意**のまま書き、あとで「$\hat H_0$ を対角化するものを選んだ」と明示した。
   既定の平面波を黙って置くと、その「選んだ」という一手が消える。
   **帰結**: `∇→ik` は平面波と**宣言されているときだけ**当たる規則になる
   （推測が要らない代わりに、宣言のない場に対しては理由付きで断る）。
3. 係数層の2操作は、対表現と同じ場所（`pair_representation` の隣）に置く——
   どちらも「係数はスカラー、演算子は QA」の同じ線の上にある。

## 4. バックエンド移行の一般論 — リプレイとしてなら原理的に可能

問い: 「操作の保存が利用者記法の数式だけで CAS 形式が無いなら、定義を与え直せば
バックエンドを移行できるのでは？」

答え: **原理的に可能。移行＝「操作ログを新バックエンド上でリプレイする」**。

| 保存されている層 | バックエンド依存性 | 移行時 |
|---|---|---|
| 利用者の書いた式（canonical / latex） | 中立 | そのまま持てる |
| 共通操作（semantic operation） | 中立（原則#3） | 新バックエンドの builder で再レンダリング |
| CAS の返した結果（`_nb_Ek` 等） | 依存 | 持ち込まず再計算 |

原則#6（途中切替禁止）の根拠は「既存の式表現が無効になる」ことで、リプレイは
全部作り直すので抵触しない。ファイルスナップショット fork の親戚
（「新ファイルに、別バックエンドで、履歴を再実行」）。

**壁は3つ:**

1. **操作カバレッジの非対称**（本丸）: 演算子代数は Julia 専用、residue/assume/ode2 は
   Maxima 専用。リプレイは最初の非対応操作で止まる。移行の動機がたいてい
   逆方向の非対応操作そのものなので、「全履歴」より「ステップ N までの系譜」が現実的
2. **結果の形に依存した後続ステップ**: 式 ID 参照は安全だが、前の結果の綴りを見て
   書かれた操作（結果形に合わせた substitute の lhs 等）は新バックエンドで
   一致しなくなり、**silent-wrong になりうる**（substitute は不一致でも success を返す）
3. **意味論の差**: Maxima 代入時評価 vs Julia 構造保持（docs/03）。検証対象

成立させるなら: 差分検証を義務化（実 CAS の差分、文字列比較不可）・止まったら理由付きで
止まる・宣言の与え直しを対話にする。

## 5. 本線の決定 — スカラー handoff fork（Julia → Maxima）

利用者の実際の目論見は全履歴移行ではなく、
**「Julia セッションの温度グリーン関数計算が解析的なスカラー式に到達した時点で、
その式を Maxima にやらせる」**だった。これなら:

- 渡るのは**演算子を含まないスカラー式が数本**。§4 の壁①は消える
  （Wick 後の松原和・留数・部分分数は全部スカラー CAS の仕事で、Maxima 側は実測済みで動く）
- docs/33 §7 の役割分担表を、**セッション境界で**実現する形
- BP-4 の「代替」欄（「当面はスカラー閉じ込めを別 Maxima セッションで行う」）の
  手作業を一級の機能に昇格させることに相当
- 前例がある: `NumericTask` の fork（canonical/latex/assumptions/branch を
  スナップショットして別層に渡す、provenance は後の編集に耐える）と同じ形

**必要なもの4つ:**

1. **持ち出し形式**: Julia 結果の canonical は `_nb_Ek` なので、渡すのは利用者記法の
   表示形。docs/32 の境界修復（表示は利用者自身の記法で閉じる）が前提として効く。
   受け側は Maxima の `latex_to_canonical` 経路
2. **定義の与え直し**: `\xi_k`, `\Delta`, `\omega_n` 等を Maxima 側で再登録。
   必要記号の列挙は既存の未定義記号検出を流用し、まとめて訊く対話に
3. **Provenance**: 元セッション・ステップ・ブランチへの参照をスナップショット
   （NumericTask と同じ規律）。論文執筆ユースケースでの本体価値
4. **検証**: バックエンドを跨ぐので `ratsimp(差)=0` を片側で取れない。
   数値スポットチェック（両セッションで同じ点を代入して一致確認）。
   N-1 数値層のテンプレート経路をグラウンドトゥルースとして流用できる見込み

**純スカラー判定は全自動不要**: handoff は利用者が式を明示的に選んで発動する操作なので、
「演算子が残っていたら理由付きで拒否」で足りる（BP-4 難所①の全自動検出は要らない）。

### 5.1 実装状況（2026-08-01、第1スライス）

| 要素 | 実装 |
|---|---|
| 記述子＋来歴 | `notebook/models/handoff.py`（`ScalarHandoff`／`HandoffDeclaration`）。項目は `NumericTask` に合わせた——どちらも「式が理論タイムラインを離れて別の場所で続く」ため |
| 渡してよいかの判定 | `notebook/runtime/scalar_handoff.py: operator_symbols` — **演算子が残っていたら理由付きで拒否**。`kind=="operator"` だけでなく**統計（fermi）でも**判定する（粒子名経由の宣言は kind ではなく statistics を持つ） |

### 5.2 第2スライス（2026-08-01）— NL 経路と「何を渡すか」の訂正

**NL トリガ**（`ui/interpret_handoff.py`、`i18n/nl_patterns.json` の
`scalar_handoff_nl`、日英）: 「`E5` を Maxima セッションに渡して」／
`hand E5 off to a Maxima session`。ルールベースで LLM の前。**どの式が渡るかは
利用者の選択そのもの**——それを推測すると、演算子検査を「検査」で済ませられる
（BP-4 の自動検出が要らない）という設計の前提が崩れる。割り込みは
`numeric_fork_nl` の隣に置いた（どちらも「式が理論タイムラインを離れて別の場所で
続く」形で、対象を明示的に名指すので通常の計算依頼を飲み込まない）。

**渡し先は開かない。** ファイルを作って名前を返すだけで、元のセッションは
そのまま（`/fork` と同じ形）。計算の途中で元セッションの文脈を畳むのは、
利用者がいちばん望まない瞬間だから——③の UX 判断はこれで決着。

**測定で設計が1つ変わった（「何を渡すか」）。** 当初は**式に現れる記号だけ**を
持ち出していたが、NL 経路の end-to-end テストが落ちて分かった: S-c の続きは
運んだ被積分関数を **`omega_D` まで**積分するのに、その上限は式に現れない。
持ち出されないので渡し先では未宣言となり、**未宣言の添字は添字として読まれる**ため
答えが `asinh(omega(D)/Delta)` になった——エラーはどこにも出ない。
**宣言は値ではない**ので作業中の c 数宣言をひと通り運ぶことにした（演算子は除く）。
手作業の測定（§6）が Delta・V・N_0・omega_D・xi を宣言していたのと同じ姿。

### 5.3 第3スライス（2026-08-02）— 渡りの検証

§5 の④。バックエンドを跨ぐので **`ratsimp(前 - 後) = 0` は使えない**（別プロセス・
別記法）。比べられるのは**ある点での値**で、2つの canonical から数値層の
ホワイトリスト変換（`canonical_to_numpy`）を通して2回計算して突き合わせる
（`verify_crossing`）。

**何を保証し、何を保証しないかを明記する。** これが見ているのは**渡りそのもの**
——持ち出し→読み直しの往復が別の式に化けていないか——で、本プロジェクトが
繰り返し見つけてきた失敗の形そのもの（docs/32 の `\frac{1}{\sqrt{x}}` →
**積** `frac1*sqrt(x)`、§5.2 の未搬送宣言による `omega_D` → `omega(D)`）。
**2つの CAS 同士を突き合わせるものではない**——それには各セッション内の数値評価が
必要で、別の仕事。

**検証できない場合を「一致」と書かない。** 数値ホワイトリスト外（`asinh` など）の
式では検査が走らないので、その旨と理由を返す（`not_checkable`）。渡し先の
タイムラインにも結果をそのまま記録し、NL の応答にも出す。

**numpy はアプリ venv に入れない**（数値層は専用 `.venv-numeric`、CLAUDE.md の規律で
SymPy と同じ扱い）。スカラーの一点評価に配列は要らないので、変換器が出しうる
numpy 名だけを `math` に写す小さな shim を使う。shim に無い名前は
AttributeError となり、`not_checkable` として報告される——**一致として報告されない**。

### 5.4 第4スライス（2026-08-02）— UI ボタン

### 5.5 S-c を機構経由で再走（2026-08-03）— 2件の欠陥、うち1件は S-c を完全に止めていた

§6 の手動測定を**機構経由で**やり直した。手作業では手で転記したので、演算子検査も
値照合も一度も通っていなかった——**機構化したものは機構で走らせないと確かめたことに
ならない**、という当たり前のことが2件の欠陥として出た。

**① ラベル付きの結果が拒否されていた（S-c は完走できなかった）。**
真空期待値の結果は `c(-k,d) c(k,u) = uv/(u²+v²)²` という**ラベル付き等式**で、左辺は
「何の期待値か」を示すラベル。演算子検査が行全体を走査して左辺の `c` を見つけ、
「演算子が残っている」と断っていた。**期待値は定義上 c 数**なので、この機構が渡すために
作られた当のものを追い返していたことになる。

検査対象を**値（右辺）**にした（`scalar_handoff.split_export_form`、トップレベルの `=` で分割。
`\sum_{k=1}` のような波括弧内の `=` は区切りにしない）。**検査の緩和ではない**——値に演算子が
あれば従来どおり拒否する。演算子ラベルは登録せず、渡し先のメモに「〜の値」として残す
（`ScalarHandoff.source_label_latex`）。H-1 の `H = J x y` のように**ラベルが記号名**なら
従来どおり等式ごと渡る。

**② 照合できないものを「不一致」と報告していた。** 照合の元側に `source_canonical` を
使っていたが、Julia の結果のそれは不透明ハンドル `_nb_E16`。free_symbols が食い違うので
`differed` と判定され、**正しい結果に「元の式と一致しません」と警告**していた。
§5.3 は「検証できない場合を一致と書かない」を決めていたが、**その裏返しも同じくらい重要**
だった——正しい結果を誤りだと告げるのは、黙っているより悪い。

元側の LaTeX を**元のバックエンドのハンドラで**読んだ結果と突き合わせるようにした
（`source_value_canonical`）。元ハンドラと渡し先ハンドラという2つの独立した読みの一致こそ、
この検査が見たい往復そのもの。ハンドルしか無ければ `not_checkable` と言う。

**結果:** ST-1〜12 完走。異常平均 $uv/(u^2+v^2)^2$ → handoff（宣言5件、**値照合 agreed 3点**）
→ $\int_0^{\omega_D}d\xi/\sqrt{\xi^2+\Delta^2}=\mathrm{asinh}(\omega_D/\Delta)$ →
**$\Delta=\omega_D/\sinh\frac{1}{N_0V}$**。シナリオとして
`docs/scenarios/scenario_bcs_gap_equation_{jp,en}.md` に固定した（S-c は 🟢 へ）。

**含意 — BP-2 の位置づけが変わる。** (B) を本線にする限り、グリーン関数のために
SymPy へ留数・部分分数を移植する必要は無い。BP-2 は「単一 Julia セッションで
完結させたい」需要（＝PAIR-REP 路線）が顕在化したときの課題に戻る。
julia_backend_handoff.md §5 が提案していた「まず BP-2 を実測」は、この決定により
(A) 路線に着手する場合の先行条件へ後退した。

**最初の一歩**: S-c（BCS ギャップ方程式——演算子部完了・スカラー和が残って止まっている）を
**手動 handoff で一度通し**、どこで引っかかるかを測る。

## 6. S-c 手動 handoff の実測（2026-07-31 実施）

§5 の「最初の一歩」を実施した。S-c の保存セッションは存在しなかったため、
`docs/scenarios/scenario_bcs_hamiltonian_jp.md` の scenario ブロック（生成の単一
ソース）を実 Julia で再駆動し、その先を継続した。

**再現手順**（`sessions/` は追跡外なので、記録はこの節が正本）:

```
[Julia セッション / domain=condensed_matter]
  scenario_bcs_hamiltonian_jp.md の scenario ブロック全行   # ST-1〜ST-7
  c(-k,d) c(k,u)                                          # 対の積を登録 → E14
  E14 の c(k,u) に E8 を、c(-k,d) に E10 を代入する          # g 基底へ
  @op: vacuum_expectation {"expr": "E15"}                  # → uv/(u^2+v^2)^2

[Maxima セッション / domain 指定なし]
  Delta / V / N_0 / omega_D を正の実数とする、xi を実数とする
      ↑ 2026-08-01 以降はこの宣言だけでよい。それ以前は omega_D の「正の」が
        ダイアログ経由で消えたため、明示の「omega_D > 0 と仮定する」等が要った（§6.2 ①）
  1/sqrt(xi^2 + Delta^2)
  E1 を xi で 0 から omega_D まで定積分して                  # → asinh(omega_D/Delta)
  1 = N_0 * V * (asinh(omega_D/Delta))
  E3 を Delta について解いて                                # → omega_D/sinh(1/(N_0*V))
```

### 6.1 結果 — handoff は端から端まで成立する

| 側 | 到達点 |
|---|---|
| Julia | シナリオ7ステップ完走 → 対角化 H（対生成項係数 $-\frac{\Delta(u^2-v^2)+2uv\xi}{(u^2+v^2)^2}$）→ **異常平均 $\langle c_{-k\downarrow}c_{k\uparrow}\rangle = \frac{uv}{(u^2+v^2)^2}$**（E16、2026-06 の到達点を再現） |
| 転記 | Bogoliubov 条件・ギャップ方程式を利用者記法で持ち出し（結果の canonical は `_nb_Ek` なので **latex 表示形を使う** — 設計どおり） |
| Maxima | 宣言与え直し＋**明示 assume** → 定積分 $\int_0^{\omega_D}\frac{d\xi}{\sqrt{\xi^2+\Delta^2}} = \mathrm{asinh}\frac{\omega_D}{\Delta}$ → solve → **$\Delta = \omega_D/\sinh\frac{1}{N_0 V}$（BCS 閉形式）** |

### 6.2 摩擦点（このために測った）

**Handoff 機構が吸収すべきもの:**

1. **宣言の与え直しは実際に必要**で、しかも**符号（assume）が別途要った**。
   「omega_D を正の実数とする」が添字確認ダイアログ経由になると assume が飛ばず、
   `integrate` が符号質問で**30秒タイムアウト**し、以後のコマンドも巻き添えで
   タイムアウトした（セッションが実質詰まる）。当時は明示の「omega_D > 0 と仮定する」で回避。
   → handoff の定義対話は**型と符号の両方**を運ぶこと。
   **2026-08-01 根治済み（SIGN-DIALOG-ASSUME、open_items アーカイブ）:** 実測すると
   2つの独立した欠陥で、①ダイアログの**候補**の args だけ修飾語が補われておらず
   「正の」も「実数」も消えていた（日英とも、エラーなし）②符号が未知のとき Maxima は
   質問して stdin で待ち、書き込み済みのブロック残行が無効回答として食われてセッションが
   死ぬ。②は**代わりに回答せず** SIGINT で中断し、訊かれた内容を引用して断るようにした。
   差分検証として、**明示 assume を1行も書かない上記の手順がそのまま閉形式まで通る**。
2. **ドメインは運べない**: condensed_matter を渡すとバックエンドが Julia に戻る。
   handoff 先セッションのドメイン/バックエンド指定は設計事項。
3. 持ち出しは latex 表示形ベースで実際に機能した（docs/32 の境界修復が前提として効いた）。

**独立の欠陥（handoff とは別に直すべき、silent-wrong を含む）:**

4-5. **EQ-EMBEDDED-NOTATION**（当初 EQ-SUM-RAW / EQ-INT-MANGLED として2件で起票）:
   canonical に生／壊れた LaTeX が残る（`V \sum_k*u*v`、
   `1 = N_0*V*%int_0^(omega_D) \frac1*sqrt(...)`）。
   **2026-08-01 根治。ただしここに書いた見立ては実測で偽だった**——「等式形だから」
   でも「`\sum` が壊れる」でもなく、`\sum` は正しく `sum(x(i), i)` に降りていた。
   真因は LaTeX→canonical の2規則（`\frac` が入れ子波括弧を読めない／`\i`→`%i` が
   `\int` の接頭辞に当たる）で、**等式は無関係**だった。詳細は open_items の
   アーカイブ。教訓は毎度と同じで、**起票の記述ではなく現物を測る**。
6. **H1-ALIAS-EID-LEAK**: `Delta` を H-1 で定義した後、別の式で `Delta` と書くと
   表示・canonical に **`E17`（内部 E-id）が漏れる**（`xi_k^2 + E17^2`）。
   **2026-08-01 根治**（open_items アーカイブ）。再現条件は**テキスト入力かつ
   H-1 に載らない式**——ここで踏んだ `1 = …` はまさにその形。真因は
   「LLM に渡すための置換」の結果をそのまま登録していたこと。
7-8. **S-C-MEASURE-RESIDUALS**（小2件）: 連立が解けないとき `[]` が理由なしで
   式として登録される／定積分の NL が TeX 綴り（`\xi`）にマッチしない。
   **2026-08-01 根治**（open_items アーカイブ）。8 は測り直すと**変数変換の経路にも
   同じ穴**があり（`r,\theta` で極座標の自動範囲算出が効かない）、そちらも直した。
   積分変数の綴りの残り（Unicode ギリシャ・未宣言の添字つき）は
   **INTEGRAL-VAR-NOTATION** として分離（Julia を含めて後日まとめて）。

### 6.3 判断材料としての結論

- **SCALAR-HANDOFF は物理的に成立し、Maxima 側の道具は全部足りる**（BP-2 不要の確認）。
- 手作業で約10コマンド。機構化の本体は §5 の4項目のうち
  **②定義与え直し（＋符号）と①持ち出し**で、④検証（数値スポットチェック）が残実装。
- 上記 4〜6 は handoff 以前の入力系の欠陥で、**登録が成功してしまう**ぶん
  優先度が高い（4・5 は silent-wrong の形そのもの）。4-5 は 2026-08-01 に根治、
  残るのは 6〜8。
