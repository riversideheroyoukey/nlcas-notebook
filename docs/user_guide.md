# ユーザーガイド

CAS支援付き理論研究者デジタルノートの操作説明です。

> **通らなかったときは:** 計算を**断っている**処理は
> [docs/refusals.md](refusals.md) に一覧してあります——記法ごとに、なぜ断って
> いるか、回避策、そして**その拒否が暫定か確定か**（暫定＝CAS が primitive を
> 持たないだけで、自前実装すれば通るもの）が書いてあります。

---

## 起動

```bash
./scripts/start.sh
```

ブラウザが自動で開きます。開かない場合は `http://localhost:8000/notebook.html` を直接開いてください。

Ollama（LLM supervisor）は起動時に自動で立ち上がります。

## セッションの開始と研究分野の選択

### 新規セッションを始める

ヘッダーの「+ New」ボタンをクリックすると新規セッションダイアログが開きます。

1. **セッションタイトル**（省略可）を入力する
2. **言語**を選択する（English / 日本語）— デフォルトは English
3. **研究分野**（省略可）をカテゴリ別のチェックボックスから選択する
4. 「Start」ボタンをクリック

研究分野を指定しない場合は汎用プロンプトのみで動作します。

### 表示言語の切り替え

表示言語はセッションごとに設定します。言語を変更したい場合は「+ New」ボタンで新規セッションを作成し、言語セレクタで目的の言語を選択してください。セッション開始後、UI の全要素（ボタン・ラベル・メッセージ）が即座に切り替わります。

デフォルト言語は `config/default_settings.json` の `"language"` フィールドで変更できます。

### 研究分野の効果

分野を指定すると、その分野に対応するプロンプトヒントが起動時に LLM へ自動的に送られます。

| コンポーネント | 注入されるヒント |
|---|---|
| LLM Supervisor | `supervisor_hint.txt` — 分野固有の記号・慣習の説明 |
| OCR エンジン | `ocr_hint.txt` — 分野固有の手書き記号の認識ヒント |

例: **解析力学**を選択した場合、`q`, `L`, `H` などの文字が一般化座標・ラグランジアン・ハミルトニアンとして解釈されやすくなります。

### 複数の分野を同時に指定する

チェックボックスで複数の分野を選択できます。例えば「量子力学」と「微分方程式」を同時に選択すると、両方の分野に対応したプロンプトが使用されます。

> 選択した研究分野はセッションファイルに保存されます。セッションを読み込むと以前に選択した分野が自動的に復元されます。

### 分野の対応状況（バッジ表示）

分野一覧には対応状況を示すバッジが表示されます。

| バッジ | 意味 |
|---|---|
| （なし） | 動作確認済み。通常通り使用できる |
| 🔵 **準備中** | ヒントは存在するが、専用の CAS 操作がまだ接続されていない。基本的な計算は動くが、分野固有の操作は未対応 |
| 🟡 **未実装** | ヒントは存在するが、対応する CAS 操作が未実装。選択しても計算上の効果は限定的 |

「準備中」「未実装」の分野はグレーアウト・選択不可になっています。

## 数式の入力

### テキストで入力する

入力欄に数式を LaTeX 形式またはそのまま入力して「送信」します。

```
(x^2-1)/(x-1)
sin(x)^2 + cos(x)^2
f(x) = sin(x)
```

送信すると式が `E1`、`E2`、… のように番号付きでタイムラインに追加されます。

### 書ける記法（よく訊かれるもの）

以下はそのまま打てます。**断られる形と対になっている**ので、断り文が出たときは
併せてこの表を見てください（断られる形の一覧は [docs/refusals.md](refusals.md)）。

| 書き方 | 例 | 備考 |
|---|---|---|
| 関数の冪 | `\sin^2 x`, `\cos^2\theta + \sin^2\theta` | 指数は**値**に掛かる（`sin(x)^2`）。`\sin_2 x` のような**添字**は読みが無いので断られる |
| 逆三角・逆双曲線 | `\sin^{-1} x`, `\tanh^{-1} x`, `\arcsin(x)` | 逆関数として読む（逆数には cosec・sec・cot という固有名があるため曖昧さが無い）。`\log^{-1}` は名前つき逆数が無いので断られる |
| 極値（具体的な範囲） | `\max_{i=1}^{3} x_i`, `\max_{1\le i\le 3} x_i` | `\min`・`\sup`・`\inf`・`\arg\max`・`\arg\min`・`\limsup`・`\liminf` も同じ。**記号の範囲（`\max_i`・`\max_{i=1}^{n}`）は書いて残せるが値は出ない**——「評価して」の時点で理由つきに断る |
| 極値（明示集合） | `\max_{i \in \{1,2,3\}} x_i` | **非連続でもよい**（`\{1,3,7\}`）。`\max_{1<i<3}` は整数と実数で読みが違うので断られる |
| 条件つきの和 | `\sum_{i<j}^{N} V_{i,j}`, `\sum_{i \ne j}^{N} V_{i,j}` | 範囲の書き換えとして計算する。`i<j` は N(N-1)/2 項、`i \ne j` は N(N-1) 項で**別物**。最近接 `\sum_{\langle i,j\rangle}` は格子の性質なので格子名を指定する |
| 行列（TeX 書法） | `\begin{pmatrix} 2 & 1 \\ 1 & 2 \end{pmatrix}`、`bmatrix`・`matrix`・`Bmatrix`・`smallmatrix`・`array`、plain TeX の `\pmatrix{…}` | `[2, 1; 1, 2]` と**同じもの**として読む。**画面に出た行列をそのままコピーして打ち直せる**（表示は `pmatrix`）。縦棒の `\begin{vmatrix}` は**行列式**（スカラー）として読み、値まで出る。二重縦棒 `\begin{Vmatrix}` はノルムで、操作が無いため読まない |
| 絶対値・行列式の縦棒 | `\|x\|`, `\|x\| + \|y\|` | どちらの意味か確認ダイアログが出る（複数あっても**1回の決定で全部に効く**）。二重縦棒 `\|v\|` はノルムで、操作が無いため断られる |
| 宣言のやり直し | `\hat H_0 を行列として宣言し直して` / `re-declare H as a matrix` | 既に別の型で宣言した名前は、**そのままでは上書きされません**（宣言はこのノートの読み方を決めるので、黙って変えると既に書いた式の意味が変わる）。変えるときは「宣言し直して」と明示します |
| 数の領域の宣言 | `z を複素数とする`, `n を整数とする` | CAS に届く。`conjugate(z)*z` は `z^2` に潰れず、`sin(n\pi)` は `0` になる |
| 装飾つきの名前の微分 | `\frac{\partial}{\partial t}\hat c_{n\sigma}(t)`, `\frac{d}{dt}\bar q(t)`, `\frac{d}{dt}\mathcal{H}(t)` | ハットや棒は**名前の一部**なので、装飾ごと微分される。`\frac{d}{dx}\sin x` も同じ（`\sin` は単独では量ではない） |
| 冪の微分 | `\frac{d}{dx}x^2`, `\frac{d}{dx}f(x)^2`, `\frac{d}{dt}\left(f+g\right)^2` | 指数は**微分される側**に付く。`\frac{d x^2}{dx}` も同じ |
| 近似の関係 | `G^{(2)} \approx \langle \hat n\rangle G` （`\simeq`・`\cong` も同じ） | **書けて、書いたまま表示される**。ただし CAS に「およそ等しい」は無いので、これ自体を計算しようとすると理由つきに断られる——右辺を新しい量として登録してから操作する |
| 上付きのラベル | `G^0`, `\Sigma^{(HF)}`, `G^{(2)}_{p\sigma,q\sigma}` | 指数ではなく**名前の一部**として読む（`G^0` を指数と読むと 1 になる）。宣言（`G^0 を行列とする`）にも解く変数にも、この綴りのまま使える |
| 解く変数の綴り | `E33 を G^{(HF)}_{n\sigma}(\omega) について解いて` | ラベル・添字・引数が付いたままで指定できる。その名前が既に定義済みでも、指示の中では**その名前として**扱われる |
| 両辺に**左から**掛ける | `E23 の両辺に (1 - G^0 \Sigma)^{-1} を左から掛けて` | 行列など**非可換な積**では左右が別の式なので、側を言う。`\Sigma` や `G` を行列と宣言してあれば、左辺の $(1-G^0\Sigma)^{-1}(1-G^0\Sigma)$ は 1 に簡約される（Dyson 方程式の形式解がこれで出る） |
| 宣言の言い方 | `c を電子の消滅演算子とする`／`とみなす`／`と定義する`／`として宣言する`、`define c as …`／`declare c as …`／`let c be …`／`c is …`（`as`・`is`・`are`・`be`・`to be`） | **どの宣言も同じ語彙**で書けます——総称の型宣言も、正準対も、スピン演算子も、ラプラス変換の定義も同じです。**例外は2つあり、どちらも理由があります**: 日本語の `と置く`／`とおく` は代入の言い方なので（`x を 0 と置く`）、型の語を書いた宣言でだけ受けます。英語の素の `to` も同じ理由で受けません（受けると `convert E1 to polar coordinates` が宣言になってしまう）。`let x be a scalar` / `declare x as a scalar` が動く綴りです |
| 装飾つきの名前の宣言 | `\hat H_0 をスカラーとする` | 装飾は名前の一部として数える（`H_hat_0` が登録される）。宣言しておくと、計算結果の表示も `\hat H_0` のまま |
| クロネッカーδの縮約 | `\sum_{n m} \varepsilon_{n\sigma}\delta_{nm} A_{n,m}` を「簡約して」 | δ が和を潰して対角形になる。**CAS が返した結果に対しても効く**ので、「対角化の仮定を代入 → 簡約」で固有値が出る |
| フーリエ変換 | 逆変換の定義の積分を書いて「両辺を t で微分して」 | 専用の操作は無い。$e^{-i\omega (t-t')}$ の**空白は積の印**（空白が無いと $\omega$ を関数として適用した読みになる） |

**ベクトルの体積測度（`\int d^3k`）は成分に開いてから計算します。**
`\int d^3k\,f(k)` のように書いたものは、そのままでは CAS に渡せる形がありません。
「**E1 を成分に展開して**」と指示すると各成分の反復積分になり、以後は普通の積分として
扱えます（成分名 `k_x, k_y, k_z` は自動で登録されるので、そのまま積分変数に使えます）。

```
k をベクトルとする
\int d^3k f(k)                    ← E1
E1 を成分に展開して                 → 3重の反復積分になる
```

Julia（第２量子化）セッション固有のものは以下です。

| 書き方 | 例 | 備考 |
|---|---|---|
| 添字付きスカラー | `xi_k`（`xi` を宣言済み） | 基底が未宣言だと断られる（`xi` を宣言するか `xi_k` を丸ごと宣言） |
| スピンの矢印記法 | `c(k, \uparrow)`, `c(k, ↑)` | 同時二重置換でも使える（英字 `u`/`d` でも可） |
| 異時刻の交換関係 | `E2 と E3 の反交換関係` / `the anticommutator of E2 and E3` | 時間発展させた演算子どうしなら**係数の積 × 等時刻代数**として計算する。演算子が消えればスカラーになり、係数はスカラー側でまとまって**時間差だけの関数**になる（2サイトなら `cos(w(t-u))`——自由伝播関数そのもの）。そのまま Maxima セッションへ渡せる |
| 演算子の時間発展 | `c(m) を E1 のもとで時間発展させて` / `E1 のもとでの c(m) のハイゼンベルク演算子` / `evolve c(m) under E1` / `the Heisenberg operator of c(m) under E1` | ハイゼンベルク描像の `A(t)=e^{iHt}Ae^{-iHt}`。**打ち切りなしで厳密に**出る——対角なら `e^{-i\varepsilon_m t}c_m`、2サイトの跳び移りなら `cos(wt)c_1-i\sin(wt)c_2`、原子極限の相互作用なら `c_1+(1-e^{-iUt})c^\dagger_2c_1c_2`。時間変数は既定 `t`、`時刻 s まで` のように指定も可。連鎖が有限個の演算子で閉じない場合と、基底が自由添字を持つ族になる場合（一般の2体項）は理由付きで断られる |

### 手書きで入力する

## 操作の指示

### 自然言語で指示する

入力欄に操作を日本語で書いて「送信」します。

```
E1 を展開して
E2 を x で微分する
E1 を x について因数分解
E2 を x=0 の周りで 3 次のテイラー展開
E2 を x=1 の周りで 4 次テーラー展開して
E1 を 0 から 1 まで x で定積分
E3 の x に E1 を代入
E1 を x で偏微分して
E2 を y で偏微分して
E1 の x → 0 の極限を求めて
E1 の x → 0 の右極限を求めて
```

**Enter** で送信、**Shift+Enter** で改行できます。

### ベクトル場（矢印付きの綴りでも計算できます）

`A をベクトル場とする` と宣言すれば、次はどれも同じ操作に届きます:

```
\nabla \times A          \nabla \times \vec{A}      \nabla \times \mathbf{A}
\nabla \cdot A           \nabla \cdot \vec{A}       curl \vec{A} / div A
\nabla f                 \nabla \vec{f}
```

**引数を書いた形（`\vec{A}(t)`）は、式としては書けますが、ベクトル解析の操作では
断られます。** 成分を `A_x(t)` と読むと座標での微分が 0 になり、∇× も ∇· も静止した
答えを返してしまうためで、書かれていない座標依存をこちらで補うことはしません。
回転や発散を計算したいときは**引数を書かずに** `\nabla \times A` と書いてください。

### 宣言した名前は、そのまま指示に書けます（2026-09-11）

宣言した対象は**名前のまま**オペランドに書けます——式番号にしなくて構いません:

```
A のノルムを求めて / the norm of A          →  sqrt(A_z^2+A_y^2+A_x^2)
A の発散を求めて   / the divergence of A     →  ∂A_x/∂x + ∂A_y/∂y + ∂A_z/∂z
f の勾配を求めて   / the gradient of f       →  (∂f/∂x, ∂f/∂y, ∂f/∂z)
```

**ただし、宣言しただけでは「値」がありません。** 値を必要とする操作
（微分・積分・簡約など）は、その条件を述べて断ります——**何として宣言されて
いるか**、**値がまだ無いこと**、そして**満たす道**です。道は2つあります:

| 道 | 書き方 | 結果 |
|---|---|---|
| 値を与える | `A = \begin{pmatrix} x^2 \\ 0 \\ 0 \end{pmatrix}` のあと `A を x で偏微分して` | `matrix([2*x],[0],[0])` |
| 宣言だけで計算できる操作を使う | `A の発散を求めて`・`A のノルムを求めて` | 上の表のとおり |

宣言だけから計算できる操作は種別ごとに違います——ベクトル場はノルム・発散・回転・
内積・外積、スカラー場は勾配・スカラーラプラシアン・微分。**行列とテンソルには
いまのところありません**ので、そちらは値を与えてください（断り文もそう案内します）。

### 値も宣言も無い名前を書いたら（2026-09-18）

```
zvar を簡約して / simplify zvar
  →  `zvar` は、この notebook がまだ何も持っていない名前です（値も宣言もありません）。
     値を与えてから同じ指示を書いてください——例: `zvar = a x + b`。
```

**その名前について答えます——直前の式で代用しません。** 以前は直前に登録した式の
簡約が `completed` で返っており、微分・積分では捨てられた名前が**変数の欄**に入って
研究者が書いた変数のほうが落ちていました。**スカラーとして宣言しただけの名前も同じ**
です（値がまだ無いので）。

**通る道は「値を与える」**です（`zvar = a x + b`）。ベクトル場・行列などの**対象**
として宣言した名前は、そのまま書けます（上の節）。

名前が式の**一部**なら計算は進み、⚠ に未定義の名前が出ます:

```
E_{total} を簡約して   →  E(total)   ＋ ⚠ 未定義シンボル: E_total
```

> **変数の位置は別です。** `x で微分して` の `x` は未定義でも**変数**として立って
> いるので、これまでどおり直前の式を微分します。判別は助詞・前置詞の位置です。

### 極限（片側もそのまま書けます）

`\lim_{x \to 0} \frac{\sin x}{x}` のように**記法のまま式として書いて**も、
`E1 の x → 0 の極限を求めて` のように**指示として書いて**も同じ操作に届きます。

**片側極限は向きを書いてください**——両側と**答えが違う**からです
（$\lim_{x\to0}|x|/x$ は不定、右からは $1$、左からは $-1$）。向きの書き方は3通り、
どれでも同じです:

| 書き方 | 例 |
|---|---|
| 点に印を付ける | `\lim_{x \to 0^+} f(x)` ／ `E1 の x → 0+ の極限を求めて` |
| 語で言う | `E1 の x → 0 の右極限を求めて`（左極限・右側極限・左側極限も可）／ `the right-hand limit of E1 as x -> 0` ／ `the limit of E1 as x -> 0 from the right` |
| 欄を名指す | `limit of E1 with var=x, point=0, direction=plus` |

$\lim_{t' \to t^+} G(t,t')$（等時刻グリーン関数）のように**CAS が値を出せない**
形は、`limit(...)` のまま保持されて表示されます——書けて、見えて、後続の操作に
渡せます。

**Julia（第２量子化・凝縮系）のセッションでは計算できません**（Symbolics.jl に極限が
無く、QuantumAlgebra は演算子代数のため）。式として書いて表示することはでき、値が
要る段階で Maxima のセッションへ渡してください（[docs/refusals.md](refusals.md)）。

## 定積分の変数変換（ヤコビアン）

範囲つきの定積分そのものを別の座標へ変数変換し、**被積分関数も積分範囲も新変数に書き換わった定積分**を
表示してから評価できます。CAS 構文は不要で、すべて自然言語で進みます。

**1. 範囲つき定積分を与える（この時点では計算しない）。** 2 通りの書き方ができます。

```
x^2+y^2<=1 の領域で x^2+y^2 を定積分        ← 領域述語（単位円板）
\int_{0}^{1} \int_{0}^{1} (x+y) \, dx \, dy   ← LaTeX の定積分記法
```

登録された式は $\iint_{x^2+y^2\le1}(x^2+y^2)\,dx\,dy$ のように**未評価のまま表示**されます。

**2. 変数変換を指示する。**

```
E1 を x,y から r,theta へ x=r*cos(theta), y=r*sin(theta) で変数変換して
```

**3. 新しい範囲つき定積分が表示される。** 被積分関数にヤコビアン $|J|$ が掛かり、積分範囲も新変数のものに
なります（例：$\int_{0}^{2\pi}\!\int_{0}^{1} r^3\,dr\,d\theta$）。標準的な座標変換（極座標×円板、球座標×球）の
**新しい範囲は自動算出**されます。当てはまらない一般の変換では、新変数指定に範囲を添えてください。

```
E7 を x,y から u:0..1, v:0..1 へ x=2*u+v, y=u+3*v で変数変換して
```

範囲を省いた場合は LLM が範囲を提案し、提案に満足できなければ上のように範囲を明示して指示し直せます。

**4. 評価する。**

```
この定積分を評価して
```

反復積分が実行され、$\displaystyle\int_{0}^{2\pi}\!\int_{0}^{1} r^3\,dr\,d\theta=\frac{\pi}{2}$ のように
**式＝値**で表示されます（球座標·単位球なら体積 $4\pi/3$）。

> **被積分関数だけを変換したいとき**は、定積分オブジェクトを介さず直接
> `x^2+y^2 を x,y から r,theta へ x=r*cos(theta), y=r*sin(theta) で変数変換して` と指示し、
> 続けて `簡約して` とすると $r^3$ が得られます。単変数の定積分は
> `E3 を r で 0 から 1 まで定積分して` のように書けます。

## 偏微分・陰関数微分

### 偏微分（∂ 記法）

多変数式（右辺に 2 つ以上の変数を含む）を微分すると、`d` の代わりに `∂` が自動的に使われます。

```
z = (x+y)^2 を登録 → E1
E1 を x で偏微分して → ∂z/∂x = 2(y+x)    （E2）
E2 を y で偏微分して → ∂²z/∂x∂y = 2      （E3）
```

高階・混合偏微分も自動的に `∂` 記法になります。

### 偏微分（∂）か全微分（d）かを確認します

多変数の式を微分するとき、偏微分 $\partial/\partial x$（他の記号を固定）と全微分 $d/dx$
（他の記号も $x$ の関数として連鎖律で微分）は結果が変わり得ます。**どちらかをシステムが
推測すると誤りのもとになるため、判別できないときは利用者に確認します。** これは物理に限らず
数学でも同じで、「時間」を特別扱いはしません。

```
z = x^2 + y を登録 → E1
E1 を x で微分して   → 偏微分（∂/∂x）か全微分（d/dx）か選択を求められる
```

**次数の書き方は問いません。** 「3階」「３階」「三階」「3rd order」「third order」は
同じ意味に読みます（微分の階数・級数の次数・N重交換子・モーメント・展開の深さ、
どれでも同じです）。読めない綴りは**推測せず**、その語を無視して既定で進めることは
しません。

**判別のルール:** 微分変数自身と、**定数として宣言した記号**を除いて、なお別の記号
（自由変数や、その変数に依存すると宣言した量）が残るときに確認します。

- **定数を宣言すれば確認は減ります**：`a と b をスカラーとする` 済みなら、`a x + b` を `x` で
  微分しても確認は出ません（$a,b$ は定数なので $\partial=d$）。`x^2` のように微分変数以外の
  記号がなければ確認は出ません。
- **明示すれば確認は出ません**：**`x で全微分して`**（連鎖律あり, d）／**`x で偏微分して`**（他を固定, ∂）。
- スクリプト・テスト・LLM なしの非インタラクティブ実行では、曖昧な微分は**エラー**になります。
  「全微分」「偏微分」を明示してください。

> 物理での時間微分（`r, theta` を時間依存宣言 → `t` で全微分）も同じ枠組みです。時間依存の
> 宣言は CAS に依存関係を伝えるための機構で、$r,\theta$ は定数ではないため確認対象になります。

**解析力学セッションでは、時間で偏微分すると座標は止まります。** $q$ と $\dot q$ は
独立な量なので、$\partial/\partial t$ はそれらを固定したまま微分します——つまり
**明示的な時間依存だけ**が残ります。全微分は連鎖項に加えてその項を含みます。

```
q を時間依存関数として定義する
L = \dot{q}^2/2 - q^2/2 + F q \cos(w t)     ← E1
E1 を t で偏微分して → ∂L/∂t = -F q w sin(w t)
E1 を t で全微分して → dL/dt = -F q w sin(w t) + F q̇ cos(w t) + q̇ q̈ - q q̇
```

これはエネルギー定理 $dH/dt = -\partial L/\partial t$ で使う量です。

> **解析力学の外では $\partial/\partial t$ と $d/dt$ は一致します。**
> 「時間依存関数として定義する」は「その量は $t$ の関数である」という宣言なので、
> そう宣言された記号だけで書かれた式は $t$ だけの関数になり、固定できる別の変数が
> ありません。解析力学だけが違うのは、そこでは $q$ と $\dot q$ が**独立な量**として
> 宣言されるからです。

### 陰関数の微分（y=f(x) 型の方程式）

`y = cos(x)` のように左辺が単純変数名の方程式を微分する場合、確認ダイアログが表示されます。

```
「E1 は方程式です。y の微分の扱いを選んでください。」

  [ y を x の関数として微分 ]  [ 両辺を独立に微分 ]  [ キャンセル ]
```

| 選択肢 | 動作 |
|---|---|
| y を x の関数として微分 | `depends([y],[x])` を宣言してから微分。結果は `dy/dx = -sin(x)` |
| 両辺を独立に微分 | y を x に依存しない記号として微分。結果は `'diff(y,x,1) = -sin(x)` |

「y を x の関数として微分」を選ぶと、以降の微分でも y が x の関数として扱われます（同一セッション内）。

## 仮定の追加・削除

### 追加

自然言語で指示します（英語も同等に動作します: `assume x > 0`）。

```
x > 0 を仮定する
E3 > 0 と仮定する         （式番号を条件に埋め込める。E3 自体の実際の値に展開されて CAS に送られる）
m は正の実数とする
n は正の整数とする
```

タイムライン上部に青い仮定タイルが追加されます。
仮定は Maxima の `assume()` に送られ、以後の積分・極限などの計算に反映されます。

`m は正の実数とする` / `n は正の整数とする` のような型宣言は、記号の型（実数・整数など）を
登録するだけでなく、符号（正/負/非負/非正）も別途保持し、その符号は自動的に `assume()` として
CAS へ送られます（「正の整数」のように種別＋符号の複合宣言でも、どちらの情報も失われません）。
判別式の符号など、扱っている問題に依存する仮定（例: 減衰振動子の運動方程式を一般解する前に
判別式の符号を確定する）は、このコマンドをセッション・シナリオ側で明示的に呼ぶことで表現します
— ツール側が代わりに物理的な仮定を選ぶことはありません。

### 削除

仮定タイルの「✕」ボタンをクリックすると仮定が解除されます（Maxima の `forget()` が呼ばれます）。

## ブランチ操作

計算の分岐点から別の探索ルートを試したいときに使います。

> **💡 ブランチの設計思想について**  
> UI や履歴、式の参照レベルではブランチ構造が維持されますが、CAS（数式処理エンジン）内部状態の完全な「時間旅行」（任意の過去のインメモリ状態への瞬時復帰）は意図していません。セッションの保存や再開は安全な **スナップショット（Snapshot）方式** に基づいており、計算状態が大きく変わるような危険な分岐（Dangerous Fork）については、**ファイルレベルでのフォーク（別ファイルとしての保存）** によって安全に扱うことを推奨しています。

### ブランチを作成する（fork）

タイムライン上の CAS タイル（緑枠）にマウスをのせると「⎇」ボタンが現れます。

1. 「⎇」をクリック → fork ダイアログが開く
2. **ブランチ名**（省略可）を入力して「分岐を作成」
   - 省略すると `branch_2`, `branch_3` … と自動命名されます
3. ヘッダのブランチセレクタで新しいブランチに切り替えて計算を続けます

### セッションをファイルとして分岐する（File-level Fork）

fork ダイアログの「スナップショットとして保存」チェックをオンにすると、インメモリでのブランチを作らずに、そこまでの状態を独立した JSON ファイルとして `sessions/` に保存（分岐）できます。計算の前提や仮定が大きく変わる場合は、このファイル分離による安全な分岐を推奨します。

- ファイル名を入力（省略すると日時から自動生成）
- チェックをオンにすると「保存ファイル名」入力欄に切り替わります

### ブランチを切り替える

ヘッダの「Branch」セレクタでブランチを選択します。タイムラインが選択したブランチのみの式履歴に更新されます。

> 式番号はノートブックファイル全体でユニークです。fork 後のブランチ側と元の main 側で式番号が衝突することはありません。

## LLM 考察（Adviser）

CAS の計算結果に対して LLM から数学的・物理的な解説を得られます。

### 基本の使い方

1. タイムライン上の式エントリ（緑枠）をクリックして選択
2. 操作ボタンバーに「💡 考察」ボタンが表示される
3. クリックすると考察モーダルが開く
4. 質問欄に追加の問いを書くか、空のまま「考察する」を押す
5. LLM からの解説がモーダルに表示される（数式は KaTeX でレンダリング）
6. 「📝 メモとして保存」で解説をタイムラインに残せる

### LLM の選択

モーダル上部のドロップダウンで使用する LLM を選択できます。

- `●` のついたエントリは現在接続可能
- `○` のついたエントリは未接続（選択しても送信時にエラー）
- `☁` マークはクラウド API エンドポイント（従量課金の場合あり）

`models/default/config.json` の `preferred_adviser` に指定したエンドポイントが先頭に表示されます。

### 接続状態

| ボタン表示 | 意味 |
|---|---|
| 💡 考察 … | 接続確認中 |
| 💡 考察 | 接続可能 |
| ⚠️ 考察（未接続） | LLM サーバーに届かない |

「⚠️ 考察（未接続）」の状態でボタンを押すと再接続を試みます。成功すればそのままモーダルが開きます。

## セッションのタイトルとファイル名

セッションには**タイトル**と**ファイル名**の2つの名前があり、独立して管理されます。

| 名前 | 説明 | 確認場所 |
|---|---|---|
| **タイトル** | セッション作成時（または分岐フォーク時）に設定される内部名。JSON ファイルに保存される。 | 📊 ステータスモーダルの「タイトル」行 |
| **ファイル名** | `sessions/` フォルダ内の実際のファイルパス（例: `HB_2.json`）。保存時に決まる。 | 📊 ステータスモーダルの「ファイル」行、💾 保存ダイアログの「上書き保存（…）」ボタン |

**注意点：**
- タイトルとファイル名は一致しない場合があります。  
  例：タイトル「HB」のセッションを `HB_2.json` として保存した場合、タイトルは「HB」のまま。
- セッションを読み込んだ後にタイトルを変更しても、ファイル名は変わりません。
- ファイル名からブランチや実験のバリエーションを区別し、タイトルは研究テーマを表す、という使い分けが推奨されます。

## セッションの保存・読み込み

### 保存

「💾 保存」ボタン → 保存ダイアログが開きます。

| 選択肢 | 動作 |
|---|---|
| 上書き保存 | 前回保存したファイルに上書き（前回保存がある場合のみ表示） |
| 名前を付けて保存 | ファイル名を入力して `sessions/` フォルダに保存 |
| 保存せずに続ける | ダイアログを閉じる |

ファイル名を省略すると日時から自動生成されます。ダイアログには現在のフォルダ内の既存 `.json` ファイルが一覧表示されます。ファイル名をクリックすると入力欄に自動補完され、上書き保存が容易になります。

### 自動保存

5 分ごとに自動で `sessions/autosave/slot_1.json` ～ `sessions/autosave/slot_5.json` へローテーション保存されます。前回の保存から変更がない場合はスキップします。

### LaTeX エクスポート

「💾 保存」ボタン → 保存ダイアログの「⬇ LaTeX 出力」ボタンをクリックすると、アクティブブランチのタイムライン（指示・CAS 式・メモ・仮定）を自己完結 `.tex` ドキュメントとしてダウンロードできます。

- 日本語セッション: `jsarticle` + upLaTeX 形式
- 英語セッション: `article` + pdfLaTeX 形式

ユーザーの指示（「微分して」等）は `\instruction{}` のようなマクロではなく、プレーンテキスト段落として数式の間に挿入されます。そのまま論文原稿として加工・編集できます。

### 読み込み

「📂 読み込み」ボタン → 保存済みセッション一覧が表示されます。ファイルをクリックして読み込みます。

### 終了

「Exit」ボタンをクリックすると保存ダイアログが表示されます。保存してから終了するか、保存せずに終了できます。

| 項目 | 説明 |

| OCR Engine | 手書き入力に使う認識エンジン |
| Refiner | 認識結果の後処理モデル（LaTeX 後処理） |

セッション中に変更できます。手書き入力の精度が悪いときはエンジンや refiner を切り替えてみてください。

利用可能なエンジンと refiner は `models/engines/` および `models/refiners/` ディレクトリから自動的に読み込まれます（`config.json` を持つディレクトリのみ）。

### OCR パイプラインの動作

```
手書き画像
  ↓
OCR Engine（画像 → draft LaTeX）
  ↓
Refiner（draft LaTeX ＋ 元画像 → 修正 LaTeX）← VLM refiner は画像も参照
  ↓
LaTeX トークンとして入力欄に挿入
```

VLM 対応の refiner（llama-3.2-vision、qwen3-vl、internvl3.5）は元の手書き画像と engine の出力を両方参照して誤認識を修正します。engine 単独より高い精度が期待できます。refiner を「なし」にすると engine の出力がそのまま使われます。

## 時間依存変数とドット記法

解析力学など時間依存する変数を扱う場合、`declare_time_dependent` で変数を時間の関数として宣言すると微分結果の表示が切り替わります。

> **⚠ 解析力学の制限：前定義が必須**
>
> `q_dot` という識別子を使っても $\dot{q}$ として表示されず、d/dt 操作も正しく機能しません。
> 式を入力する **前に** 必ず `q を時間依存関数として定義する` を実行してください。
>
> - 後から宣言した場合：既存の式に遡及しない。`d/dt(q_dot) = 0` となり計算が壊れる。
> - セッションをやり直す場合は、宣言をステップ 0 として最初に行うこと。
>
> 速度変数の入力は `\dot{q}` または `diff(q,t)` を使用する。

### 時間依存の宣言

```
q を時間依存関数として定義する
```

または入力欄で `declare_time_dependent` 操作として実行します。宣言後は `q` が `q(t)` として扱われます。

### 微分記法の切り替え

時間依存変数の `t` による微分を、**ドット記法**（`q̇`）か **Leibniz 記法**（`dq/dt`）で表示できます。この記法は、グローバルな一括切り替えではなく、**シンボル（変数）ごとに個別かつ独立して設定・管理**されます。これにより、同じ計算セッション内で異なるシンボルに対して異なる微分表記を美しく混在表示させることが可能です。

```
q をドット記法にする
q を Leibniz 記法にする
```

デフォルトはドット記法です。設定された記法は各シンボルの `notation` 属性としてシンボルテーブルに保存・永続化され、セッション保存時やロード後にも完全に維持されます。

### 一般化速度に対する偏微分（∂/∂q̇）

ラグランジアンの変分で使う `∂L/∂q̇` 操作は `diff_wrt_qdot` として実行されます。

```
E1 を q̇ で偏微分
```

結果は `∂E1/∂q̇ = ...` のように表示されます。

## 一般文字添字（Index Notation）と静的インデックス縮約

非可換代数、テンソル解析、統計力学などで多用される文字添字（$i, j, k, l$ など）を含む数式表現をそのまま記述し、システムがその代数的意味を理解して静的に簡約（縮約）や名前衝突回避（アルファタイジング）を実行することができます。

### 1. 添字表記の解釈

手書きやテキスト入力された `x_i`, `A_{ij}` などの文字添字表現は、システム内で **`IndexedSymbol`**（添字付きオブジェクト）として厳密に区別・解決されます。
* **配列アクセスとの区別**: 一般的に理論計算では `x_i` は配列アクセスではなくインデックス付きの記号族を指すため、バックエンドへ下降（lowering）する際はデフォルトで関数適用形式 `x(i)` に下降されます。量が明示的にベクトルや行列、テンソルとして定義されている場合のみ、配列形式 `x[i]`, `A[i,j]` に下降されます。
* **通常の関数呼び出しとの区別**: 数式上は両方とも Maxima 等で `x(i)` と表現されますが、Notebook IR（内部 AST）上では、添字付き記号 `IndexedSymbol(x, [i])` と通常の関数呼び出し `FunctionCall(x, [i])` は厳密に区別され続けます。この区別は、セッションの保存・復元（save/load）を経た後も完全に維持されます。

### 2. 明示的総和（\sum）と KroneckerDelta（\delta）の自動縮約（Contraction）

数式セルに `\sum_{j} \delta_{i,j} f_j` と入力すると、明示的な離散総和（`IndexSum` / `\sum`）の内部において、ダミー添字（bound index）と `KroneckerDelta`（`delta(i, j)`）の積が存在する場合、自動的にインデックス縮約が適用されます。

```
IndexSum(delta(i, j) * f(j), j) を登録
  ↓
自動縮約が適用され、f(i) として登録される（E1）
```

* **安全な適用スコープ**: 自動縮約（`contract_indices`）およびダミー添字のリネーム（`alphatize_indices`）は、**明示的な `IndexSum` の内部にのみ適用**され、アインシュタインの縮約記法（暗黙的な総和）を自動で推測・適用することはありません。


### 2.5 積分（Integral）のパースと処理

LaTeX記法の不定積分 `\int f(x) dx` も同様にパースされ、内部ASTの `Integral(f(x), x)` に変換されます。Maximaバックエンドでは `integrate` に送られます。積分変数（`dx` などの微分記号）は自動的に検出されます。

### 3. ダミー添字の衝突回避（アルファタイジング）

入れ子になった総和や、並列した積の中で同じダミー添字名（例: `i`）が重複して衝突することを避けるため、システムが自動的にダミー添字を安全な別の文字（`j`, `k` …）へリネーム（アルファ変換）します。

```
IndexSum(f(i), i) * IndexSum(g(i), i) を登録
  ↓
自動的に並列衝突が回避され、IndexSum(f(i), i) * IndexSum(g(j), j) として安全に解決
```

### 4. 非可換積の順序保存と厳密ロック

量子演算子の積 $A_j B_k$ や `a'(1) a(1)` （スペース区切りでの暗黙の積）など、非可換代数（統計力学・量子力学）の文脈で総和・縮約を行う場合、インデックス縮約やアルファタイジングが演算子積の左右の順序関係を崩すことは決してありません。
非可換要素が含まれる暗黙積は、AST レベルで順序固定の `NonCommutativeMul` として厳密にロックされ、CAS（特に Maxima）側で勝手にアルファベット順にソートされるのを防ぎます。

### 5. 定義域・値域の検証 (Domain & Range Validation)

縮約が行われる際、2つの添字の定義域（例: `spin`, `spatial`）や値域（例: `1..N`）が不整合な場合は `ValueError` が投げられ、計算の安全性が守られます。このエラーが発生した際も、システムはクラッシュせず、デバッグ REPL やブラウザ UI で安全にエラーメッセージが表示されます。

### 6. 表記ブリッジと表示用 LaTeX 自動復帰 (Display Bridge)

数式処理バックエンド（Maxima / Julia）の内部処理のために `x(i)` や `A[i,j]` のように下降（lowering）された表現は、計算完了後に `SymbolContext` を参照して元の美しい LaTeX 形式 `x_i`, `A_{ij}` および `\delta_{ij}` へ自動的に Pretty-print 復元（Display Bridge）されます。
* **時間依存ガード**: 時間依存変数 `q(t)` の `t`（時間パラメータ）や、定義関数の自然引数（`natural_vars`）は、下付き添字として誤認されず通常の関数引数のままで安全に維持されます。

### 7. 虚数単位 $i$ と添字 $i$ の自動衝突回避

Julia セッションでは、`i` を虚数単位（Julia の `im`）として扱うか、変数（添字）として扱うかを次の3段階で自動判定します。

| 条件 | 判定 | 出力 |
|---|---|---|
| `i` が `:i`（演算子引数）として現れる | 演算子添字 | `QuIndex("i")` |
| `i` が `IndexSum` の束縛変数（`Σ_i`）として現れる | 総和添字 | `sumindex(...)` |
| `i` が `SymbolContext` に宣言済み | ユーザー定義変数 | `i`（そのまま）|
| 上記いずれでもない（未宣言・非束縛） | 虚数単位 | `im` |

**量子多体・量子光学セッションでは `i` は原則として虚数単位として扱われます。**

#### 格子モデルなど、`i` を整数添字として使いたい場合

サイト添字 `i` を式の中で使いたい場合は、事前に宣言してください。

```
i をスカラーパラメータとして定義する
```

宣言後は `ε(i)` や `c(i)` などの式で `i` が整数変数として扱われます。

量子演算子の引数として `c(i)` と書いた場合は、リゾルバが自動的に `:i`（添字マーカー）を付与するため、宣言なしでも正しく演算子添字として機能します（虚数単位に変換されません）。

#### スピン添字の記法

2添字演算子 `c(k, σ)` のスピン成分（第2引数）には、以下の記法が使えます。

| 入力 | 内部正規化 | Julia QuIndex |
|---|---|---|
| `↑`, `\uparrow` | `u` | `QuIndex("u")` |
| `↓`, `\downarrow` | `d` | `QuIndex("d")` |
| `σ`, `\sigma` | `s` | `QuIndex("s")` |
| `T`（横波） | `T`（そのまま） | `QuIndex("T")` |
| `L`（縦波） | `L`（そのまま） | `QuIndex("L")` |
| `up`, `dn` | `u`, `d` | `QuIndex("u")`, `QuIndex("d")` |

QuantumAlgebra.jl の制約により、QuIndex 名は**1文字**でなければなりません。`sigma`→`s`、`alpha`→`a` のような多文字ラベルは自動的に1文字に正規化されます。

### 8. プライム記号（$'$）のドメイン依存動的解決

同じプライム記号 `'` を、アクティブなセッションドメインに基づいて動的に分類します。
* `calculus`（解析学）ドメイン: `f'(x)` を自動的に `Derivative(f(x), [(x, 1)])` に解決します（多重プライム `f''(x)` なども order に応じて自動追従します）。
* `second_quantization`（量子力学）ドメイン: `a'(i)` や `a_i'`（添字付き記号へのプライム）を生成演算子 $a^\dagger_i$ (Symbol `"a'"`) に解決し、ダガー（$\dagger$）記号として代数特性を保持します（例：`[a_i, a_j'] = \delta_{ij}`）。

### 9. 行列随伴・複素共役・転置の文脈（MathType）依存の安全な自動解釈

ユーザーが入力した `A^\dagger`, `A^*`, `A^T` といったべき乗表現を、対象の `MathType`（行列、ベクトル、演算子、スカラー）に基づいて適切に数学的意味へと自動分類します。
* `A^*` : 常に複素共役（`Conjugate`）として解釈されます。

  **受け付ける綴り**（すべて同じ意味になります。TeX エディタから貼っても、
  このシステムが表示した式をそのまま打ち直しても通ります）:

  | 綴り | 例 |
  |---|---|
  | 星を後ろに置く | `\psi(x)^*` / `\psi(x)^{\ast}` |
  | 星を関数の前に置く（物理の標準） | `\psi^*(x)` / `\psi^{\ast}(x)` / `\psi^\ast(x)` / `\psi^{\star}(x)` |
  | 添字つき | `\psi^*_{n}(x)` / `\psi_{n}^{*}(x)` / `\varphi^*_{m,s}(x)` |
  | 上線（**複合式のみ**） | `\overline{\psi(x)}` / `\overline{a+b}` |

  表示はどれも星が関数の前に付いた形（$\varphi^{\ast}_{m,s}(x)$）に揃います。
  共役の有無で添字の読みは変わらないので、$\varphi^*_{m,s}(x)\,\varphi_{m,s}(x)$ は
  同じ基底関数の積として正しく組になります。

  **注意（意図的な例外）**: 単独の記号に付けた上線 `\bar{z}` / `\overline{z}` は
  **共役ではなく名前** `z_bar` です（H-1 の装飾名規約——`\bar{H}` を「H バー」という
  別の量として登録するための綴り）。単独記号の共役は `z^*` と書いてください。

  **関数はそのまま残ります。** 波動関数や行列要素——$\psi^*(x)\,\psi(x)$、
  $\varphi^*_{m,s}(x)\,\varphi_{n,t}(x)$——は共役が保たれたまま計算に進みます。

  **裸のスカラー記号は実数扱いです。** Maxima は宣言のない記号を実数とみなすため、
  $z^*z$ は $z^2$ に簡約されます（誤りではなく、CAS の既定の仮定です）。
  なお 2026-08-09 時点では「z を複素数とする」と宣言してもこの簡約は止まりません
  （宣言が CAS に届いていない——open_items COMPLEX-DECL-NOT-SENT）。それまでは
  $|z|^2$ を残したい場合、その量を関数として書くか、簡約せずに保持してください。
* `A^\dagger` : 常に随伴・エルミート共役（`Adjoint`）として解釈されます。
* `A^T` または `A^{\mathrm{T}}` : 変数 `A` が `matrix`, `vector`, `tensor` として登録されている場合**のみ**、転置（`Transpose`）として解釈されます。それ以外（スカラーや未登録）の場合や、指数が `T` 以外の文字（例: `A^n`）の場合は、すべて通常のべき乗（`Pow`）として安全にフォールバックされます。この機構により、温度変数 $T$ などとの衝突を完全に防ぎます。

### 10. 将来の拡張・実装が延期されている事項

数式処理の解釈の自由度と安全性を優先するため、以下の高度な表記ブリッジ機能は Phase 3 以降へ意図的に延期されています：
1. **Einstein 縮約記法（暗黙的総和）の自動適用**: 誤判定による意図しない式変形を防ぐため、将来的にドメイン設定からの明示的なオプトイン（opt-in）として導入します。
2. **共変・反変（上下添字）の表現**: べき乗（Power）との衝突を完全に排除する AST 表現を設計した上で、Phase 3 にて導入します。
3. **DiracDelta + Integral の自動縮約**: 連続積分における delta 簡約は、積分変数と測度の精緻な推論と照合の上でサポート予定です。
4. **交換子・反交換子の直接ブラケット記法 `[A,B]`, `{A,B}`**: 通常のリストや集合と区別するため、ドメインが `quantum_mechanics` の場合にのみオプトインで判定を有効化する設計を準備しています。

## ベクトル解析と LaTeX ナブラ（$\nabla$）記法

物理や工学で多用されるベクトル解析演算子（勾配、発散、回転、ラプラシアン）を、LaTeX 形式のナブラ記法（$\nabla$）やラプラシアン記法（$\Delta$）から自動的に数学的セマンティクスを解決して計算・追跡できます。

### 1. ナブラ・ラプラシアンの自動解決ルール

LaTeX 形式の文字列がシステムに入力されると、プリプロセッサが自動的に対応する標準 CAS 関数に変換します。

| 入力 LaTeX 例 | 自動変換後の CAS 表現 | 数学的意味 | 備考 |
|:---|:---|:---|:---|
| `\nabla \cdot F` | `div(F)` | **発散 (Divergence)** | $F$ はベクトル（`\vec{F}`, `\mathbf{F}`） |
| `\nabla \times F` | `rot(F)` | **回転 (Curl)** | Julia / Maxima の両対応 |
| `\nabla^2 \phi` または `\Delta \phi` | `laplacian(phi)` | **ラプラシアン (Laplacian)** | $\phi$ はスカラーまたはベクトル |
| `\nabla \phi` | `grad(phi)` | **勾配 (Gradient)** | $\phi$ はスカラー |

* オペランドには、ギリシャ文字（例: `\phi`）、ベクトル表記（例: `\vec{F}`, `\mathbf{F}`）、丸括弧でグループ化された複合式（例: `(A + B)`）などが高精度に自動キャプチャされます。
* **入力前提**: 手書き画像認識（OCR）の結果やキーボード入力から **LaTeX 形式の文字列がシステムに渡されれば**、手書きかどうかにかかわらず数学的セマンティクスを完全に保持して各 CAS バックエンド（Maxima, Julia）で微分展開・記号計算できます（手書き画像認識自体の精度はスコープ外）。

> **単項演算子としての入力（そのまま計算される）:** 登録済みのベクトル場 `E`・スカラー場 `f` に対し、
> 以下を**式として入力するとその場で計算**されます（`発散を求めて` の自然文コマンドと同じ結果）。
> ナブラ記法・名前付き演算子・括弧の有無いずれも可：
>
> | 入力例 | 操作 | 必要な場 |
> |---|---|---|
> | `\nabla \cdot E` ・ `div E` ・ `div(E)` ・ `divergence E` | 発散 | ベクトル場 |
> | `\nabla \times E` ・ `curl E` ・ `rot E` ・ `curl(E)` | 回転 | ベクトル場 |
> | `\nabla f` ・ `grad f` ・ `grad(f)` | 勾配 | スカラー場 |
> | `\nabla^2 f` ・ `laplacian f` | ラプラシアン | スカラー場 |
>
> 例：平面波 $E=(0,\cos(kx-\omega t),0)$ で `\nabla \cdot E` → `0`、`curl E` → `[0,0,-k\sin(kx-\omega t)]`。
> 場として登録されていない裸のスカラー（例 `div t`）には作用しない（誤発火防止）。

### 2. バックエンドでの振る舞い

* **Maxima セッション**:
  - 標準パッケージ `vect` が自動ロードされ、`express(grad(f))`、`express(div(F))`、`express(rot(F))`、`express(laplacian(f))` 等を呼び出すことで、自動的に偏微分の和へ美しく展開されます。
* **Julia セッション**:
  - `grad`, `div`, `rot`, `curl`, `laplacian` が事前定義された `@syms` 記号オブジェクトとして機能するため、エラーを発生させることなくそのまま記号的な数式表現として処理・評価が可能です。

### 3. 具体的な成分を持つベクトル場の計算（成分の与え方）★重要

**「与えられた $\boldsymbol{E},\boldsymbol{B}$」のように具体的な成分式を持つベクトル場で div / curl を計算するには、2 段で与えます。**

1. **ベクトル場を宣言**する：`E をベクトル場として定義する`（`define_vector_field`）。
   これで成分 `E_x, E_y, E_z`（デカルト）が**抽象関数として登録**されます。
2. **各成分に具体値を等式（H-1 等式形式 `LHS = RHS`）で与える**：
   ```
   E_x = 0
   E_y = cos(k*x - w*t)
   E_z = 0
   ```
   これで成分が CAS に束縛され、以降の `E の発散を求めて`・`E の回転を求めて` が
   **この成分値を使って**偏微分の和を計算します。

> **混乱しやすい点（必読）:** `define_vector_field` の引数に**成分式は渡せません**
> （受け付けるのは `name` / `coordinate_system` / `natural_vars` のみ）。成分は必ず
> **上記のように等式で別途与えます**。これは設計上の決定で、成分名の衝突・`depends` の
> 一貫性・セッション復元時のマッピングを避けるためです（[doc 13](developer_manuals/13_vector_field_design_spec.md) §1）。
>
> 座標変数（x, y, z）以外の変数（時間 $t$、波数 $k$、角振動数 $\omega$ など）も**自由シンボル**
> として成分式に使えます。Faraday/Ampère の $\partial/\partial t$ は素の `t で微分` で計算できます。

**例（平面電磁波で Maxwell 方程式の整合を確認）:** 詳しくは
[scenario_maxwell_consistency.md](scenarios/scenario_maxwell_consistency_jp.md)（$\nabla\!\cdot\!E=0$・$\nabla\!\cdot\!B=0$・
Faraday・Ampère から分散関係 $\omega=ck$ を導く）を参照。

### 4. 内積・外積

```
A と B の内積を求めて                        the dot product of A and B
\vec{A} と \vec{B} の外積を求めて            the cross product of \vec{A} and \vec{B}
u と v の内積を求めて                        compute the dot product of u and v
\nabla \times \vec{A} と \vec{B} の内積を求めて  the dot product of \nabla \times \vec{A} and \vec{B}
```

オペランドは**助詞（と / の）や `of` / `and` までが1つ**で、空白では切れません。
次の形がベクトルとして読まれます。

| 書き方 | 例 |
|---|---|
| ベクトル場として宣言した名前（`\vec{}` 付きでも同じ） | `A`、`\vec{A}` |
| 成分を角括弧で並べた値 | `u = [1, 2, 3]` |
| 列ベクトル・行ベクトル | `u = \begin{pmatrix} 1 \\ 2 \\ 3 \end{pmatrix}` |
| ベクトルを返すナブラ演算 | `\nabla \times \vec{A}`（回転）、`\nabla f`（勾配） |

**丸括弧の組 `(1, 2, 3)` はベクトルとして読みません**（ノルムと同じ読み方）。
発散・ラプラシアンのようにスカラーを返す演算をオペランドにすると、理由を述べて断ります。
英語で微分表示を切り替えるときは **`dot notation` / `Leibniz notation`** と記法の語まで
書いてください（`dot` だけでは内積の文と区別できないため）。

### 4b. 積分（英語の綴り、2026-09-18）

```
integrate a x^2 over x            a x^2 を x で積分して          →  (a x³)/3 + C
integrate a x^2 with respect to x
the integral of a x^2 over x
integrate a x^2 over x from 0 to 1                              →  a/3
```

変数を導く語は **`over` / `with respect to` / `w.r.t.` / `by` / `in` / `for`** のどれでも
同じです（**境界を付けても外しても、微分でも積分でも同じ表**を読みます）。以前は英語だけ
被積分関数が式として扱われず、`integrate a x^2 over x` が**係数 `a` を変数と読んで**
`a x² + C` を返していました（微分側は `in` / `for` / `over` が同じ形で `0` を返していました）。

**座標系は変数ではありません。** `integrate x^2 in polar coordinates` のように座標系を
書くと、理由と**通る道**を述べて断ります——座標を変えるのは2段です:

```
definite-integrate x^2 + y^2 over the region x^2 + y^2 <= 1
Change variables in E1 from x,y to r,theta via x=r*cos(theta), y=r*sin(theta)
evaluate this integral                                        →  π/2
```

### 5. オペランドに書ける式

回転・発散・勾配・ラプラシアン・ノルム・行列式のオペランドには、名前だけでなく**式**が書けます。
係数も和も**そのまま計算に入ります**。

```
2 v の回転を求めて                  the curl of 2 v
v - 2 w の回転を求めて              the curl of v - 2 w
x v の回転を求めて                  （積の微分まで込み：x ∇×v + ∇x × v）
P + 2 B の発散を求めて              （値を与えたベクトル P と宣言したベクトル場 B の和）
\vec{v} \times \vec{w} の回転を求めて  the curl of \vec{v} \times \vec{w}
2 (v ~ w) の発散を求めて            the divergence of 2 (v ~ w)
v ~ w + r の発散を求めて            the divergence of v ~ w + r
2 u の勾配を求めて                  the gradient of 2 u
```

値を与えた名前（`v = [y, -x, 0]`）はその値の型で、宣言した名前は宣言の型で読みます。
**外積を含む式は、一般の操作にもかけられます**（2026-09-19）——`K = 2 (\vec{P} \times \vec{Q})`
と書いてから `K を簡約して` / `K を x で全微分して` / `K の x に 1 を代入して` が通ります。
以前はここで**生の CAS エラー**が返っていました（Maxima に `~` は無く、系は `nb_cross` を
使います。画面と canonical には研究者が書いた `\times` / `~` がそのまま残ります）。

**外積は式の中に埋まっていても読みます**（`2 (v ~ w)`・`x (v ~ w)`・`(v ~ w) + r`・
`(v ~ w) ~ r`）。どこまでが外積かは式の構文が決めるので、**括弧を書かなくても外積が先**です
——`v ~ w + r` は `(v ~ w) + r` です。
**2つのベクトルを並べただけの積**（`v w`）は内積か外積か決まらないので、理由を述べて断ります——
`v と w の内積を求めて` / `v と w の外積を求めて` と書いてください。

### 6. 入れ子のベクトル演算

```
\nabla \cdot (\nabla \times \vec{A})       ∇·(∇×A)       div(curl(A))
\nabla \times \nabla f                   A の回転の発散を求めて
\nabla \cdot \left(\nabla f\right)        the divergence of the curl of A
```

どの綴りも同じ値に着地します（$\nabla\cdot(\nabla\times A)=0$、$\nabla\times\nabla f=0$、
$\nabla\cdot\nabla f$ はラプラシアン）。括弧は省いても、`\left( … \right)` でも読めます。
**スカラーを返す演算の結果にベクトルの演算を重ねる**（$\nabla\cdot(\nabla\cdot A)$）と、
理由を述べて断ります。場は宣言した名前のほか、**H-1 で値を与えた名前**
（`u = x^2 + y^2` のあとの `\nabla u`、`v = [y, -x, 0]` のあとの `\nabla \times v`）でも計算されます。

## 英語で「操作名 式」と書く

英語では操作名を先に、式を後に書けます。**式は文末まで**読まれます。

```
simplify a x^2 + b x + c
factor x^2 - 1
normal order c^\dagger_{1\uparrow} c_{1\uparrow}
```

式が文末で終わらない書き方——`differentiate f with respect to x`、
`integrate f over x from 0 to 1`、`substitute x=2 into E1`——は、それぞれの操作が
自分の形で読みます。宣言（`Define k, m as scalars`）も別扱いです。

日本語は語順が逆（`式 を 操作して`）で、こちらは以前から読めていました。

## サイトとスピンを持つ演算子の記法（Julia セッション専用）

凝縮系でいちばん基本的な綴り——サイト番号とスピン射影の2添字——は、次のどれで
書いても同じ演算子になります。

| 書法 | 例 |
|---|---|
| LaTeX の下付き（推奨） | `c_{1\uparrow}`, `c^\dagger_{1\downarrow}`, `c_{k\sigma}` |
| 矢印そのもの | `c_{1↑}`, `c^\dagger_{2↓}` |
| 語 | `c_{1,up}`, `c_{2,dn}` |
| 関数形 | `c(1,\uparrow)`, `c'(1,u)` |

**スピンの射影（↑/↓）は「値」、スピン変数（σ）は「変数」**として扱われます。
矢印は和で束縛できない（`\sum_\uparrow` とは書かない）ので、異なる矢印は異なる値
であり、`\delta_{\uparrow\downarrow}` は 0 に評価されます。`\sigma` は文字のまま
残るので、`\sum_\sigma` の中の `\delta_{\sigma\sigma'}` は残ります。

```
c_{1\uparrow} と c^\dagger_{1\uparrow} の反交換子    → 1
c_{1\uparrow} と c^\dagger_{2\uparrow} の反交換子    → 0   （サイトが違う）
c_{1\uparrow} と c^\dagger_{1\downarrow} の反交換子  → 0   （スピンが違う）
c_{k\sigma} と c^\dagger_{k\sigma} の反交換子        → 1   （σ は変数のまま）
```

### 交換子・反交換子のオペランドは、積でも式番号でも名前でもよい

オペランドの区切りは助詞（`と` / `の`）とキーワード（`of` / `and`）で、空白では
ありません。演算子の**積**をそのまま片側に書けます。

```
c^\dagger_{1\uparrow} c_{1\uparrow} と c^\dagger_{1\downarrow} c_{1\downarrow} の交換子
E1 と c_{1\uparrow} の交換子
E1 と S_p の交換子                      （H-1 で名前を付けた式は名前で呼べる）
[c(1,u), c'(1,u)]                       （括弧記法。カンマは括弧の深さで判定）
{c(1,u), c'(1,u)}
[c(1,u), [c'(1,u), c(1,u)]]             （入れ子もそのまま）
```

英語も同じです（`commutator of A and B` / `anticommutator of A and B` /
`normal order <式>`）。

### 和の記法

範囲を書いた和は、**その範囲どおりに展開して**計算されます。範囲を書かない和は
形式和のまま扱われます（どちらも、書いたとおりの意味です）。

```
H = -w \sum_{\sigma} (c^\dagger_{1\sigma} c_{2\sigma} + c^\dagger_{2\sigma} c_{1\sigma})
    + U \sum_{i=1}^{2} c^\dagger_{i\uparrow} c_{i\uparrow} c^\dagger_{i\downarrow} c_{i\downarrow}
N = \sum_{i=1}^{2} (c^\dagger_{i\uparrow} c_{i\uparrow} + c^\dagger_{i\downarrow} c_{i\downarrow})
[E1, N]     → 0        （粒子数の保存）
```

$\prod_{i=1}^{n}$ も同じように展開されます。範囲が記号（$\sum_{i=1}^{N}$）のときは
展開できないので、形式和として扱われます。

### スピンについての和

`\sum_\sigma` は範囲を書きませんが、**宣言した粒子**からスピン射影の値集合が
決まるので、そこに展開されます。電子なら $m=\pm 1/2$ の2つ（↑ と ↓）です。

```
c を電子の消滅演算子として定義して          ← ここで値集合が決まる
H = -w \sum_{\sigma} (c^\dagger_{1\sigma} c_{2\sigma} + c^\dagger_{2\sigma} c_{1\sigma})
N = \sum_{i=1}^{2} \sum_{\sigma} c^\dagger_{i\sigma} c_{i\sigma}
[E1, N]     → 0
```

粒子を書かずに定義した場合や、値集合に1文字の書き方が無い場合（スピン1以上）は
展開せず、形式和のまま扱います。この場合、和どうしの交換子は簡約しきれずに
残ることがあります。

### 核スピン（NMR/NQR）

核スピン演算子は、修飾を付けたまま宣言できます。**核種を書けば、その核スピン $I$ が
記録され、確認メッセージに出ます。**

```
I を ^{13}C の核スピン演算子として定義して   → I = 1/2、射影は 2 通り
K を 27Al の核スピン演算子として定義して     → I = 5/2、射影は 6 通り
S を電子スピン演算子として定義して
```

核種は `13C` / `^{13}C` / `¹³C` / `C-13` のどれでも書けます。英語では
`define I as the nuclear spin operator of 13C` のように後ろに置いても読みます。

- **核種を書かないと何も推測しません。** 「核スピン演算子」だけなら演算子として
  登録され、$I$ は記録されません（「まだ言われていない」）。
- $^{12}$C のように $I=0$ の核種も表にあります（NMR-silent であることが書ける）。
- サイトごとに違うスピンを使う計算（超微細・異核種）は
  `サイト1のスピンを1/2、サイト2のスピンを1とする` で宣言します。
  **核種でも書けます**——`サイト1のスピンは 13C、サイト2のスピンは 27Al とする`
  （$I$ は表から決まるので、大きさを言い直す必要はありません）。

**実例:** [2サイト Hubbard 模型を最後まで計算するシナリオ](scenarios/scenario_hubbard_dimer_operator_algebra_jp.md)
——保存量・SU(2) 代数の導出・Pauli の恒等式・原子極限の厳密な時間発展が、すべて
計算結果として出ます。

## スピン成分演算子の記法（Julia セッション専用）

`S をスピン演算子として定義する` で定義したスピン演算子の**サイト付き成分**は、以下の 2 種類の書法で入力できます。

### 入力できる書法

| 書法 | 例 | 説明 |
|---|---|---|
| **サフィックス形式** | `Sz_1`, `Sx_k` | 成分を識別子のサフィックスとして表記（推奨） |
| **上付き形式** | `S^z_1`, `S^x_k` | 成分を LaTeX 上付きで表記 |

> **注意:** 下付き形式 `S_z_1`（S の直後にアンダースコア）は**使用できません**。  
> `S_z` は SymbolContext に登録された `Sz` とは別の識別子として解釈されます。

### 書法は最初の入力で宣言される

**セッション内で最初に使用した書法が、そのスピン演算子の表示スタイルとして記憶されます。**  
以降のすべての計算結果が同じ書法で表示されます。

| 最初の入力 | 以降の計算結果の表示 |
|---|---|
| `H = -gamma * B * Sz_1`（サフィックス） | `Sy_1`, `Sx_2` |
| `H = -gamma * B * S^z_1`（上付き） | `S^y_1`, `S^x_2` |

例えば上付き形式でハミルトニアンを入力した場合、交換子や EOM の結果も `S^y_1` のように表示されます。

## 最近接相互作用の展開（expand_neighbor_sum）（Julia / Maxima 両対応）

1次元鎖の最近接ボンド和 `Σ_{⟨ij⟩} body(i,j)` を、サイト数 N と境界条件を指定して
明示的な和に展開します。展開後は通常の式として交換子・平均場近似・簡約などに渡せます。

- **Julia セッション**: body はスピン演算子（`Sz_i` 等）。量子スピン鎖（Ising/Heisenberg）。
- **Maxima セッション**: body はスカラー格子項（古典 Ising `-J*s_i*s_j`、格子エネルギー、
  量子化学のクーロン/交換項など）。`s_i` は `s(1)` のような添字付きで展開されます。

### 引数

| 引数 | 内容 | 例 |
|---|---|---|
| `body` | 2サイト添字の演算子積（ユーザー記法） | `Sz_i*Sz_j`、`Sx_i*Sx_j + Sy_i*Sy_j + Sz_i*Sz_j` |
| `index1` / `index2` | site 添字名（相異なる2文字） | `i` / `j` |
| `n_sites` | 鎖のサイト数 N（≥2） | `4` |
| `boundary` | `open`（既定）または `periodic` | `periodic` |

### 展開規則

```
open      : body(1,2) + body(2,3) + … + body(N-1,N)
periodic  : 上記 + body(N,1)   （N≥3。2サイト環は二重結合を避ける）
```

### 自然言語での使い方

```
S をスピン演算子として定義する

S^z_i S^z_j の最近接和を 4 サイト 周期境界で展開して
→ Sᶻ(1)Sᶻ(2) + Sᶻ(2)Sᶻ(3) + Sᶻ(3)Sᶻ(4) + Sᶻ(4)Sᶻ(1)
```

- トリガ語: 「最近接和」「隣接和」「最近接相互作用和」「格子和」＋「展開」。
- 英語は**和の名詞**が引き金: `nearest-neighbor sum` / `nearest neighbour sum`
  （英式綴りも可）/ `neighbour sum` / `lattice sum` ＋ `expand`。本体は
  `sum of <本体>` に続き、`over` / `on` / `in` / `for` / 読点のどれかで終わります
  —— 日本語は助詞と字種が本体の境界になりますが、全 ASCII の英文では
  この語彙が境界です（`expand the neighbour sum of Sz_i Sz_j over a 4-site
  periodic chain`）。
- サイト数は「N サイト」（全角数字可）、境界は「周期境界」→ periodic、無指定/「開放端」→ open。
- site 添字（`_i`, `_j`）は body の下付きから自動検出されます（成分上付き `^z` は除外）。

板書に近い**和記号での入力**も使えます:

```
\sum_{\langle i j \rangle} S^z_i S^z_j を 3 サイト 周期境界で展開して
→ S^z_1 S^z_2 + S^z_2 S^z_3 + S^z_3 S^z_1
```

- `\sum_{⟨ij⟩}`／`\sum_{<ij>}`／Unicode `Σ_{⟨ij⟩}` を受け付け、山括弧の2文字が site 添字 (i,j)。
- サイト数 N と境界は記号自体には含まれないため、併記の「N サイト」「周期境界」から取ります。
- `\sum_{k}` のような単一添字和はボンド和ではないため、この展開は発火しません。

### 例（Ising 鎖・操作の直接呼び出し）

```
body=-J*Sz_i*Sz_j, index1=i, index2=j, n_sites=4
→ -J Sᶻ(1) Sᶻ(2) - J Sᶻ(2) Sᶻ(3) - J Sᶻ(3) Sᶻ(4)
```

site 添字（`_i`, `_j`）は `Sz_1` のように具体的サイト番号へ置換され、和全体が標準の
変換パイプラインで解決されます。スピン成分記法（`Sz_i` / `S^z_i`）はどちらも使えます。

### 全ペア和（分子・量子化学）

最近接ボンドではなく**全ペア** `Σ_{i<j}`（分子のクーロン項・対ポテンシャル、Madelung 型
格子和など）も `pair_constraint=all_pairs` で展開できます。NL では `\sum_{i<j}` 記法か
「全ペア和」で指定します。

```
q_i q_j の全ペア和を 3 サイトで展開して
→ q_1 q_2 + q_1 q_3 + q_2 q_3
```

**分子クーロン**のような **2添字のペア記号**（距離 `r_{ij}`、対ポテンシャル `V_{ij}`、
ボンド依存結合 `J_{ij}`）も両添字が置換されます:

```
q_i q_j / r_{ij} の全ペア和を 3 サイトで展開して
→ q_1 q_2 / r_{1,2} + q_1 q_3 / r_{1,3} + q_2 q_3 / r_{2,3}
```

ペア記号は `r_{ij}`・`r_i_j`・`r_{i,j}` のいずれの記法でも同じく `r(1,2)` 等に展開されます。

### 2D 格子（正方・三角）

正方格子・三角格子の最近接和も展開できます。格子サイズは `lattice_shape="LxxLy"`
（例 `"3x4"`、省略時は √n_sites の正方格子）で指定します。

```
Sz_i Sz_j の正方格子 3x3 の最近接和を展開して        → 12 ボンド（開放端）
S^z_i S^z_j の三角格子 3x3 周期境界で展開して          → トーラス上の三角格子
```

- 「正方格子／square lattice」→ 4近接、「三角格子／triangular lattice」→ 6近接（正方＋対角）。
- サイズは長方形可（`2x4`）。境界 `open`（有限平面）/`periodic`（トーラス）。
- 内部では 2D サイトを線形インデックスに写像してボンドを張るだけなので、body 記法は 1D と同じ。

ペア構造はプラガブルで、`nearest_neighbor`（1D 既定）・`all_pairs`・`square_2d`・`triangular_2d`・
`honeycomb_2d`（ハニカム）を内蔵。境界は `open`／`periodic`（トーラス）／`cylinder`（x のみ周期）。

**任意グラフ（分子・欠陥・名前のない格子）:** 内蔵の格子名（正方/三角/ハニカム）にない構造は、
「グラフ」＋ボンドの列を自然言語でそのまま指定して展開できます（分散関係の抽象結晶記述子と同じ
発想の逃げ道）。サイト数の指定は不要（ボンドリストがサイトを決めます）。

```
Sz_i Sz_j のグラフ (1,2),(2,3),(1,3) の最近接和を展開して
  → Sz_1 Sz_2 + Sz_2 Sz_3 + Sz_1 Sz_3       （三角形グラフ）
```

英語も同様です:

```
Expand the nearest-neighbor sum of Sz_i Sz_j over the graph (1,2),(2,3),(1,3)
```

内部的にはこれは `pair_constraint="custom"` ＋ `edges` を指定したのと同じです（`edges` は
`(1,2),(2,3)` 形式の文字列か `[(1,2),(2,3)]` のリストとしても渡せます）。格子＝隣接リストなので、
内蔵生成器で表せない構造（分子・格子欠陥・任意グラフ）はこれで何でも展開できます。

> **未対応の格子名を指定した場合:** 「ダイヤモンド格子」のように内蔵の格子名にない名前を指定すると、
> 黙って別の格子（1次元鎖など）にフォールバックすることはなく、明示的にエラーになります（未対応の
> 格子名一覧と、上記のグラフ記法への案内がエラーメッセージに含まれます）。

### シンボリック保持（展開せず後で具体化）

ボンド和の**数式をそのまま**（`-J \sum_{\langle i j \rangle} S^z_i S^z_j` のように展開動詞・サイト数
なしで）入力すると、**展開せずシンボリックに登録**され、`\sum_{⟨ij⟩}` の形のまま表示されます。
抽象的な Hamiltonian を書いておき、計算したいときに格子を決めて具体化する流れに使えます。

```
-J \sum_{\langle i j \rangle} s_i s_j        → E1（\sum 形のまま保持）
E1 を 正方格子 2x2 で展開して                 → 具体化（2×2 正方格子の明示和）
```

- 最近接 `\sum_{⟨ij⟩}` と全ペア `\sum_{i<j}` を保持できます（係数 `-J` 等は前置可）。
- 具体化時に格子種類（正方/三角/ハニカム）・サイズ・境界を指定できます。

**名前を付ける（等式形）:** `H = -J \sum_{⟨ij⟩} S^z_i S^z_j` のように名前を付けて登録でき、
以降は名前で具体化できます:

```
H = -J \sum_{\langle i j \rangle} s_i s_j      → H として保持
H を 三角格子 3x3 で展開して                     → 名前参照で具体化
```

**和を保ったままのパラメータ代入:** シンボリックなボンド和に対し、和を展開せずに body の
パラメータを置き換えられます（`Op(Σ body) = Σ Op(body)`）。

```
H = -J \sum_{\langle i j \rangle} s_i s_j     → H
H の J を 2t に置き換えて                       → H = -2t \sum_{⟨ij⟩} s_i s_j（和を保持）
H を 正方格子 2x2 で展開して                    → 各ボンド -2t（代入が伝播）
```

抽象的なまま記号計算を進め、最後に格子を決めて検証する流れに使えます。
- サイト演算子を消すような代入（平均場）・整理は後続の段階で対応予定。

**シンボリックな交換子（Heisenberg EOM、Julia スピンセッション）:** シンボリックなボンド和に
対し、局所演算子との交換子を**近傍和の形のまま**得られます。

```
H = -J \sum_{\langle i j \rangle} S^z_i S^z_j      → H
[H, S^x_n]                                          → \sum_{j∈nn(n)} -2J i\, S^y_n S^z_j （一般 EOM）
E2 を 正方格子 3x3 のサイト5で展開して               → -2J i\, S^y_5 (S^z_2+S^z_4+S^z_6+S^z_8)
```

一般的な EOM を記号で得て、特定の格子・サイトで具体化して検証できます。
- 現状は表示＋具体化まで（2段交換子などの合成は将来段階）。

### tight-binding 分散関係（バンド構造の解析導出）

ホッピング模型のハミルトニアンから、**ブロッホ表示の分散関係（バンド）を解析的な閉形式**で導出できます。
黒板でやる「ハミルトニアンを書く → Bloch 行列 → バンド」の流れを、決定論的に（CAS 非依存で）出します。

**できることの一覧:**

| 対象 | 例 | 命令の例 |
|---|---|---|
| 単一バンド（鎖/正方/三角） | `ε(k)=-2t(cos k_x+cos k_y)` | 「H の正方格子で分散関係を求めて」 |
| 〃 ＋次近接（t–t′） | 正方/鎖/三角の第2近接シェル | 「…次近接 t' を含めて…」 |
| 二部 2 バンド（ハニカム＝グラフェン） | `ε_±=±t√(3+2cos+…)` | 「H のハニカム格子で分散関係を求めて」 |
| 〃 ＋次近接 t'／質量 Δ／副格子別 t_α' | ギャップ付き Dirac 等 | 「…次近接 t' で／質量 Δ を含めて…」 |
| ≥3 副格子（Lieb の平坦バンド） | `ε=0, ±t√(4+2cos+…)` | 「H の Lieb 格子で分散関係を求めて」 |
| 非二部 3 副格子（カゴメ） | 平坦＋Dirac | 「H のカゴメ格子で分散関係を求めて」 |
| SSH（トポロジカル入口） | `ε_±=±√(v²+w²+2vw cos k)` | 「SSH 模型の分散関係を求めて」 |
| **任意結晶（抽象記述子）** | ボンド `(α,β,ΔR,振幅)` から Bloch 行列＋バンド | 「次のボンドで結晶の分散関係を求めて: …」 |

上の名前付き格子・SSH はすべて、最後の**抽象結晶記述子の特殊例**です。N≤2 は閉形式バンド、N≥3 は Bloch 行列
（バンドは Lieb/カゴメ型のテンプレートのみ閉形式）。

> **これは解析導出ツールであって数値バンド計算コードではありません。** Γ–K–M 経路に沿った実際のバンド図・
> DOS・フェルミ面・トポロジー量（Chern 数等）は対象外で、将来の数値拡張（`docs/open_items.md` F-1n）です。

以下、各機能の詳細です。

**分散関係 ε(k)（tight-binding・単一バンド）:** シンボリックなボンド和（ホッピング）に対し、
**分散関係**を求められます。単位胞のホッピング構造からブロッホ和 `ε(k)=Σ_{ΔR} 2t\cos(k·ΔR)` を
直接構成します（交換子を経由しません）。格子は指定がなければ鎖、`正方格子`／`三角格子`で上書き可。

```
H = -t \sum_{\langle i j \rangle} c'_i c_j     → H（ホッピングを保持）
H の分散関係を求めて                            → ε(k) = -2t \cos k                （鎖）
H の正方格子で分散関係を求めて                   → ε(𝐤) = -2t(\cos k_x + \cos k_y)   （正方）
H の三角格子で分散関係を求めて                   → ε(𝐤) = -2t(\cos k_x + \cos k_y + \cos(k_x+k_y))
```

- ホッピング振幅はボンド body の前置係数（`-t` 等）から取られます。
- `次近接 t' を含めて` と添えると第2近接シェルが加わります（t–t′ モデル）。例：正方格子なら
  `ε(𝐤) = -2t(\cos k_x+\cos k_y) - 2t'(\cos(k_x+k_y)+\cos(k_x-k_y))`、鎖なら `-2t\cos k - 2t'\cos(2k)`、
  三角格子なら `… - 2t'(\cos(k_x-k_y)+\cos(2k_x+k_y)+\cos(k_x+2k_y))`。

**多バンド（ハニカム＝グラフェンの2バンド）:** 二部 2 副格子の格子では、2×2 ブロッホ行列の
固有値として**2バンド** `ε_±(k)` が得られます。

```
H = -t \sum_{⟨ij⟩} c'_i c_j               → H
H のハニカム格子で分散関係を求めて          → ε_±(𝐤) = ±t√(3 + 2cos k_1 + 2cos k_2 + 2cos(k_1−k_2))
```

ここで `k_1, k_2` はプリミティブベクトル方向の換算運動量（`k·a_1`, `k·a_2`）です。

**次近接ホッピング（対角項）:** `次近接 t' を含めて` と添えると、同副格子ホッピング t' による
対角項 `d(k)` が加わります（ハニカムは A/B 対称で両バンド共通）。

```
H のハニカム格子で次近接 -t' を含めて分散関係を求めて
  → ε_±(𝐤) = -2t'(cos k_1 + cos k_2 + cos(k_1−k_2)) ± t√(3 + 2cos k_1 + 2cos k_2 + 2cos(k_1−k_2))
```

**質量項（副格子ポテンシャル）でギャップを開ける:** `質量 Δ を含めて`（または `副格子ポテンシャル Δ`）で、
スタガード副格子ポテンシャル（A:+Δ / B:−Δ）が入り、ギャップ付き Dirac 分散になります。一般式は
`ε_±(k) = (d_A+d_B)/2 ± √(((d_A−d_B)/2)² + |f|²)` で、対称な次近接は前半（band 平均）、Δ は √ の中に入ります。

```
H のハニカム格子で質量 \Delta を含めて分散関係を求めて
  → ε_±(𝐤) = ±√(Δ² + t²(3 + 2cos k_1 + 2cos k_2 + 2cos(k_1−k_2)))
```

**副格子ごとに異なる次近接振幅:** `次近接 t_A', t_B' を含めて`（カンマ区切りで2振幅）とすると、
A/B で異なる対角 `d_α=2t_α'S(k)` を持つ一般式になります。対称成分 `(t_A'+t_B')S` は band 平均
（√ の外）、反対称 `(t_A'−t_B')S`（＋質量 Δ）は √ の中に入ります。

**3 副格子以上（Lieb 格子の平坦バンド）:** 中心副格子が相互に繋がらない副格子に結合する star 構造の
格子では、**平坦バンド ε₀=0 ＋ 分散バンド ε_±** が厳密に得られます。

```
H の Lieb 格子で分散関係を求めて
  → ε_0 = 0,  ε_±(𝐤) = ±t√(4 + 2cos k_x + 2cos k_y)
```

カゴメ格子（非二部・3 副格子すべてが結合）も、閉三角形の恒等式で立方が因数分解でき、**平坦バンド＋
Dirac 2 本**が得られます。

```
H のカゴメ格子で分散関係を求めて
  → ε_flat = 2t,  ε_±(𝐤) = -t(1 ± √(3 + 2cos k_x + 2cos k_y + 2cos(k_x+k_y)))
```

**SSH 模型（1D ダイマー化鎖）:** セル内ホッピング v とセル間ホッピング w を持つ 1D 二部鎖の分散は、
自己完結のプリセットとして求められます（H の登録は不要）。`v=…, w=…` で振幅記号を上書きできます。

```
SSH 模型の分散関係を求めて        → ε_±(k) = ±√(v² + w² + 2vw cos k)
SSH模型 v=t_1, w=t_2 の分散関係を求めて  → ε_±(k) = ±√(t_1² + t_2² + 2 t_1 t_2 cos k)
```

**抽象結晶記述子（任意ボンド入力）:** 上記すべての名前付き格子を統一する一般表現として、結晶を
**ボンド `(α, β, ΔR, 振幅)`** のリストで直接定義できます（α,β=副格子番号、ΔR=セル変位の reduced 座標、
Hermitian 共役は自動付加）。Bloch 行列 `H̃(k)=Σ amp·e^{ik·ΔR}` を構成し、N≤2 は閉形式バンドも出ます。

```
次のボンドで結晶の分散関係を求めて: (0,1,(0),v),(0,1,(-1),w)
  → H̃(k) = [[0, v + w e^{-ik}], [v + w e^{ik}, 0]]   （SSH の Bloch 行列）
     ε_±(k) = ±√(v² + w² + 2vw cos k)
```

- N=1：スカラー（単一バンド）、N=2：一般 2×2 Hermitian 閉形式、**N≥3：Bloch 行列＋永年方程式 `det(H̃(k)−εI)=0`**
  （バンドはその根。一般 N×N の閉形式は Abel–Ruffini で原理的に不可なので、解析ではこの方程式の表示までが守備範囲。
  特別構造の Lieb/カゴメは閉形式テンプレートで対応済み）。SSH・グラフェン・質量項などはこの記述子の特殊例です。

**簡単な格子での記述例（N ごとの挙動を確認）:**

```
N=1（単副格子・1D 鎖、副格子 0 の自己ホッピング ΔR=(1) で単一バンド）:

次のボンドで結晶の分散関係を求めて: (0,0,(1),-t)
  → ε(k) = -2t cos k                         （行列は出ない・鎖の名前付き分散と同じ結果）

N=2（SSH と同じ形。上の例参照）:

次のボンドで結晶の分散関係を求めて: (0,1,(0),v),(0,1,(-1),w)
  → H̃(k) = [[0, v + w e^{-ik}], [v + w e^{ik}, 0]]
     ε_±(k) = ±√(v² + w² + 2vw cos k)

N=2（副格子ごとに逆符号のオンサイト項 ±M を足してギャップを開ける）:

次のボンドで結晶の分散関係を求めて: (0,0,(0),M),(1,1,(0),-M),(0,1,(0),-t)
  → ε_±(k) = (M-M)/2 ± √(((M+M)/2)² + t²)     （オンサイト項は ΔR=(0) の自己ボンドで指定）

N=3（3 副格子・一般には閉形式がなく永年方程式になる例）:

次のボンドで結晶の分散関係を求めて: (0,1,(0),a),(1,2,(0),b),(0,2,(0),c)
  → H̃(k) は 3×3 Bloch 行列
     det(H̃(k) - εI) = 0                       （閉形式の ε(k) は出ない — N≥3 の一般則）
```

> **現状の制限:** 格子は 1D 鎖・全ペア・正方/三角/ハニカム・任意グラフ（custom）、境界は
> open/periodic/cylinder に対応済み。記号交換子は表示＋具体化まで（2段交換子の合成は将来段階）。
> 分散関係は単一バンド（鎖/正方/三角）＋二部多バンド（ハニカム2バンド）＋次近接 t'＋質量 Δ まで実装。
> 副格子ごとに異なる一般 d_α・3 副格子以上の一般 N×N・単一バンドの多殻は将来段階。
> 詳細は `docs/open_items.md` F-1 参照。

### 有限グラフの隣接行列とグラフ不変量

無限系の分散（上）とは別に、**有限グラフ／クラスター**の隣接行列 A とその不変量を扱えます。A は具体的な
**整数行列**なので、固有値・冪・三角形数などが厳密に求まります（無限系の立方根問題は起きません）。

格子（正方/三角/ハニカム＋サイズ）・N サイト鎖・任意グラフ（`グラフ (1,2),(2,3),…`）から指定できます。

```
正方格子 2x2 の隣接行列を求めて          → 4×4 の隣接行列（以後 eigenvalues 等を連鎖可）
5サイトの鎖の次数列を求めて              → \deg = (1, 2, 2, 2, 1)
グラフ (1,2),(2,3),(1,3) の三角形の数を求めて   → \#△ = 1
グラフ (1,2),(2,3),(1,3) の隣接行列の固有値を求めて → 2, -1, -1（三角形のスペクトル）
```

隣接行列は**通常の行列式として登録**されるので、登録後に「固有値を求めて」「行列式」などの既存の行列演算を
そのまま続けて適用できます。tight-binding 有限クラスター・分子のスペクトルやスペクトルグラフ理論に使えます。

**スペクトルグラフ恒等式:** 任意の単純グラフで成り立つ一般定理（`tr A=0`, `tr A²=2|E|`, `tr A³=6N△`）を
表示でき、さらに具体グラフで**検証**できます（整数計算で両辺を突き合わせ）。

```
グラフの恒等式を表示して                      → tr A = 0, tr A² = 2|E|, tr A³ = 6N△
グラフ (1,2),(2,3),(1,3) で恒等式を確認して        → tr A² = 2|E| = 6, tr A³ = 6N△ = 6 （三角形1個）
```

### スピン演算子のネスト交換子（運動方程式・モーメント階層）

有限格子上のスピン模型（Heisenberg / Ising）について、スピン演算子の**交換子**$[H, S^\alpha_n]$（＝運動方程式
$dS/dt$）と、その**2段交換子**$[H,[H,S^\alpha_n]]$（＝加速度 $d^2S/dt^2$・モーメント階層の起点）を求められます。
内部の合成可能なスピン代数（su(2) 交換関係＋Leibniz則）が結果を記号データで保持するので、**1段目の結果を
2段目にそのまま合成**できます。

```
イジング模型 2サイトで S^x_1 の交換子を求めて        → [H, S^x_1] = i J S^y_1 S^z_2
イジング模型 2サイトで S^x_1 の二重交換子を求めて      → [H, [H, S^x_1]] = J² S^x_1 (S^z_2)²
ハイゼンベルク模型 3サイト鎖で S^x_2 の二重交換子を求めて → 近傍 (1,3) の二重和（干渉項 2J² S^z_1 S^x_2 S^z_3 を含む）
```

格子は正方/三角/ハニカム＋サイズ、N サイト鎖、任意グラフ（`グラフ (1,2),…`）で指定できます。係数は Gauss 整数
×結合定数の厳密な記号で、スピンの大きさによる $(S^z)^2$ 等の数値化（spin-½ で 1/4 等）は行わず演算子のまま保持します。

模型は **Heisenberg / Ising / XXZ（J_z 異方性）/ XY** に対応し、**横磁場**（`-h Σ S^x_i`）・縦磁場（`S^z`）を
加えられます。ネストの次数も任意です（「3段交換子」で $[H,[H,[H,O]]]$）。

```
XXZ模型 2サイトで S^x_1 の交換子を求めて          → -i J S^z_1 S^y_2 + i J_z S^y_1 S^z_2
横磁場イジング模型 2サイトで S^z_1 の交換子を求めて   → [H, S^z_1] = i h S^y_1 （場による歳差）
イジング模型 2サイトで S^x_1 の3段交換子を求めて      → i J³ S^y_1 (S^z_2)³
```

**∞温度モーメントと連分数（recursion 法）:** spin-½・無限温度での偶モーメント $M_{2k}=(L^kO, L^kO)$
（$L=[H,\cdot]$、内積 $(A,B)=\langle A^\dagger B\rangle$）と、演算子 Lanczos による連分数係数 $b_n^2$ を求められます。
これは高温展開・スペクトル関数の連分数表示の入力になります。

```
イジング模型 2サイトで S^x_1 の2次までのモーメントを求めて → M_0 = 1/4, M_2 = J²/16
イジング模型 2サイトで S^x_1 の4次までのモーメントを求めて → M_0, M_2, M_4
イジング模型 2サイトで S^x_1 の2段までのモーメントを求めて → M_0, M_2, M_4（段数で指定）
イジング模型 2サイトで S^x_1 の連分数を求めて              → b_1² = J²/4 （以降は早期終了）
```

**「n次」と「n段（＝深さ n）」は別の指定です。** モーメントは偶数次しかない
（$M_0, M_2, M_4, \dots$。奇数次は無限温度で 0）ので、

| 書き方 | 意味 | 例 |
|---|---|---|
| `n次まで` / `up to nth order` | **モーメントの次数** $M_n$ まで | `4次まで` → $M_0, M_2, M_4$ |
| `n段まで` / `深さ n` / `up to depth n` | **recursion を n 回**（$M_{2n}$ まで） | `2段まで` → $M_0, M_2, M_4$ |

奇数を書いた場合（`3次まで`）は $M_0, M_2$ が返ります——奇数次は恒等的に 0 なので、
それが「3次まで」の答えです。何が返ったかは各項のラベル（$M_0$, $M_2$, …）が言います。

**連分数は「次」も「段」も同じ数**です。連分数の n 次近似とは係数
$b_1^2 \dots b_n^2$ を持つ段のことで、数えている物がモーメントとは違います。

内積・トレースは spin-½ 無限温度を仮定し、単一サイトで $(S^a)^2=1/4$ 等に簡約して評価します（交換子計算自体は
スピンの大きさに依らず演算子のまま）。

**一般式（展開せず配位数 z で）:** 具体格子に展開せず、**配位数 z を含む一般式**でモーメント・連分数を求められます。
2次モーメントは異なるボンドの交差項がトレースで消えるため、代表ボンド1本の寄与 × z で厳密に閉じます。

```
ハイゼンベルク模型で一般の格子の S^x の2次モーメントを求めて → M_0 = 1/4, M_2 = (1/8) z J²
イジング模型で配位数 z の S^x の連分数を求めて              → b_1² = (1/4) z J²
```

z を具体値にすると上の具体格子の結果（例：鎖の内部サイト z=2）を再現します。

## ノルム

ベクトルの大きさと、行列のノルムを求められます。

```
E1 のノルムを求めて / E1 の大きさを求めて       ← ベクトル（2ノルム）
compute the norm of E1 / the magnitude of E1
E1 の Frobenius ノルムを求めて                 ← 行列（種類を書く）
E1 のスペクトルノルムを求めて
E1 の最大絶対列和を求めて / E1 の最大絶対行和を求めて
compute the Frobenius / spectral / 1-norm / infinity norm of E1
```

**ベクトルは種類が要りません。** `\|v\|` は2ノルム（大きさ）で、これは記法の慣用です。

**行列は種類を書いてください。** Frobenius・スペクトル・最大絶対列和・最大絶対行和は
どれも別の値なので、書かなければ**種類を名指して断ります**——既定を1つ選ぶのは、
問題によって変わる数学の選択をシステムが勝手にすることになるからです。

**ベクトルの書き方。** `\begin{pmatrix} 3 \\ 4 \end{pmatrix}`（列ベクトル）や
`v = [1, 2, 3]`（成分）と書くか、ベクトル場として宣言してください。
**丸括弧の組 `(3, 4)` はベクトルとしては読みません**し、**平坦な2要素の角括弧は
交換子です**（`[3, 4]` は `3·4 − 4·3`）ので、2成分ベクトルはその綴りでは書けません。

**1行/1列の行列はベクトルとして扱います**（Frobenius もスペクトルも2ノルムと一致
するので、そこで選択は起きていません）。種類を書けばその値が返ります。

**記法でも書けます。**

```
\|v\|  /  ||v||  /  \|E1\| を計算して  /  compute \|E1\|
\begin{Vmatrix} 3 \\ 4 \end{Vmatrix}
\|E1\| の Frobenius ノルムを計算して        ← 行列は種類を添える
```

**`=` を含む形は「求めよ」ではなく「述べた式」として扱います。**
`\|v\| = 5` は「大きさは5である」という主張、`E2 = \|v\|` は定義なので、
計算はしません。計算したいときは記法だけを書くか、言葉で書いてください。

**単一の縦棒 `|x|` はノルムではありません**（絶対値か行列式かを確認します）。

**エネルギーモーメントと三角形数（高温展開）:** ∞温度のエネルギーモーメント $\langle H^n\rangle$（高温展開係数）は、
グラフ不変量で表せます：$\langle H^2\rangle = c_2|E|$（辺数 $=\frac12\mathrm{tr}\,A^2$）、$\langle H^3\rangle = c_3|E| + d_3 N_\triangle$
（三角形数 $=\frac16\mathrm{tr}\,A^3$）。**3次モーメントに三角形数が現れる**のが要点で、これは 3c-graph の `tr A³` と
スピン代数を繋ぐ橋です。

```
ハイゼンベルク模型の高温展開を一般式で求めて        → ⟨H²⟩ = (3/16)J²|E|, ⟨H³⟩ = (9/32)J³N△ − (3/32)J³|E|
イジング模型の高温展開を一般式で求めて              → ⟨H²⟩ = (1/16)J²|E|, ⟨H³⟩ = (3/32)J³N△ （純・三角形）
ハイゼンベルク模型 正方格子 3x3 の高温展開を求めて   → 具体値（|E|=12, N△=0 → ⟨H³⟩=−9/8 J³）
```

三角形を持つ格子（三角格子・ハニカムの一部）と持たない格子（正方）で $\langle H^3\rangle$ が変わる、という物理が
そのまま出ます。

**一般スピン S（spin>½）:** `一般スピンで` と添えると、モーメントを **$x=S(S+1)$ の多項式**として返します
（単一サイトトレースを √ 閉路ペアリング＋$x$ での厳密補間で評価）。$S=\frac12$ つまり $x=\frac34$ を代入すると
上の spin-½ 値を再現します。

```
ハイゼンベルク模型の一般スピンでの高温展開を求めて
  → ⟨H²⟩ = (1/3)J²x²|E|,  ⟨H³⟩ = (2/3)J³N△x³ − (1/6)J³x²|E|   (x = S(S+1))
```

既知の単一サイト値：$\langle S^aS^b\rangle=\frac{x}{3}\delta_{ab}$、$\langle S^xS^yS^z\rangle=\frac{i}{6}x$、
$\langle (S^z)^4\rangle=\frac{3x^2-x}{15}$。

`4次まで` と添えると $\langle H^4\rangle$ も出ます。これは **4-cycle（四角形）数 $N_\square$**（$\mathrm{tr}\,A^4$ 由来）を含み、
3次の三角形に続く次の loop が現れます（代表クラスタからのフィットで厳密に決定・検証済み）。

```
ハイゼンベルク模型の高温展開を一般式で4次まで求めて

> **書いた次数が届かないときは断ります。** 一般式（配位数 $z$ の記号形）で閉じて
> いるのは $M_2$ と $b_1^2$ まで、高温展開は 2〜4 次までです。それを超える次数を
> 書くと理由付きで断り、**格子を具体的に書けば次数が効く**ことを案内します
> （例:「ハイゼンベルク模型 3サイト鎖で S^x_2 の4次までのモーメントを求めて」）。
  → ⟨H⁴⟩ = (9/32)J⁴N□ − (9/32)J⁴N△ − (3/32)J⁴·wedge − (3/128)J⁴|E| + (27/256)J⁴|E|²
ハイゼンベルク模型 正方格子 2x2 の高温展開を4次まで求めて → 具体値（N□=1）
```

**比熱の高温展開（有限温度）:** これらのモーメントから、**比熱 $C(\beta)$ の高温展開**（有限温度の観測量）を組めます。
$C(\beta)=\kappa_2\beta^2-\kappa_3\beta^3+\frac12\kappa_4\beta^4+O(\beta^5)$（$\kappa_n$ は連結なエネルギー累積量）で、格子
ループが次数ごとに現れます（$|E|$ が $\beta^2$、$N_\triangle$ が $\beta^3$、$N_\square$ が $\beta^4$）。

```
ハイゼンベルク模型の比熱の高温展開を一般式で求めて → C(β) = (3/16)J²|E|β² − … + (9/64)J⁴N□β⁴ + O(β⁵)
ハイゼンベルク模型 正方格子 2x2 の比熱の高温展開を求めて → (3/4)J²β² + (3/8)J³β³ − (3/32)J⁴β⁴ + O(β⁵)
```

（スピン>½ は一般スピンの単一サイトトレース評価が別途必要で将来段階。現状は spin-½・無限温度起点の高温展開です。）

**スペクトル関数（連分数・recursion 法）:** 連分数係数 $b_n^2$ から **Green 関数** $G(z)=1/(z-b_1^2/(z-b_2^2/\cdots))$ を
組み、有限クラスタでは連分数が**有限終端**して厳密な有理関数になります。**単一モード**（係数1本）では厳密な
**スペクトル関数** $S(\omega)=\tfrac12[\delta(\omega-\omega_0)+\delta(\omega+\omega_0)]$（$\omega_0=\sqrt{b_1^2}$）が出ます。

```
イジング模型 2サイトで S^x_1 のスペクトル関数を求めて → S(ω) = ½[δ(ω−J/2) + δ(ω+J/2)]（スピン歳差）
ハイゼンベルク模型 3サイト鎖で S^x_2 のグリーン関数を求めて → 入れ子連分数 G(z)（多モード）
```

**多モードの極・重み（閉形式）:** 係数2本までは極と重み（留数）を閉形式で抽出します。例：Heisenberg 3鎖の
S^x₂ → 中心ピーク＋ $\pm\sqrt{b_1^2+b_2^2}=\pm 3J/2$、$S(\omega)=\tfrac59\delta(\omega)+\tfrac29\delta(\omega\mp\tfrac32 J)$
（重みの総和＝1）。係数3本以上で根号が単項式にならない場合は有理形 $G(z)=P(z)/Q(z)$ を表示（極＝分母 Q の根）。

**無限系の連続バンド（平方根終端）:** 係数が一定値 $b_\infty$ に収束する無限系では、尻尾の連分数が**平方根終端**
$t(z)=(z-\sqrt{z^2-4b_\infty^2})/2$ に和され、離散デルタではなく**連続バンド**になります。一様鎖の解析的
スペクトル密度は Wigner 半円 $S(\omega)=\sqrt{4b_\infty^2-\omega^2}/(2\pi b_\infty^2)$（バンド $|\omega|\le 2b_\infty$）です。

```
平方根終端の連続スペクトル密度を求めて
  → t(z) = (z − √(z²−4b∞²))/2,  S(ω) = √(4b∞²−ω²)/(2πb∞²)  （|ω|≤2b∞）
```

これらは**解析的閉形式まで**が守備範囲です。具体的な数値プロット・係数3本以上の極の数値・$b_\infty$ の数値外挿は
範囲外（将来の数値基盤 F-1n）。

**回転座標系変換（NMR/ESR）:** 磁場中の1スピンについて、ラボ系ハミルトニアン
$H_{\rm lab}=-\omega_0 S^z-\omega_1 S^x$ を回転座標系（周波数 $\omega$、z 軸まわり）へ移した
**有効ハミルトニアン**を求められます。$U=e^{-i\omega t S^z}$ のフレーム項 $+\omega S^z$ が加わり、
$H_{\rm rot}=-\Omega S^z-\omega_1 S^x$（$\Omega=\omega_0-\omega$ 離調）になります。

```
回転座標系の有効ハミルトニアンを求めて
  → H_rot = -Ω S^z_1 - ω_1 S^x_1 （Ω = ω_0 - ω）,  ω_eff = √(Ω² + ω_1²),  [H_rot, S^z_1] = i ω_1 S^y_1
```

有効磁場 $\omega_{\rm eff}=\sqrt{\Omega^2+\omega_1^2}$ と回転系での歳差（Rabi 章動）も同時に出ます。
これにより磁気共鳴（NMR/ESR）ドメインの中心的な計算が回ります。

### 格子図の TeX 出力

`expand_neighbor_sum` で展開した格子は、**TeX エクスポート時に格子図（TikZ）が展開式の隣に
自動挿入**されます。サイトを線形インデックス、ボンドを線で描き、周期境界の巻きボンドは破線。
これで「生成器が作った格子が望みの形か」を論文上で確認できます。

- プリアンブルに tikz を自動追加（英: `\usepackage{tikz}`、日: `\usepackage[dvipdfmx]{tikz}`）。
- 別マシンでコンパイルする場合、そのマシンの TeX に TikZ があるか `kpsewhich tikz.sty` で確認できます
  （パスが表示されれば導入済み。MacTeX は同梱、BasicTeX は `sudo tlmgr install pgf standalone`）。

**図単体の保存:** 「格子図を保存して」（`save the lattice figure`）で、直近に展開した格子の図を
`sessions/` に **SVG ＋ standalone TeX** として保存します（ローカルに LaTeX があれば PDF も）。
ビューアで素早く確認したいときや、図を単独で共有したいときに使います（TeX 本文への埋め込みは
エクスポート時に自動なので、この保存は別物）。

## Heisenberg 方程式の計算（Julia セッション専用）

第二量子化セッションで演算子の時間発展（Heisenberg 運動方程式）を計算します。

### 入力形式

```
a_1 の Heisenberg 方程式 E1
Sm_1 の Heisenberg 方程式 E1
E1 と a(1) のハイゼンベルク方程式
E1 のもとでの a(1) のハイゼンベルク方程式を求めて
Heisenberg equation of a(1) for E1
the Heisenberg equation of a(1) under E1
```

- `a_1`、`Sm_1` のように**演算子名 + `_` + サイト番号**の形式で演算子を指定します
- `E1` はハミルトニアンの式番号です（タイムラインで確認してください）
- ハミルトニアンを省略した場合は直近のハミルトニアン式を自動参照します（複数候補がある場合は確認ダイアログ）
- **表記も語順も問いません**——`Heisenberg`／`ハイゼンベルク`／`ハイゼンベルグ`、
  `運動方程式` の有無、ハミルトニアンが先か演算子が先か。どちらがどちらかは
  **位置ではなく助詞（`のもと`／`と`）・前置詞（`of`/`for` … `under`）が決めます**

### 結果の形式

QuantumAlgebra.jl は `i[H, A]` を計算し、結果を Cartesian 基底で返します。  
表示書法（サフィックス `Sz_1` か上付き `S^z_1` か）はセッション最初の入力に従います（上記参照）。  
$S^-$ などの梯子演算子形式への変換は `collect_spin_pm` を使用してください。

## 量子演算子代入（Julia セッション専用）

第二量子化セッションで量子演算子を別の演算子の線形結合に置き換えます。Bogoliubov 変換・正準変換・偏光分解などに使います。

### 基本の使い方

```
c を電子のフェルミオン演算子として定義する
g を準粒子のフェルミオン演算子として定義する
xi, u, v, Delta をスカラーパラメータとして定義する

H = IndexSum(xi c'(k) c(k) - Delta c'(k) c'(-k) - Delta c(-k) c(k), k)   ← E1

E1 の c(k) に u g(k) + v g'(-k) を代入する   ← Bogoliubov 変換
```

結果は `normal_form()` で整理されて返ります。

### 記号添字は既定で「すべての添字」を意味する

書かれた添字が**記号**（`k`, `i`）のとき、代入は**その添字を持つすべての演算子**に
掛かります。Bogoliubov 変換はまさにそれを意図した書き方です（`c(k) → u g(k) + v g'(-k)`
は「すべての k について」）。

平均場のように**片方の添字だけ**を置き換えたい場合は、演算子に `だけ` / `のみ`
（英語では `only`）を添えます：

```
H = J Sz_i Sz_j                       ← E1

E1 の Sz(i) に Mz を代入して            → H = Mz^2 J        （両方が置き換わる）
E1 の Sz(i) だけに Mz を代入して        → H = J Mz Sz_j     （i だけ）
```

英語では `In E1, substitute Mz for Sz(i) only` と書きます。

**`だけ` は演算子の呼び出し（添字ごと）に添えてください。** `Sz(i) だけ` は
「その添字の Sz」を指しますが、`Sz だけ` は「Sz という演算子だけ（Sy ではなく）」の
意味になり、添字については何も言っていないためです。

**具体的な添字（`Sz(1)`・`Sz(A)`）には `だけ` は要りません** —— サイト番号や
副格子ラベルは1箇所しか指しようがないので、自動的にその添字だけが置き換わります。

### BCS 超伝導（スピン添字なし）

スピンを `a`（アップ）と `b`（ダウン）の別演算子で表現する場合、同時代入が必要です：

```
E1 の a(k) に u alpha(k) + v beta'(-k) を、b(-k) に u beta(-k) - v alpha'(k) を代入する
```

`a` と `b` が**異なる演算子**の場合は自動的に多ルール同時代入になります。

> **⚠ 注意 — スピン演算子を別々に宣言する場合の制限**  
> `a をフェルミオン演算子として定義する` と `b をフェルミオン演算子として定義する` を**別々に宣言**すると、QuantumAlgebra.jl では `a` と `b` の間の交換関係が**交換（commute）**として扱われます。`operator_substitute` で `a` と `b` が完全に置き換わる場合は問題になりませんが、代入前に H を `normal_order` や交換子計算にかけると物理的に誤った結果になります。
>
> **推奨**: 下記「スピン添字あり」の 2添字演算子アプローチを使う。単一 `@fermion_ops c` で宣言した `c(k, ↑)` と `c(k, ↓)` は正しく反交換します。

### BCS 超伝導（スピン添字あり）

単一の演算子 `c(k, σ)` で両スピンを表現する場合：

```
c をフェルミオン演算子として定義する
g を準粒子フェルミオン演算子として定義する

E1 の c(k, ↑) に u g(k, ↑) + v g'(-k, ↓) を、c(-k, ↓) に u g(-k, ↓) - v g'(k, ↑) を代入する
```

スピン記法（`↑`/`↓`、`\uparrow`/`\downarrow`、`up`/`dn`）は自動的に正規化されます。

### 円偏光の分解（ボゾン）

```
a を光子のボゾン演算子として定義する
b をボゾン演算子として定義する

H = IndexSum(omega a'(k,R) a(k,R) + omega a'(k,L) a(k,L), k)   ← E1

E1 の a(k,R) に (1/sqrt(2))*(b(k,x) - i*b(k,y)) を、a(k,L) に (1/sqrt(2))*(b(k,x) + i*b(k,y)) を代入する
```

`i` は Julia の虚数単位 `im` に自動変換されます（`i` が未宣言の場合）。随伴も正しく複素共役されます。

### CAS 由来式への代入制限

`E2` が `E1` への `operator_substitute` の結果（QA が計算した式、`_nb_E2` 形式）の場合、さらに `E2` に代入することはできません。元の式 `E1` に最初から多ルールで代入してください。

ただし **SymPy 式**（代数インデックス演算後の結果）への `substitute` は対応しています。例えば交換子計算後に `k→p` のインデックス置換を行うことができます。

## 演算子を共通因子としてまとめる（collect_by_operators）（Julia セッション専用）

演算子積を共通因子として、複数の項の係数を合算します。Bogoliubov 変換後など、同じ演算子積を含む項をまとめる際に使います。代数インデックス（`-k`, `k+q`）を含む SymPy 式に対して動作します。

### 基本の使い方

```
c をフェルミオン演算子として定義する
xi, u, v をスカラーパラメータとして定義する

E1 = -u^2 * xi * c'(k) * c(-k) + v^2 * xi * c'(k) * c(-k)   ← E1

E1 を演算子でまとめて
```

結果: `(v² - u²) ξ · c†(k)c(-k)` — 同じ演算子積 `c†(k)c(-k)` を持つ項が係数 `(v²-u²)ξ` としてまとまります。

## 演算子恒等式代入（operator_identity）（Julia セッション専用）

`substitute` 操作の第3ルーティングとして自動起動します（LHS が量子演算子の場合）。CAS 計算済みの QuExpr 結果に対して、演算子を別の演算子や線形結合に置き換えます。

```
c をフェルミオン演算子として定義する
alpha をフェルミオン演算子として定義する

E2 の c を alpha で置き換えて   ← operator_identity: c(i) → alpha(i)
```

スカラー置換も対応:

```
S をスピン演算子として定義する
n をスカラーパラメータとして定義する

E2 の Sz を (1-2*n)/2 で置き換えて   ← Sz(i) → (1-2*n)/2
```

## Sx/Sy を Sp/Sm 記法で整理（collect_spin_pm）（Julia セッション専用・表示専用）

ハイゼンベルク EOM や JC モデルの計算結果（Sx/Sy/Sz 表示）を、ユーザー定義の梯子演算子（Sp/Sm）記法で整理します。**表示専用操作**で式番号は割り当てられません。計算の継続は元の QuExpr（EOM 結果等）から行います。

### 定義と使い方

```
# ① 梯子演算子を定義（H-1 で登録）
Sp = Sx(1) + im*Sy(1)
Sm = Sx(1) - im*Sy(1)

# ② ハミルトニアンと EOM を計算（普通に Sx/Sy 基底で）
H = J * (Sx(1)*Sx(2) + Sy(1)*Sy(2) + Sz(1)*Sz(2))
E5 の E2 のハイゼンベルク方程式      ← EOM 結果が Sx/Sy 表示で得られる

# ③ 表示を整理（いつでも呼べる・式番号は出ない）
「E5 を Sp/Sm でまとめ直して」
→ (-2Ji) Sm(1) Sz(2) + (2Ji) Sm(2) Sz(1)   ← 表示のみ
```

その後も E5 は QuExpr として利用可能:

```
E6 = normal_order(E5)           ← E5 から継続
「E6 を Sp/Sm でまとめ直して」    ← E6 の表示を整理
→ ...                            ← 表示のみ（式番号なし）
```

### Sz をコンテキストとして保持

多サイト系（Heisenberg モデル等）では `Sz` はコンテキスト演算子として自動的に保持されます:

```
# EOM が Sx(1)*Sz(2) 型の項を含む場合も正しく処理
heisenberg_eom → -2Ji·Sx(1)·Sz(2) + ... → (-2Ji) Sm(1) Sz(2) + ...
```

## 演算子ペア → c-number 置換（pair_substitute）（Julia セッション専用）

n 次演算子積の中から特定の2演算子積を c-number（スカラー値）に置き換えます。数密度演算子の置換（Hartree 近似の第一段階）などに使います。

### 基本の使い方

```
c をフェルミオン演算子として定義する
n_k, Delta をスカラーパラメータとして定義する

H = xi c'(k) c(k) + xi c'(-k) c(-k)  ← E1

E1 の c'(k)*c(k) を n_k で置換して   ← pair_substitute
```

`pair_rules` として置換ルールを複数指定できます。`pattern` は**式入力と同じユーザー記法**で書けます
（H-3）。プライムで生成演算子、`*` で演算子積、`-k` で運動量反転を表します:

| ユーザーが書く | 意味 |
|---|---|
| `c'(k)*c(k)` | 数密度演算子ペア |
| `c'(-k)*c(-k)` | 反転運動量の数密度ペア |
| `c'(k)*c'(-k)` | BCS 対生成ペア |
| `Sz_1*Sz_2` | スピン演算子積（スピンセッション） |

内部の bares 表示（`c†(K) c(K)` の Unicode 上付き・`-k→K` 変換）をユーザーが知る必要はありません
— 入力は Julia 側で同じ正規化機構に通して照合されます。マッチは演算子の並び順に依存しません
（`c'(k)*c'(-k)` と `c'(-k)*c'(k)` は同一視）。なお旧来の bares 表示（`c†(k) c(k)`）も後方互換で
受け付けます。多添字（運動量＋スピン）の演算子 `c'(i,s)*c(l,s)` もそのまま使えます。

**2演算子ペア専用です。** `pair_substitute` は項全体が一致する**2演算子積**を c-number に置換します。
4フェルミオン相互作用 `c'(i,s)*c'(j,p)*c(k,p)*c(l,s)` のような**3個以上の演算子積**を pattern に与えると、
演算子数を検知してエラーとなり `wick_contract` の使用を案内します（順序非依存マッチがフェルミ符号を
取りこぼすのを防ぐため）。相互作用の平均場分解（ペアを期待値に潰して残りを保持）は `wick_contract`
を使ってください。

## Wick 収縮（wick_contract）（Julia セッション専用）

n 次演算子積の中から指定した演算子ペアを取り出し、そのペアを c-number に置き換えつつ残りの演算子積を保持します。Hartree-Fock（HF）近似・BCS 平均場理論のデカップリングに使います。

### 基本の使い方

```
c をフェルミオン演算子として定義する

H = c'(k,u) c'(-k,d) c(-k,d) c(k,u)  ← E1

E1 を Wick 収縮して：
  c†(k,σ)c(p,τ) の期待値は rho(k,σ,p,τ)
  c(k,σ)c(p,τ) の期待値は kappa(k,σ,p,τ)
  c†(k,σ)c†(p,τ) の期待値は kappaStar(k,σ,p,τ)
```

### 出力

全ての可能な収縮項が**個別の式**（各 E-ID）として列挙されます。

```
E3: -ρ(k,↑,-k,↓) · c†(-k,↓) c(k,↑)   [ρ / Fock項]
E4: +ρ(k,↑,k,↑)  · c†(-k,↓) c(-k,↓)  [ρ / Hartree項]
E5: +ρ(-k,↓,-k,↓)· c†(k,↑) c(k,↑)   [ρ / Hartree項]
E6: -ρ(-k,↓,k,↑) · c†(k,↑) c(-k,↓)  [ρ / Fock項]
E7: -κ(-k,↓,k,↑) · c†(-k,↓) c†(k,↑) [κ / 異常平均]
E8: +κ*(k,↑,-k,↓)· c(-k,↓) c(k,↑)   [κ* / 異常平均共役]
```

その後、物理的考察（または LLM Adviser の提案）に基づいて残す項を選択します：

```
E3, E4, E5, E6, E7, E8 のうち E4, E5, E7, E8 を足してH_MFとして定義して
```

### 収縮値の標準記法

| 記号 | 定義 | 意味 |
|---|---|---|
| **ρ**（4添字） | $\rho(k,\sigma;\,p,\tau) = \langle a^\dagger(k,\sigma)\,a(p,\tau)\rangle$ | 一粒子密度行列（1-RDM） |
| **κ**（4添字） | $\kappa(k,\sigma;\,p,\tau) = \langle a(k,\sigma)\,a(p,\tau)\rangle$ | 異常密度行列（BCS 対消滅） |
| **κStar**（4添字） | $\kappa^*(k,\sigma;\,p,\tau) = \langle a^\dagger(k,\sigma)\,a^\dagger(p,\tau)\rangle$ | 異常密度行列共役 |

**ρ は V^{HF} そのものではありません。** 個々の収縮値 ρ を相互作用ポテンシャルで畳み込んだものが HF ポテンシャル $V^{HF}$ になります：

$$V^{HF}(k,\sigma;\,p,\tau) = \sum_{q,\nu}\,v(k\sigma q\nu;\,p\tau q\nu)\,\rho(q,\nu;\,q,\nu)$$

### value テンプレートの書き方

| テンプレート | 収縮値 | 用途 |
|---|---|---|
| `"rho"` | plain scalar ρ | 簡単なケース |
| `"rho(INDEX1,INDEX2)"` | $\rho(k,\,p)$ | 運動量のみ |
| `"rho(INDEX1_0,INDEX1_1,INDEX2_0,INDEX2_1)"` | $\rho(k,\sigma,p,\tau)$ | 運動量＋スピン（**推奨**） |

`INDEX1_0` = op1 の第1インデックス（運動量）、`INDEX1_1` = op1 の第2インデックス（スピン）。

### 定数項（ダブル収縮）

`include_constant: True` を指定すると、さらに収縮を重ねた定数（スカラー）項も出力します。自由エネルギーの計算などに必要な場合に使います。

### 高次項への適用

一度の Wick 収縮で次数が 2 下がります。6次項を2次にするには 2 回繰り返します：

```
6次項 E1 を Wick 収縮 → 4次項 E2〜E10（を選択）
選択した 4次項 E5 を Wick 収縮 → 2次項 E11〜E14（を選択）
```

## 定義と代入

### 定義（LHS = RHS 形式）

式を「名前付き」で登録すると、以降その名前で参照・展開できます。

```
H_0 = p^2 / (2*m)     ← H_0 を定義（E1）
H_1 = -k * (x - a)^2  ← H_1 を定義（E2）
H = H_0 + H_1         ← H を定義（E3）
```

定義した名前は `lhs_alias_map` に記録され、「再評価」操作で値を展開できます。

### 定義（文で書く形）

`=` を使わず、文で書くこともできます。**同じ形の文が、続く語によって2つに分かれます。**

| 打つ文 | 何になるか |
|---|---|
| `x を 3 とする` / `set x to 3` / `let x be 3` | 定義 `x = 3` |
| `x を a + b とする` / `set x to a + b` | 定義 `x = a + b` |
| `x をスカラーとする` / `let x be a scalar` / `declare x as a scalar` | **型の宣言**（`define_scalar_parameter`） |

語尾は `とする` のほか `とします` / `とおく` / `と置く` / `とみなす` も読みます。

**数は語で書けます。** `ゼロ` / `零` / `zero` は 0、`one` は 1 として読みます
（`x をゼロとする` → `x = 0`、`E1 の右辺をゼロとする` → `右辺 = 0`、
`substitute x = zero into E1` → `x` に 0 を代入）。
ただし**文全体が数のときだけ**です——式の中に立っている `one` は記号のままですし、
**名前を書く欄も書き換えません**（`define spin operator one` は `one` という名前の
演算子を宣言します）。
序数（`third`）と倍数副詞（`twice`）は「何階微分か」を数える語で、値にはなりません。

**式番号そのものは値にできません。** `E1 を 0 とする` は「方程式全体を 0 とみなす」
のか「右辺を 0 に置く」のかが書かれていないので断ります。**`E1 の右辺を 0 とする`**
（英語は `set the right-hand side of E1 to 0`）と書いてください。

### バックエンドによる評価タイミングの違い

| バックエンド | H = H_0 + H_1 登録後 | H_1 を後から変更したとき |
|---|---|---|
| **Maxima** | H_0, H_1 の現在値で即座に評価・確定 | H は変わらない（定義時に固定） |
| **Julia** | 構造 `H_0 + H_1` をそのまま保持 | H は変わらない（明示的な再評価が必要） |

**両バックエンド共通：** 後から H_1 を更新しても H は自動で変わりません。  
「再評価」操作で明示的に反映させてください。

### 値を置く（代入）

式の中の記号を値に置き換えるとき、次の綴りが通ります。

```
E1 の x を 2 に置換して          E1 の x を 2 と置く / とおいて
E1 で x = 2 として               E1 で x = 2 とする / とします
E1 の x = 2 として               E1 に対して x = 2 として
set x = 2 in E1                 let x = 2 in E1 / put x = 2 in E1
substitute x = 2 into E1        In E1, set x = 2
```

**`とする`／`として` は `=` の形でだけ使えます。** 助詞の形
（`E1 の x を 2 とする`）は受けません——`を` の後ろには**型の名詞**が来うるので
（`x をスカラーとする`・`\gamma を正の実数とする`）、宣言と見分けがつかないためです。
`を` で書きたいときは **`と置く` / `に置換して`** を使ってください。

**式番号が要ります。** `x = 2 として` のように対象を書かない文は、代入ではなく
**定義**（`x = 2` の登録）として読まれます。

### 再評価（re_evaluate_expr）

定義済みシンボルを現在の値に置き換えて式を展開します。バックエンドに関係なく同じ自然言語で動作します。
**QA 式・SymPy 式（代数インデックス操作後）の両方に対応しています。**

#### パターン A：自動検出（推奨）

```
H を再評価して
```

または

```
H を H_0, H_1 の値で展開して
```

`lhs_alias_map` に登録されているシンボルを自動検出して一括代入します。

**実行例（Maxima / Julia 共通の結果）:**

```
登録済み:
  H_0 = p^2/(2*m)       (E1)
  H_1 = -k*(x-a)^2      (E2)
  H = H_0 + H_1          (E3)

"H を展開して" → re_evaluate_expr(E3) → 自動検出
  Maxima: subst([H_0=p^2/(2*m), H_1=-k*(x-a)^2], H_0+H_1)
  Julia:  substitute(H_0+H_1, {H_0=>p^2/(2*m), H_1=>-k*(x-a)^2})

結果 (E4): p^2/(2*m) - k*(x-a)^2
```

#### パターン B：値を直接指定

```
E3 の n_k を 0.42 で更新して
```

```
E3 の rho を 0.42 に、kappa を 0.1 に更新して
```

#### パターン C：式番号で参照

```
E5 の H_0 を E2 で更新して
```

→ E5 の中の H_0 を E2 の現在の canonical 値で置き換えます。

### シンボルマッチングの規則

- **単語境界マッチ：** `H` は `H_0` や `H_BCS` の中の `H` にはマッチしません。
  ```
  式: "H_0 + H_1"  →  "H" は検出されない（H_0, H_1 のみ検出）
  式: "H + V"      →  "H" が検出される
  ```
- **長い名前を優先：** `H` と `H_0` が両方定義されている場合、`H_0` が先に処理されます。
- **代入数の上限なし：** 10個でも20個でも一括処理されます。

### チェーン展開（段階的）

定義が入れ子になっている場合、1回の再評価では1段階だけ展開されます。

```
A = 1          (E1)
B = A + 1      (E2)
C = B + 1      (E3)

"C を展開して"     → C の中の B を展開 → A + 2  (E4)
"E4 を展開して"    → A + 2 の中の A を展開 → 3    (E5)
```

元の式（E3, E4）は変更されず、結果は新しい式として追加されます。

## 方程式への操作

H-1 形式（`LHS = RHS`）で登録した方程式に対して、以下の操作が使えます。

### 右辺の評価（H-5）

```
EOM = -i * diff(Sx_1, t) = commutator(H, Sx_1)   ← 方程式を登録（E5）

E5 の右辺を計算して       ← commutator(H, Sx_1) を CAS で評価
E5 の右辺を展開して       ← RHS を expand
E5 の右辺を整理して       ← RHS を simplify
E5 の右辺を因数分解して   ← RHS を factor
E5 の右辺を有理式簡約して ← RHS を rational_simplify
```

**ポイント:** 物理方程式を先に書き下してから計算させる「論文執筆スタイル」のワークフローが実現できます。結果の表示は `LHS = 評価結果` の形式になります。

**Julia セッションでのスピン演算子の注意点:**

```
❌ -i \frac{dS_x}{dt} = [H, S_x]    ← S_x はサイト未指定 → Julia エラー
✅ -i \frac{dS_{x_1}}{dt} = [H, S_{x_1}]  ← サイト番号を明示する
```

QuantumAlgebra では `Sx` 単体は演算子コンストラクタ関数であり、`Sx_1` や `Sx(1)` のようにサイトを指定して初めて演算子になります。

---

### 右辺に値を設定する（H-5z）

式の右辺を特定の値に等しいと置き、新しい方程式として登録します。運動方程式を「= 0」形式に変換するときなどに使います。

```
ml^2 \ddot{q} + mgl \sin q   ← E5 として登録（等式なし）

E5 の右辺を 0 とする   → ml²q̈ + mgl sin q = 0（E6 として登録）
```

X には数値・式・E-ID 参照が使えます：

```
E5 の右辺を 0 とする        ← 0 に等しいとおく
E5 の右辺を 1 とする        ← 正規化
E5 の右辺を \omega^2 とする ← 別の式に等しいとおく
E5 の右辺を E3 とする       ← E3 の canonical を値として使う
```

全角数字（０、１）も受け付けます。

**ポイント:** 「En の右辺を X とする」「En の右辺を X とおく」「En の右辺を X と置く」などの言い回しがすべて使えます。CAS 評価はせず、新しい方程式を即座に登録します。

---

### 両辺への操作（H-8）

```
F = m * a   ← E1 として登録

E1 の両辺を m で割って    → F/m = a
E1 の両辺に 2 をかけて    → 2 F = 2ma
E1 の両辺を 2 倍して      → 同上
E1 の両辺に V を足して    → F + V = ma + V
E1 の両辺から V を引いて  → F - V = ma - V
E1 の両辺を整理して       → F = ma（simplify を適用）
```

**ポイント:** LHS も自動で変換されるので等式形式が保たれます。連立一次方程式を筆算の要領で解くときに便利です。

---

### 方程式を解く（H-9）

**一変数を解く：**

```
F = m * a   ← E1

E1 を m について解いて   → m = F/a
E1 を a について解いて   → a = F/m
```

**連立方程式を解く（変数を指定）：**

```
alpha_k = u_k * c_k + v_k * c_dag    ← E1（Bogoliubov 変換）
alpha_mk = -v_k * c_k + u_k * c_dag  ← E2

E1 と E2 の連立方程式を c_k と c_dag について解いて
→ c_k = u_k * alpha_k - v_k * alpha_mk   （E3）
→ c_dag = v_k * alpha_k + u_k * alpha_mk  （E4）
```

**連立方程式を解く（変数を後で指定）：**

```
E1 と E2 の連立方程式を解いて
→「どの変数について解きますか？」と確認が入る
→「c_k, c_dag」と入力して実行
```

**ポイント:** 解は一件ずつ個別の式（`c_k = ...` など LHS 付き）として登録されます。引き続き計算に使えます。

**応用例：スピン昇降演算子の逆変換**

```
S_plus  = Sx + i*Sy   ← E1
S_minus = Sx - i*Sy   ← E2

E1 と E2 の連立方程式を Sx と Sy について解いて
→ Sx = (S_plus + S_minus) / 2      （E3）
→ Sy = (S_plus - S_minus) / (2*i)  （E4）
```

### 行列の対角化（固有値・固有ベクトル → 直交 P・対角 D）

具体的な数表行列は **`[a, b; c, d]`**（`;` が行区切り、`,` が列区切り）で入力します。

**TeX の書法もそのまま受け付けます**（2026-09-10）——`\begin{pmatrix} 2 & 1 \\ 1 & 2 \end{pmatrix}` と `[2, 1; 1, 2]` は同じ行列になります。表示は `pmatrix` で返るので、**画面の行列をコピーして打ち直せます**。`bmatrix`・`matrix`・`Bmatrix`・`smallmatrix`・`array`、plain TeX の `\pmatrix{…}` も同じ。縦棒の `\begin{vmatrix}` は**行列式**（スカラー）です。
`;` の **有無** で意味が変わります。

- `;` **あり** → 行列（`[2, 1; 1, 2]` は $2\times2$ 行列）
- `;` **なし** → 交換子・リスト（`[A, B]` は交換子）

登録後、以下の行列操作を自然言語で連鎖できます（すべてルールベース、LLM 非経由）。
Maxima・Julia 両バックエンドで動作します。

| やりたいこと | 指示 | 結果 |
|---|---|---|
| 固有値 | `E1 の固有値を求めて` | 固有値のリスト |
| 固有ベクトル | `E1 の固有ベクトルを求めて` | 固有ベクトル |
| 対角化（変換行列 P） | `E1 を対角化して` | 正規化固有ベクトルを列に並べた**直交行列 $P$**（$P^{-1}=P^\top$） |
| 対角行列 D | `E1 の対角行列を求めて` | 固有値を並べた**対角行列 $D$** |
| 逆行列・転置・行列式・トレース・行列積 | `逆行列／転置／行列式／トレース／行列積を求めて` | 各基本操作 |

**トレース・行列式は記法でも書けます。** $\mathrm{tr}$・$\mathrm{Tr}$・$\det$ は、
`\text{tr}(M)`・`\mathrm{Tr}(M)`・`\operatorname{tr}(M)`・`\det(M)`・`\mathrm{det}(M)`
のどの綴りでも同じ量として読みます（ラッパの違いは組版の好みです）。具体行列なら値に
なり、記号行列なら $\mathrm{tr}(M+N)$ の形のまま残って、後から代入・簡約できます。

**ワークフロー全体（対称行列の相似変換）**

```
1. 行列を登録
   A = [2, 1; 1, 2]              → E1

2. 固有値・固有ベクトル
   E1 の固有値を求めて             → E2 = 1, 3
   E1 の固有ベクトルを求めて          → E3

3. 直交変換行列 P と対角行列 D
   E1 を対角化して                → E4 = P（直交）
   E1 の対角行列を求めて            → E5 = D = diag(3, 1)

4. 相似変換 P⁻¹AP = D を確認
   E4 の逆行列を求めて             → E6 = P⁻¹（= Pᵀ）
   E6 と E1 の行列積を求めて         → E7 = P⁻¹A
   E7 と E4 の行列積を求めて         → E8 = P⁻¹AP = diag(3, 1)
```

**ポイント:**
- `対角化` は固有ベクトルを正規化して**直交行列 $P$** を返すので、$P^{-1}=P^\top$ が成り立ちます。
- `対角化`（変換行列 $P$）と `対角行列を求めて`（対角行列 $D$）は別の操作です。
- 結果は **命名・代入** で記号に束縛して後続計算に再利用できます：
  `P = E4`（命名）または `E4 を P とする`（代入命令）。束縛後は `P` を式の中で使えます。
- 表示は `\begin{pmatrix}` で数表としてレンダリングされます。

> 特性多項式から固有値を求める別法（演算子セッションでスカラー固有値が欲しいとき）は、
> 次節の特性多項式ワークフローを参照してください。

詳しい実例は [scenario_matrix_diagonalization.md](scenarios/scenario_matrix_diagonalization_jp.md)、
`domains/linear_algebra/examples/` を参照。

### 行列の固有値を求める（特性多項式ワークフロー）

行列の固有値は、**特性多項式 `det(λI − A) = 0`** を解いて求めます。`A − E·I` を手で
組み立てる必要はなく、`特性多項式を … について求めて` の一手で計算できます。

**操作：特性多項式を求める**

```
（行列 H_mat を登録した状態で）

H_mat の特性多項式を E について求めて
→ det(E·I − H_mat) を計算   （E は固有値変数、I は単位行列で自動的にサイズが合う）
```

- Julia セッション: `det(E*I - H_mat)`（`I` は `LinearAlgebra` の単位作用素）
- Maxima セッション: `charpoly(H_mat, E)`

**ワークフロー全体（2×2 BCS ハミルトニアンの例）**

```
1. 行列を登録
   H_mat = [xi_k, Delta; Delta, -xi_k] を行列とする             ← E1

2. 特性多項式を求める
   E1 の特性多項式を E について求めて
   → E² − xi_k² − Delta²                                        ← E2

3. 右辺を 0 とする（H-5z）
   E2 の右辺を 0 とする
   → E² − xi_k² − Delta² = 0                                    ← E3

4. 固有値について解く（H-9）
   E3 を E について解いて
   → E = sqrt(xi_k² + Delta²)                                   ← E4
```

**ポイント:**
- 固有値 `E` はスカラーなので、求解後そのまま第二量子化の演算子計算に代入して使えます
  （QA→SymPy の一方通行制約に引っかかりません）。
- `特性多項式`・`固有値方程式`・`永年方程式` のいずれの言い方でも認識されます。

## ポアソン括弧（ハミルトン力学）

ハミルトン力学のポアソン括弧
$$\{f, g\} = \sum_i\left(\frac{\partial f}{\partial q_i}\frac{\partial g}{\partial p_i} - \frac{\partial f}{\partial p_i}\frac{\partial g}{\partial q_i}\right)$$
を計算できます。量子の交換子の**古典版**で、非可換代数ではなく**偏微分の和**として
構成されるため Maxima がそのまま扱います。

### 正準座標対を宣言する

ポアソン括弧は「どの座標とどの運動量が共役か」を必要とします。毎回書かず、一度宣言します
（セッションに保存され、save/load で永続します）。

```
p_r を r の共役運動量とする            ← 正準対 (r, p_r)
p_theta を theta の共役運動量とする       ← 正準対 (theta, p_theta)
```

「`r と p_r を正準対とする`」（座標, 運動量 の順）という言い方も使えます。

### ポアソン括弧を求める

```
r と p_r のポアソン括弧を求めて          → 1            （正準交換関係 {q,p}=1）
H と L_z のポアソン括弧を求めて          → 0            （保存則：L_z が保存）
H と r のポアソン括弧を求めて            → -p_r/m       （Hamilton 運動方程式 \dot r={r,H}）
```

**ポイント:**
- オペランドは **E-ID**・**H-1 で登録した名前**（`H`, `L_z`）・**素のシンボル**（`r`, `p_r`）の
  いずれも使えます（式として登録していなくてもよい）。
- 正準対を宣言する前に括弧を求めると、宣言を促すメッセージが返ります。
- $\{H, L_z\}=0$ は $L_z$ が保存量であること（$H$ の対称性）を、$\{q, H\}=\dot q$ は
  Hamilton の運動方程式を与えます。

実例は [scenario_poisson_bracket.md](scenarios/scenario_poisson_bracket_jp.md)、
`domains/classical_mechanics/examples/` を参照。

## 線型変換（基底変換）と正準性（L-1）

座標変換・基準振動・回転・Bogoliubov 変換・スピン昇降演算子など、**一般の線型基底変換**を一括で扱います。
順変換（新＝M·旧）を入力すると、逆変換の生成・正準（交換関係／計量）拘束の導出・拘束適用・変換の代入・
正準性検証までが一連の操作でつながります。統一原理は計量保存 $M^\dagger G M = G$（フェルミ→反交換子、
ボース→交換子、ベクトル→Gram 行列）。

> H-9 の「連立方程式を…解いて」でも逆変換は得られますが、以下の専用操作は基底の自動同定・新基底の局所化・
> 演算子のサロゲート処理・拘束との連携を自動で行います。

### 逆変換を作る

順変換式を E-id 登録し、「逆変換を作って」と言うだけ。係数がスカラー宣言済みなら**旧基底を自動推定**します。

```
u をスカラーとする / v をスカラーとする
alpha_k  = u c_k + v c_mk      ← E1
alpha_mk = - v c_k + u c_mk    ← E2

E1, E2 の逆変換を作って
→ c_k  = (u·alpha_k - v·alpha_mk)/(u²+v²)
→ c_mk = (v·alpha_k + u·alpha_mk)/(u²+v²)
```

- 基底が曖昧なときは「どの基底について逆変換しますか？」と確認が入ります。明示するには
  `E1, E2 を c_k, c_mk について逆変換して`。
- **演算子**の場合（`c(1)`, `c'(2)` など）は基底を明示し、完全な逆変換には共役（ダガー）式も含めて
  本数を未知演算子数に合わせます（フル Nambu）。`c(1)` 等は内部でサロゲート化して解き、結果は演算子記法に戻します。

### 行列 M を直接与える

N 本の式の代わりに行列と基底を直接渡せます。

```
M = [[u,-v],[v,u]]、旧基底 c_k, c_mk、新基底 alpha_k, alpha_mk の逆変換を求めて
→ c_k = (u·alpha_k + v·alpha_mk)/(u²+v²) 等
```

`[[...],[...]]` はバックエンド非依存の中立記法です（Maxima/Julia で同一）。

### 正準拘束を求める（演算子）

変換後も正準（反）交換関係を保つ条件を導出します。統計から自動で反交換子/交換子を選ぶので、
$\eta$ の符号は自動です。

```
c をフェルミ演算子として定義 / u, v をスカラーとする
gamma = u c(1) - v c'(1)   ← E1

E1 の正準拘束を求めて
→ u² + v² = 1                （フェルミ＝ユニタリ）
```

ボース演算子なら `u² − v² = 1`（para-unitary）。多モードでは全ペア $\{γ_i,γ_j^\dagger\}=δ_{ij}$ と
異常項 $\{γ_i,γ_j\}=0$ を計算し、自明・重複を除いて登録します。

### 正準か？（para-unitary 検証）

```
E1 は正準か？
→ 非自明な拘束が残れば「次の条件を満たせば正準です」＋条件式
→ 全て自明なら「この変換は正準（para-unitary）です。追加の拘束は不要です」
```

### 非正規直交基底の計量保存条件

内積を式で宣言して Gram 行列を組み、$M G M^\top = G$ の拘束を導きます。

```
⟨e_1, e_2⟩ = s            ← 内積を宣言（未宣言は対角1・非対角0）
f1 = a e_1 / f2 = e_2     ← E1, E2

E1, E2 の計量保存条件を求めて
→ a² − 1 = 0,  (a − 1) s = 0
```

直交計量＋回転なら拘束なし（保存）。Maxima・Julia 両対応。

### 拘束のもとで簡約する

導出した拘束を式に適用して畳みます（逆変換の分母 $u²+v²$ が 1 になる等）。

```
正準拘束のもとで E3 を簡約して       ← 導出済み拘束を自動使用
E3 を E2 の拘束で簡約して            ← 拘束式を明示
→ c(1) = u·alpha_k + v·alpha_mk†     （分母が畳まれる）
```

### 変換を式に代入する

生成した変換式を target 式に流し込みます。シンボルの種別で**可換（substitute）／演算子（operator_substitute）**
に自動で振り分けます。

```
E2, E3 を E1 に代入して
  （座標）L = q_1² + q_2² に q_1=Q_1+Q_2, q_2=Q_1−Q_2 → 2Q_1² + 2Q_2²
  （演算子）H = c†c に c_1 = u g + v g† → v² + (u²−v²) g†g
```

**動詞も語順も問いません。** 単一の式を流し込むときは次のどれでも同じです。

```
E1 を E2 に代入して      / E2 に E1 を代入して      / E2 に E1 を適用して
substitute E1 into E2   / substitute E1 in E2     / apply E1 to E2
plug E1 into E2         / In E2, substitute E1
```

## 伊藤の補題（financial_mathematics ドメイン）

幾何ブラウン運動 $dS=\mu S\,dt+\sigma S\,dW$ に従う資産 $S$ の関数 $f(S,t)$ について、伊藤の補題
$$df=\left(\frac{\partial f}{\partial t}+\mu S\frac{\partial f}{\partial S}+\frac12\sigma^2S^2\frac{\partial^2f}{\partial S^2}\right)dt+\sigma S\frac{\partial f}{\partial S}\,dW$$
を計算します（既存の微分を3回呼び出して公式に代入するだけで、新規の確率解析ロジックはありません）。

```
apply Ito's lemma to log(S)
→ E1: df = (μ − σ²/2)dt + σ dW    （GBM の解析解を導く最も有名な適用例）

apply Ito's lemma to S^2
→ E2: df = (2μS² + σ²S²)dt + 2σS² dW
```

SDE 記法（$dS=\mu S\,dt+\sigma S\,dW$）や Black–Scholes 方程式は、新規機能不要——通常の式登録
（H-1）でそのまま書けます。

**対応範囲:** Black–Scholes 方程式を実際に解いてオプション価格の閉形式公式（$N(d_1), N(d_2)$ を含む）

## 多スピン種：サイトごとに異なるスピンの大きさ（F-13）

電子スピン $S=1/2$ と核スピン $I=1$ のように、**サイトごとにスピンの大きさが違う系**の
無限温度期待値（トレース）を評価します。スピン代数は CAS を経由せず Python 側で厳密に
計算しますが、**結果は CAS で使える式**として登録されるので、そのまま代入・簡約に回せます。

```
H_hf = A S^x_1 S^x_2 + A S^y_1 S^y_2 + A S^z_1 S^z_2     ← 超微細相互作用 A I·S
                                                            （サイト1=電子、サイト2=核）
サイト1のスピンを1/2、サイト2のスピンを1とする
→ サイト別スピンを宣言: S_1 = 1/2, S_2 = 1

E1 の期待値を求めて       → ⟨H_hf⟩ = 0        （各因子がトレースレス）
E1 の2次モーメントを求めて → ⟨H_hf²⟩ = A²/2    ← 物理はここに出る
```

**宣言しない場合**は従来どおり全サイト共通の $x=S(S+1)$ で評価されます（既存セッションの
挙動は変わりません）。宣言してスピンを書かなかったサイトは**記号のまま**残ります:

```
サイト1のスピンを1/2とする
E1 の2次モーメントを求めて → ⟨H_hf²⟩ = A² x2/4     ← x2 = S_2(S_2+1) は記号のまま
E2 の x2 に 2 を代入して    → A²/2                  ← 一般操作でそのまま続けられる
```

**記号名について:** サイト $i$ のスピン変数は `x1`, `x2`, …（$x_i = S_i(S_i+1)$）です。
`x_1` と添字付きにしていないのは、添字付きの記号が CAS 側で関数呼び出しに落ちてしまい、
**あとで `x_1` に代入しようとしても何も起こらないまま成功と表示される**ためです。

宣言はセッションに保存され、保存・読込をまたいで残ります。

**使いどころ:** 超微細構造（電子＋核）、異核 NMR の第二モーメント（Van Vleck）、
混合スピン鎖。エネルギー準位そのものは [F-9 の角運動量の合成](#角運動量の合成f-9atomic_physicsmagnetic_resonancenuclear_physicsquantum_mechanics)
または行列対角化で求めます。

## 角運動量の合成（F-9：atomic_physics・magnetic_resonance・nuclear_physics・quantum_mechanics）

クレブシュ・ゴルダン係数、Wigner の 3j/6j/9j 記号、角運動量の合成、ランデの g 因子、
Wigner-Eckart の定理。**バックエンドに依存しません**（Python 側で厳密に計算するので、
Maxima セッションでも Julia セッションでも同じように使えます）。値は $\sqrt{}$ を保った
**厳密形**で、小数にはなりません。

半整数は `3/2` と書きます（`1.5` は受け付けません）。

```
j1=1/2, m1=1/2, j2=1/2, m2=-1/2, J=1, M=0 のCG係数を計算して
→ ⟨1/2 1/2 1/2 -1/2 | 1 0⟩ = 1/√2        canonical: sqrt(2)/2

3j記号 (1 2 3; 0 0 0) を計算して          ← 行は ';' 区切り。丸括弧=3j
6j記号 {1 2 3; 2 1 2} を求めて             ← 波括弧=6j
9j記号 {1/2 1/2 1; 1/2 1/2 1; 1 1 0} を計算して

j1=1/2, j2=1/2 の J=0, M=0 の状態を非結合基底で展開して
→ |0,0⟩ = (1/√2) χ(1/2) ψ(-1/2) − (1/√2) χ(-1/2) ψ(1/2)   （一重項。基底記号は下記）

^2P_{3/2} のランデのg因子を求めて          → g_J = 4/3
L=2, S=1/2, J=5/2 のg因子を求めて          → g_J = 6/5

j=1/2, m=1/2, k=1, q=0, j'=3/2, m'=1/2 についてWigner-Eckartの定理を書き下して
→ ⟨3/2 1/2|T^(1)_0|1/2 1/2⟩ = (1/√6) ⟨3/2‖T^(1)‖1/2⟩
```

### 合成は「式を2つ」返す — 後段で使うのは恒等式のほう

```
I=3/2 と S=1/2 を合成して
→ E1: |3/2⟩ ⊗ |1/2⟩ : F = 1, 2                    （許される全角運動量）
  E2: I·S = ½[F(F+1) − 15/4 − 3/4]                （厳密な恒等式。F は記号のまま）
```

E2 は **F を記号のまま残してある**ので、そこから先は**一般操作の連鎖**で進みます。
超微細構造の準位（ランデの間隔則）はこうして出します:

```
E2 の両辺に A をかけて     → A I·S = (2AF² + 2AF − 9A)/4
E4 の F に 1 を代入して     → −5A/4
E4 の F に 2 を代入して     →  3A/4       差 = 2A = A·F   ← 間隔則
```

つまりハミルトニアン（$H_{\rm hf} = A\,\mathbf I\cdot\mathbf S$）と結合定数 $A$ は
**利用者が与えます**。F-9 が特定のモデルを埋め込むことはありません。微細構造
（$\zeta\,\mathbf L\cdot\mathbf S$）もまったく同じ手順です。

**選択則**は覚える規則ではなく、Wigner-Eckart 係数が 0 になることとして出てきます
（$\Delta J$ が $k$ を超える、$\Delta m \neq q$、$0 \to 0$ など）。

### 基底記号は「指定すれば自分の記法、しなければシステムが選ぶ」

展開の積状態は**名前付きの記号**として書かれます。こうしないと計算に使えないためです
（ケットは CAS の値ではないので、`|½,½⟩` のままでは簡約も代入もできません）。

**指定しない場合**——システムが未使用の記号を選び、どれを使ったかを伝えます:

```
j1=1/2, j2=1/2 の J=0, M=0 の状態を非結合基底で展開して
→ |0,0⟩ = (1/√2) χ(1/2) ψ(-1/2) − (1/√2) χ(-1/2) ψ(1/2)
   canonical: sqrt(2)/2*chi(1/2)*psi(-1/2) - sqrt(2)/2*chi(-1/2)*psi(1/2)

  E1：基底記号を指定しなかったので chi, psi を使いました（このセッションで未使用の
  記号です）。自分の記法にしたい場合は「… を u と v の非結合基底で展開して」の
  ように指定してください。
```

**指定する場合**——論文の記法に合わせられます:

```
j1=1/2, j2=1/2, J=1, M=0 を u と v の非結合基底で展開して
→ |1,0⟩ = (1/√2) u(1/2) v(-1/2) + (1/√2) u(-1/2) v(1/2)
```

どちらの場合も**表示されているものと計算できるものが一致します**。

**指定した名前は検査されます:**

| 状況 | 結果 |
|---|---|
| 既に使われている記号（例：先に `phi = x^2` と定義済み） | 拒否。H-1 の定義が CAS 側にも束縛されるため、そのままだと展開が `(x^2)(1/2)` のような無意味な式に化けたまま**成功として返ってしまう** |
| 2つとも同じ名前 | 拒否。第1・第2の角運動量は別の空間の状態なので区別が消える |
| 添字付きの名前（`chi_1` 等） | 拒否。`chi_1(1/2)` は関数呼び出しではなく添字として解釈されるため。単純な名前（`chi`, `psi`, `u`）を使ってください |

**逆向きは防げません:** 展開を作った**後で**同じ名前を定義すると、H-1 の仕様どおり
定義が全体に伝播し、その展開の意味も変わります（F-9 固有ではなく H-1 のグローバル
束縛の性質です）。基底名には後で使う予定のない記号を選んでください。

**制約:**
- 「許される F の一覧」（`[1, 2]`）はリストとして登録されますが、リストを反復する操作は
  用意していないため実質は記録用です。準位は上記のように F ごとに代入します。
- **直交性は CAS が知りません**（χ(1/2)·χ(-1/2) は勝手には 0 になりません）。内積・
  行列要素が必要なら、係数を CG 係数として個別に求めてください。
- 量子数が三角関係を破る場合は 0、そもそも不可能な場合（|m| > j 等）は
  **エラーとして止まります**（黙って 0 を返しません）。

## 摂動展開（extract_order / truncate_series）

摂動パラメータ ε の多項式として書かれた式から、各次の項を取り出したり打ち切ったりします。スカラー式・量子演算子式（QuExpr）の両方に対応します。

### 使い方

```
c をフェルミオン演算子として定義する
xi, ep をスカラーパラメータとして定義する

H = xi c†(1)c(1) + ep (c†(1)c(2) + c†(2)c(1))  ← E1

E1 から ep の 0 次項を取り出して   → ξ c†(1)c(1)    （非摂動 H₀）
E1 から ep の 1 次項を取り出して   → c†(1)c(2) + c†(2)c(1)  （摂動 V）
E1 を ep の 1 次で打ち切って       → H₀ + ε V
```

### value テンプレートの書き方

| 操作 | 必須フィールド | 説明 |
|---|---|---|
| `extract_order` | `expr`, `var`, `order` | λ^n の係数を返す（演算子またはスカラー） |
| `truncate_series` | `expr`, `var`, `order` | order 次以下の項のみ残す |

## 演算子テイラー展開（operator_taylor_expand）（Julia セッション専用）

スカラー関数 f(x) を量子演算子 H に適用した式 f(H) ≈ Σ aₖ Hᵏ を計算します。

### 使い方

```
a をフェルミオン演算子として定義する
xi, beta をスカラーパラメータとして定義する

H = xi a†(1)a(1)  ← E1

E1 に exp(-beta*x) を適用（order=4）
→ 1 + (-beta·xi + beta²xi²/2 - ...) a†(1)a(1)
```

各次の計算は QuantumAlgebra の演算子積（`Hᵏ = H·H·…·H`）で行われ、反交換関係・射影演算子の性質（`n²=n` 等）が自動的に適用されます。

| 入力例 | 結果の特徴 |
|---|---|
| `exp(-beta*x)` + 数演算子 H | `1 + (e^{-βξ}-1)·n` へ収束（射影性） |
| `exp(-beta*x)` + ホッピング H | 対角・非対角・4体項が各次に出現 |
| `1/(1-x)` | resolvent 展開 `1 + H + H² + H³ + ...` |
| `cos(x)` | 偶数冪のみ出現 |

## 未定義シンボルの検出と定義の促し

### 概要

数式を入力すると、`SymbolContext`（シンボル登録表）に登録されていないシンボルが含まれていた場合、⚠ 警告バナーが表示されます。

```
⚠ 未定義シンボル: xi, Delta
  定義例: 「xi をスカラーとする」「xi をベクトルとする」「xi を行列とする」など
```

Julia（第二量子化）セッションでは、多文字の物理パラメータ（`xi`, `Delta` など）が未定義のまま計算操作を実行しようとすると、**CAS 実行前にブロック**されてエラーが表示されます。

### 自由変数とは

`x`, `a`, `t`, `i`, `j` のような **1 文字のシンボル**は「自由変数」として扱われ、宣言なしでも計算できます。CAS（Maxima も Julia も）はこれらをそのまま文字として計算に使えるためです。

一方、`xi`（緩和長）、`Delta`（ギャップ関数）、`omega_n`（松原周波数）のような**多文字の物理パラメータ**は、Julia / QuantumAlgebra.jl において明示的な宣言が必要です。宣言しないと「演算子として呼び出そうとしている」と誤認識されてエラーになる場合があります。

| シンボルの種類 | 例 | 宣言が必要か |
|---|---|---|
| 1 文字の自由変数 | `x`, `a`, `t`, `i`, `j` | 不要（どのバックエンドでも） |
| 多文字の物理パラメータ | `xi`, `Delta`, `omega_n` | **必要**（Julia セッション） |
| 量子演算子 | `a(k)`, `psi(k)` | **必要**（`ボソン演算子として定義` など） |

### 値を与えた名前は、もう変数ではありません

`y = x^3` のように名前へ**値を与える**と、その名前は CAS 側でもその値に結びつき
ます。だから `y` は変数としては使えません——微分や定積分の変数の欄に書くと、
**満たされていない条件**を述べて断ります。

```
z^2 + y
y = x^3
E1 を y で偏微分して
  → `y` には E2 で値 `x^3` が与えられています。値を持つ名前は変数ではないので、
     「微分する」の変数にはできません。
     ① `x^3` が書かれている変数で操作する  ② 値を持たない別の名前を変数に使う
```

案内される2つの道はどちらも実際に通ります。

| 書き方 | 結果 |
|---|---|
| `E1 を x で偏微分して`（値が書かれている変数） | `3*x^2` |
| `E1 を u で偏微分して`（値を持たない名前） | `0` |

**あとから「`y` をスカラーとする」と宣言しても値は消えません**（実測）。値を与える
前の状態へ戻す道は用意していないので、変数にしたい名前には値を与えないでください。

一方、**その名前が指すものについて解く**のは正しい書き方で、そのまま通ります——
`Az_z = \partial A_z/\partial z` と名前をつけてからゲージ条件を `Az_z` について
解くと、`\partial A_z/\partial z = -\partial A_x/\partial x-\partial A_y/\partial y`
が返ります（クーロンゲージのシナリオ）。代入（`E1 の y に 3 を代入して`）も
同じく通ります。

### 定義の方法

未定義の ⚠ バナーが出たら、以下のような自然言語で定義できます：

```
xi をスカラーパラメータとする
Delta をスカラー変数とする
F をベクトルとする
H を行列とする
T をテンソルとする
omega_0 を実数パラメータとして定義して
```

定義後は `SymbolContext` に登録され、同じシンボルを使った計算が実行できるようになります。

#### 対応している入力パターン

シンボル宣言はルールベースで処理されるため、以下のパターンで書くと LLM を経由せず即座に登録されます。

**日本語（構造: `<記号> を <ラベル> とする/と定義する`）**

| 入力例 | 型 |
|---|---|
| `m を質量とする` | スカラー |
| `m を実数スカラーとして定義する` | スカラー |
| `m と a を実数スカラーと定義する` | スカラー（複数同時） |
| `\gamma と B を実数スカラーとして定義する` | スカラー（TeX 記法） |
| `F をベクトルとする` | ベクトル |
| `H を行列と定義する` | 行列 |
| `T をテンソルとする` | テンソル |
| `xi_k を実数スカラーとする` | スカラー（確認ダイアログあり） |

**後置定義（`<記号> は <ラベル>`）** も対応しています：

| 入力例 | 型 |
|---|---|
| `m は質量` | スカラー |
| `m は質量である` | スカラー |
| `F はベクトルである` | ベクトル |
| `H は行列` | 行列 |
| `xi とはスカラーパラメータ` | スカラー |
| `m と g は実数スカラー` | スカラー（複数同時） |

**誤検出ガード：** シンボルトークンが `は` の前になければマッチしません（「結果はベクトル」「これは行列です」はスルー）。ラベルが数字や 1 文字の識別子のみの場合（「x は 0」「x は a」）もスルーして代入操作等として処理されます。

**英語（構造: `<sym> is (a) <label>` / `define <sym> as <label>`）**

| 入力例 | 型 |
|---|---|
| `m is a scalar` | スカラー |
| `define F as a vector` | ベクトル |
| `H is a matrix` | 行列 |

**ラベルの自由度：** 「スカラー」「実数パラメータ」「質量」「BCS 秩序パラメータ」「１電子エネルギー」のように、物理的な名称を書いてもスカラーとして登録されます（ベクトル・行列・テンソルキーワードがない場合は自動的にスカラー扱い）。

**ギリシャ文字の入力について：** Unicode のギリシャ文字（`ω`、`α`、`Δ` など）をそのまま入力すると、自動的に TeX 表記（`\omega`、`\alpha`、`\Delta`）に変換されてから処理されます。添字は TeX 記法で入力してください（`\omega_0` など）。Unicode 添字（`₀` など）は非対応です。

**添字付きシンボルの宣言（確認ダイアログ）：** `xi_k をスカラーとする` のように 1 文字の添字付きでシンボルを宣言すると、確認ダイアログが表示されます：

- **「k は成分インデックス（xi の k 成分）」** → `xi` として登録（`xi_k` は k に依存した xi の値）
- **「k は名前の一部（xi_k という固有の量）」** → `xi_k` として登録（xi_k という固有名の量）

数字添字（`omega_0`）や 2 文字以上の添字（`H_BCS`）は自動判定されダイアログは出ません。複数添字（`a_k_s`）は自動的にインデックスとして strip されます。

### Maxima セッションでは

Maxima はすべてのシンボルを自由変数として扱うため、未定義シンボルがあっても計算はブロックされません（⚠ 警告は表示されます）。

## よくある操作のながれ

### 式を登録して変形する

```
1. 入力欄に "(x^2-1)/(x-1)" と入力
2. 「送信」→ タイムラインに E1 として表示
3. 入力欄に "E1 を有理式として簡約" と入力
4. 「送信」→ 確認ダイアログで「実行」
5. タイムラインに E2 = x+1 が表示される
6. E2 をクリックして選択 → 「微分…」ボタン → 変数 x を入力
7. E3 = 1 が表示される
```

### 手書き式を登録して操作する

```
1. 「✍️ 手書き入力」→ ∫sin(x)dx を手書き
2. 認識結果を確認して「送信」→ 入力欄に数式トークンが挿入される
3. トークンの後に "を計算して" と入力
4. 「送信」→ E1 が登録されて積分が実行される
```

### 仮定を追加してから積分する

```
1. "x > 0 を仮定する" → 「送信」→ 青い仮定タイルが追加
2. "1/x を x で積分" → 「送信」→ log(x) が返る
   （仮定がないと正負の条件分岐が発生し、結果が変わる場合がある）
```

### 積分の変数変換（ヤコビアン自動挿入）

多変数積分の変数変換では、**ヤコビアン行列式が自動で挿入**されます。`A − E·I` のように
手で組み立てる必要はありません（Maxima セッション）。

被積分関数・旧変数・新変数・変換式（旧変数を新変数で表したもの）を与えると、
新しい被積分関数 `f(変換) × |∂(旧)/∂(新)|` が返ります。これを新変数で積分します。

> **重要：2 段構成です（変数変換 → 簡約）。**
> `change_integration_variables` が返すのは**未簡約の生 Jacobian 積**
> （例：極座標で `(r sin²θ+r cos²θ)(r²sin²θ+r²cos²θ)`）です。教科書形 `r³` /
> `r²sinθ` に畳むには、続けて **`簡約して`（`simplify`）** を実行します。
> $\sin^2+\cos^2=1$ の適用は **`簡約して` 一語で Maxima・Julia 共通**（どちらの CAS でも同じ言い方で OK）。
> `三角簡約して`（`trig_simplify`）も同じ結果になります。
>
> **唯一の差は結果の畳み込みの強さ（CAS 能力差）:** Maxima は極座標 `r³`・球座標 `r²sinθ` とも完全に clean。
> Julia（Symbolics.jl）は **2 次元・極座標 `r³` は clean** ですが、**3 次元・球座標は $\sin^2\phi+\cos^2\phi$ が
> 残り**未簡約（数学的には正しい）。完全 clean な体積要素 `r²sinθ` は Maxima のみ。

**極座標への変換 `∫(x²+y²) dx dy`:**
```
（x²+y² を E1 として登録した状態で）

① E1 を x,y から r,theta へ x=r*cos(theta), y=r*sin(theta) で変数変換して
   → (r sin²θ + r cos²θ)(r² sin²θ + r² cos²θ)   ← 生 Jacobian 積（未簡約）
② 直前の結果を 簡約して
   → r³        （= (x²+y²)→r² に ヤコビアン r を掛けて簡約したもの）
```

**球座標の体積要素 `∫ dV`:**
```
① 1 を x,y,z から r,theta,phi へ
   x=r*sin(theta)*cos(phi), y=r*sin(theta)*sin(phi), z=r*cos(theta) で変数変換して
   → 生 Jacobian 積（未簡約の多項式）
② 直前の結果を 簡約して
   → r² sin(theta)     （球座標の体積要素。Julia は未簡約形で止まる＝CAS 能力差）
```

**ポイント:**
- 変換式は旧変数と同じ順序で、カンマ区切りで与えます（`atan2(v,u)` のような関数引数のカンマは保護されます）。
- `多変数変数変換`・`ヤコビアン`・`極座標に変換`・`球座標に変換` のいずれの言い方でも認識されます。
- **教科書形にするには続けて `簡約して`（simplify）を実行**（両バックエンド共通。`三角簡約して` も可）。
  Julia は 3 次元・球座標を完全には畳めない（CAS 能力差。上記「重要」を参照）。
- 結果はあくまで「新しい被積分関数」です。続けて新変数で `定積分` すると体積分などが完成します。
- Maxima・Julia のどちらのバックエンドでも利用できます（Julia では Symbolics.jl の `jacobian`/`det` を使用）。

### もっと詳しい実例（シナリオ集）

分野別に**期待値つきで一通り追える実例（ワークシート）**を [scenarios.md](scenarios.md) に集めています。
連成振動・二重振り子・中心力の保存量・行列の対角化・イジング分配関数・ヤコビアン体積要素・格子図 →
TeX など、🟢 実現済みのシナリオを分野・バックエンド付きで一覧にしています。「実際の研究の流れを
最初から最後まで見たい」ときの入口です。

## 複数ステップの解法プラン（C-Ext-5）

「固有値を求めて微分方程式を解いて…」のように、複数の operation を組み合わせて
初めて答えに辿り着く問題があります。C-Ext-5 はこの**複数ステップの解法をプラン
として提案・実行する**機能で、入口が3つあります。いずれも実行前に必ず確認画面が
挟まり、自動実行はされません。

### 入口1：固定ワークフロー（即座に候補が確定している場合）

「固有状態を求めて」のような、**よく使う組み合わせがあらかじめ決まっている**
複合的な依頼は、LLM を介さずルールベースで即座にプラン化されます。

```
find the eigenstates of E1
```
→ 特性多項式 → 固有値 → 固有ベクトル、の3ステップが1つのプランとして提案されます。

```
Heisenberg equations for all components of S
```
→ 登録済みの演算子の各成分についてハイゼンベルク方程式を一括で導出します
（Julia セッション専用）。

固定ワークフローのトリガー語句は意図的に**狭く**設定されています——
「固有値を求めて」のような単発の依頼は、これまで通り単一 operation
（`eigenvalues`）のまま実行され、プラン化されません。

### 入口2：解法候補の提案（どう解くか自体を相談したいとき）

解き方が複数考えられる問題では、Adviser（LLM）に候補を出させることができます。

```
解法の候補
solution candidates
```

登録済みの直近の式を対象に、Adviser が複数のアプローチ（各ステップの operation・
理由）を提案し、確認カードに並びます。どれを選ぶかはあなたが決めます。

**Supervisor 自動選択:** 候補を全部見るのではなく「一番良さそうなもの」を
Supervisor に選ばせたい場合は、明示的に別の言い方を使います。

```
自動で解法を選んで
auto-select the best
```

これは「解法の候補」とは**別のトリガー**です——「候補を見せて」と言ったときは
文字通り全候補が表示され、Supervisor が勝手に1つに絞ることはありません。自動選択
を頼んだ場合も、Supervisor が選んだ1件は**実行前に確認カードとして表示され**、
そのままボタンで確認する必要があります（無言で実行はされません）。候補が1件しか
ない場合はLLM呼び出しなしで即座にその1件が確認カードになります。

### 入口3：自由計画（決まった型にはまらない依頼）

固定ワークフローにも該当せず、単なる候補相談でもなく、「この式をどうにかして
扱いたい」という自由な依頼は、LLM に手順そのものを組み立てさせることができます。

```
計画を立てて
plan this
```

Adviser が対象の式・履歴・仮定を踏まえてステップ列を提案し、解法候補と同じ確認
モーダルで表示されます。

### 実行と失敗時の挙動

確認カードで実行を選ぶと、プランの各ステップが順に実行されます。あるステップが
失敗すると、**そこで安全に停止**し、それまでに成功したステップの結果は失われません
（「n/m ステップ成功」の形でタイムラインに残ります）。未実行分は「skipped」として
記録されるだけで、勝手にリカバリを試みたりはしません。

停止したプランカードには2つのボタンが出ます：

- **🔁 再試行** — 原因（未宣言のシンボルなど）をあなたが直したあと、**同じプラン**を
  もう一度最初から実行します。
- **🔄 別の方法で再計画** — Adviser に「前回はここで失敗した」という文脈を渡して、
  **別のアプローチ**を新たに提案させます。研究者側の作業（宣言など）では直せない、
  アプローチ自体が悪かった場合に使います。

どちらもプラン全体を再実行する点は同じで、確認を経ずに再実行されることはありません。

### 数値計算層との接続

固定ワークフローや解法候補が生成した式（`E-id`）は、他の式と同じように選択して
「🔢 数値計算へ」フォークできます。ただし `eigenvalues` のような一部の operation は
**値のリスト形**（`[[固有値のリスト],[重複度のリスト]]`）で結果を返すため、その
まま数値層へフォークすることはできません。個々の固有値を数値化したい場合は、
特性多項式（プランの中間ステップとして残っています）を改めて `solve` して
**個別の式として登録し直して**からフォークします。実例は
[scenario_avoided_crossing.md](scenarios/scenario_avoided_crossing.md) を参照。

## 数値計算層（N-1）

解析的に解けない式に**数値で当たりをつける**ための、理論層と並ぶ別レイヤーです。
理論式を「数値計算タスク」へフォークすると Python コード（numpy/matplotlib/scipy）が
生成され、ネットワーク遮断・書込制限付きの sandbox で実行されて、図・表・値が
**来歴付き**（元の式・仮定・パラメータ設定ごと）でノートのタイムラインへ戻ります。

**入口は2つ**（式を選択すると両方のボタンが出ます）:

- **🔢 数値計算へ（決定的経路）** — 掃引変数と固定値をフォームで指定。対応する
  計算はコードが**決定的に**生成され、レビュー不要でそのまま実行できます。
- **💬 対話で仕様を確定（対話経路）** — 「収束するまで反復して」「2次元で見たい」の
  ように自然言語で希望を伝えると、LLM が計算仕様（何を・どう動かして・何を出すか）を
  提案します。気に入らなければ言葉で直しを指示して洗練。仕様を承認すると、決定的
  経路で賄える仕様ならそのまま実行でき、それ以外は**コーディング LLM がコードを
  書き、あなたがレビュー・承認するまで実行されません**（編集も可能）。ホワイトリスト
  内の式では「差分検証」ボタンで決定的テンプレートと数値を突き合わせられます。

**決定的に対応している計算**（それ以外は LLM 経路の担当）:

| 計算 | 指定するもの | 出力 |
|---|---|---|
| 掃引・プロット | 掃引変数1つ（範囲・点数）＋固定値 | 図・CSV・最小/最大 |
| 複数レイヤーの作図 | 1〜2本の軸（範囲・点数）＋登録式・固定値・条件・座標 | 曲線／等高線／不等式領域／点の重ね描き、図・CSV・診断JSON |
| 1点評価 | 固定値のみ（掃引なし） | 値（複素数も可）|
| 1次元最小化 | 変数1つ（範囲）＋固定値 | 最小点・最小値（境界解は警告付き）|
| 収束ループ | 本体式列・更新写像・初期値・tol/max_iter | 収束値・反復トレース |
| 行列の数値評価 | 固定値のみ（`matrix(...)` 形式の式） | 行列（形・実/複素の型付き）|
| 固有値問題 | `matrix(...)` の式＋固定値（掃引変数は0または1つ） | 固定点=固有値（昇順）＋固有ベクトル／掃引=固有値分枝の図・CSV（避交差など）|

**API**（自動化・スクリプト向け。UI と同じ機能。下記すべての前に `/api/notebook` を付けます）:

```text
POST /numeric/fork               … タスク作成（flat 指定 or "spec" で faceted 仕様）
POST /numeric/generate/N001      … 決定的コード生成（レビュー可能な雛形）
POST /numeric/generate_llm/N001  … LLM コード生成（レビュー承認まで実行不可）
POST /numeric/approve/{artifact} … レビュー承認（"edited_source" で編集を反映）
POST /numeric/diffcheck/N001     … LLM コードとテンプレートの数値突き合わせ
POST /numeric/run/N001           … sandbox 実行 → 成果物＋タイムライン還流
POST /numeric/propose_spec       … 対話経路の仕様提案（goal・refinement）
POST /numeric/reflux/{artifact}  … 結果値を理論層の式として登録（下記）
GET  /numeric/file/{artifact}    … 図・CSV・診断JSONをダウンロード
GET  /numeric/tasks              … タスク・実行履歴の一覧（stale 報告つき）
GET  /numeric/params/{expr_id}   … 式の自由シンボル一覧（固定値入力欄の自動列挙用）
```

**事前準備（1回だけ）:** 専用の実行環境を作ります（アプリ本体とは分離）。

```bash
python3 -m venv .venv-numeric
source .venv-numeric/bin/activate
pip install -r notebook/numeric/requirements.txt
```

**計算の連鎖（typed graph）:** 実行結果の値（最小点・評価値・収束値など）は
**型付きの成果物**として記録され、次のタスクの固定値に**参照で**束縛できます —
仕様の入力に `{"value_from": "<artifact_id>"}` と書くだけです（例: 最小化で得た
`x_star` を別の式の評価に代入）。型が合わない接続（リストをスカラーとして使う、
複素数値を実数枠に入れる等）は**実行前に**エラーになります。依存関係は来歴として
残り、上流の式や仮定が後で変わるとタスク一覧に **stale（陳腐化）** として
報告されます（自動再計算はしません — 再実行するかはあなたの判断です）。

**結果を理論層に戻す（式差し戻し）:** 数値結果のスカラーは
`POST /numeric/reflux/{artifact_id}` （body `{"name": "a_star"}`）で理論層の式
`a_star = 2.274` として登録できます。以後 `a_star` は通常の記号として代入・参照に
使え、どの数値タスクのどの実行から来た値かはタイムラインの登録エントリに残ります。

**収束ループ（自己無撞着計算）:** ギャップ方程式や平均場反復のように**複数の式に
またがる大きなループ**は、仕様で本体（式の列）・更新写像（どの出力を次の反復の
どの変数に戻すか）・停止条件（tol / max_iter）を指定すると、**ループ全体が1本の
スクリプトに融合されて sandbox 1回で実行**されます（反復ごとにプロセスは起動
しません）。収束値に加えて反復トレース（CSV）が成果物として残り、**収束しなかった
場合は「成功」ではなく失敗ステップ**として記録されます（反復数・残差つき）。

**計算の全体像を見る（🕸 数値グラフ）:** ヘッダの「🕸 数値グラフ」ボタンで、
式→タスク→値の流れが DAG として表示されます。値の受け渡し（紫）・式差し戻し（破線）が
エッジとして見え、上流の式や仮定が変わって陳腐化したタスクは橙色の枠で警告されます。
理論の分岐が複数あってそれぞれで同種の計算（同じ種別・同じ対象量）を実行している場合は、
同じモーダルの下部に**分岐比較**の表（分岐×計算、結果サマリと図のサムネイル）が出ます。
比較は読み取り専用です — 分岐の統合や別分岐への再実行は行いません。

**パラメータを変えて繰り返す:** 「値を変える→グラフを見る→また変える」は
再フォークの繰り返しで行います（式を選択→🔢→値を変更→コード生成→実行）。
過去の図は消えずタイムラインに積み上がるので視覚比較できます。直前に成功した
（NaNでない）実行の値は、次に同じ式でモーダルを開いたときの固定値入力の
デフォルトとして自動的に入ります。

**前提条件との整合性:** 式が導出時の仮定（例: 判別式 `D>0`）に依存している場合、
その仮定に反する固定値でのフォークは拒否され、再入力を促されます。前提が
掃引変数を含むなどフォーク時に判定できない場合は、実行結果が全点 NaN になった
時点で「成功」ではなく警告として検出されます（該当パラメータの組み合わせを表示）。

**対応範囲と制限:**

- 決定的経路の対応関数は sin/cos/tan/exp/log/sqrt/abs など（ホワイトリスト方式。
  未対応の構造は黙って誤変換されず、明確なエラーになります）。ホワイトリスト外の
  式（特殊関数など）は 💬 対話経路＝LLM コード生成の担当です。
- **Julia セッション**（第二量子化）の計算結果は決定的テンプレートでは扱えませんが、
  LLM 経路が式の表示形（TeX）からコードを書けます（レビュー必須）。
- `eigenvalues` のリスト出力は直接フォークできません（solve 経由で個別式にして
  ください — エラーメッセージに誘導が出ます）。
- 生成物は**保存済みセッション JSON のフォルダ・ファイル名を利用した**
  `<保存先フォルダ>/<ファイル名>_numeric/<タスク>/<実行>/` に保存されます
  （セッション未保存のまま実行しようとするとエラーになり、保存を促されます）。
- 大規模計算は対象外です（生成コードを種に、コーディングエージェント等で
  発展させてください）。

## 複数の式・領域を組み合わせたグラフ

式を選択し「💬 対話で仕様を確定」（英語表示では “Set up via dialogue”）を開きます。
曲線の重ね描き、等高線・等式の境界、不等式で囲まれた領域、注目点を同じ図に描けます。
軸の範囲と標本点数を伝え、提案カードの参照式・条件・座標を確認して実行します。
この範囲の作図では、Adviserが構造化仕様を提案し、承認後に共通の描画処理が図を生成します。
通常の「🔢 数値計算へ」フォームは従来の単変数掃引などの入口です。
ヘッダの「🕸 数値グラフ」は計算の依存関係の表示で、ここで説明する作図とは別機能です。

1. 描きたい式・不等式・注目点の座標をノートに登録し、セッションを保存します。
2. 式を選択して対話を開き、式番号、軸名・範囲・点数、固定パラメータを伝えます。
3. 提案の軸と各レイヤーの参照式を確認します。誤り・不足があれば追加の指示で修正します。
4. 仕様を承認し、コード生成・実行へ進みます。対応する共通作図ではコード編集は不要です。
5. 結果カードの図を確認し、保存リンクから必要な成果物をダウンロードします。

たとえば、以下のように依頼できます（式番号は自分のノートのものに置き換えてください）。

- 「E1をx=-2から2で描き、k=1とk=3の曲線を比較。凡例を付けて」
- 「E2とE3の不等式を両方満たす領域を塗り、E4の等式を境界線として重ねて。
  x,yはそれぞれ-2から2、各軸201点で」
- 「青い領域の条件はE2・E3、緑の領域の条件はE5・E3。別の条件集合として重ねて。
  E6を横座標、E7を縦座標とする点も示して」

注目点の座標や等高線の値には、CASで求めたスカラー式の式番号を使えます。
作図機能そのものが最適化するわけではないため、「最適点」は先に計算して指定します。
既定の図形式はPNG・SVGです。PDFも必要なら依頼時に指定してください。
PNGはプレビュー用に必ず生成されます。計算後の図の下から指定形式の図、レイヤー別CSV、
診断用の `plot.json` を保存できます。図のダウンロードとセッション保存は別なので、
仕様・来歴を残すためセッションも保存してください。

領域は指定した格子で近似して描きます。細い領域・穴・境界付近を調べるときは
標本点数を増やしてください。画面の範囲外を含む全領域の厳密な判定ではありません。
各軸2〜2000点、レイヤーは最大32個、各軸の点数の積×レイヤー数は200万以下です。
非線形の領域も描けますが、厳密な形状や最適性の証明にはなりません。
軸は図の枠に合わせて独立に伸縮されるため、円が楕円に見える場合があります。
未定義の部分は描かれず、全点が無効なら失敗します。実数として描けない複素値も拒否されます。
空の標本領域や指定レベルの交差が見つからない場合は警告が表示されます。

同じ式のパラメータ比較はレイヤーごとの固定値で指定できます。式や条件を変更した後は、
新しい作図タスクを作ります。以前のタスクは作成時の参照式を保持し、変更によるstaleが報告されます。
操作例と確認項目は [汎用作図の再現例](scenarios/scenario_cartesian_plots.md) を参照。

**提案が失敗した場合:** Adviserへの接続・応答の失敗と、返答を仕様として読み取れない失敗は
区別されます。後者はアプリ側の仕様パーサによる判定で、図を生成した結果ではありません。
返答・エラー詳細を確認し、式番号や指定を明確にして再提案します。自動修復は保証されません。

## 注意点

- **仮定付きの積分・極限**: 変数の正負が不明なまま `1/x` を積分するなど、Maxima が条件分岐を必要とする場合に結果が変わることがあります。事前に `x > 0 を仮定する` などで仮定を追加してください。仮定・forget 操作自体がハングすることはありません。

- **陰関数の depends はセッション全体に影響する**: 「y を x の関数として微分」を選択すると `depends([y],[x])` が宣言され、セッション中すべての `y` の微分に影響します。意図しない場合は「両辺を独立に微分」を選んでください。

- **名前付き多変数関数の偏微分表示**: `f(x,y)` として定義した関数を偏微分すると `∂f/∂y` ではなく `f'(x,y)` と表示されます。`z = x^2+y^2` のような単純変数名の式では `∂z/∂y` が正しく表示されます。

- **量子代数操作（交換子など）**: 新規セッションで第２量子化カテゴリのドメイン（凝縮系の物理・量子光学・スピン系など）を選択すると Julia バックエンドで実行できます。Maxima セッションでは利用できません。

- **QuantumAlgebra のスピン演算子規約（重要）**: Julia バックエンドが使用する QuantumAlgebra.jl では、二準位系（TLS）のスピン演算子が**Pauli 行列規約**（固有値 ±1）で定義されています。凝縮系物理で標準的なスピン 1/2 規約（固有値 ±1/2）とは異なります。

  | 演算子 | QuantumAlgebra | 凝縮系標準 |
  |---|---|---|
  | `Sz(i)` | Pauli $\sigma_z$（固有値 ±1） | $S^z = \sigma_z/2$（固有値 ±1/2） |
  | `Sp(i)` | $\sigma^+ = (\sigma_x + i\sigma_y)/2$ | $S^+ = S^x + iS^y$ |
  | `Sm(i)` | $\sigma^- = (\sigma_x - i\sigma_y)/2$ | $S^- = S^x - iS^y$ |

  **影響例：** Jaynes-Cummings モデルの励起数保存演算子は `a'(1)*a(1) + Sz(1)` ではなく `a'(1)*a(1) + Sz(1)*(1//2)` と入力する必要があります。凝縮系・スピン系の計算で $S^z$ を使うときは、物理的な意味に応じて `Sz/2` にするか否かを確認してください。

- **スピン演算子 $S^+$/$S^-$ の定義（Julia セッション）**: `S をスピン演算子として定義する` は内部で `@tlsxyz_ops`（Sx/Sy/Sz）と `@tlspm_ops`（Sp/Sm）の両方を宣言します。この混在により `[H, S^z_{\rm tot}] = 0` のような保存則の確認が正しく計算できない場合があります（QuantumAlgebra の既知の制限）。

  **回避策：** `S をスピン演算子として定義する` の後、$S^+$ と $S^-$ を使いたい場面では、別途以下のように式として登録してください：

  ```
  Sp_1 = Sx_1 + i * Sy_1
  Sm_1 = Sx_1 - i * Sy_1
  ```

  これにより演算子がすべて Sx/Sy/Sz の基底に統一され、`normal_form` が正しく保存則を確認できます。Hamiltonian も同様に Sx/Sy/Sz で書くことを推奨します（例：Heisenberg モデルは `J * Sz_1 * Sz_2 + J/4 * (Sx_1 * Sx_2 + Sy_1 * Sy_2)`）。

  ※ 初回起動時の遅延（Time-to-first-X 問題）を避けるため、事前にターミナルで `./scripts/build_sysimage.sh` を実行して Julia のカスタムシステムイメージを構築しておくことを強く推奨します。

- **CAS 文法は直接入力しない**: `ratsimp(E1)` などの Maxima 文法は入力しないでください。自然言語で「E1 を有理式として簡約」と指示してください。

- **式番号の参照**: タイムラインの式番号（E1、E2 …）は操作指示の中でそのまま使えます。ブランチをまたいでも式番号は衝突しません。

- **変数間のスペース**: テキストで多変数式を入力するときは変数の間にスペースを入れてください（`a x + b` であって `ax+b` ではありません）。`ax` は Maxima では一つの変数名として解釈されます。

- **括弧の前のスペースは「乗算」、スペースなしは「関数呼び出し」**:

  シンボルと `(` の間に**スペースがあるか**で、積か関数適用かが決まります。スペースが
  ある場合は、そのシンボルが既知関数・宣言済み関数でない限り**乗算**として解釈されます。
  この判定はセッションの宣言（`SymbolContext`）と組込関数表に基づいて自動で行われます。

  ```
  a (x+1)     →  a × (x+1)   ← スペースあり＋a は関数でない → 積
  a(x+1)      →  a(x+1)      ← スペースなし → 関数呼び出し
  a * (x+1)   →  a × (x+1)   ← * を明示しても同じ（積）
  sin (x)     →  sin(x)      ← 組込関数はスペースがあっても呼び出し
  f (x)       →  f(x)        ← f を関数として宣言済みなら呼び出し
  ```

  **判定ルール（自動）：**
  - シンボルと `(` の間に**スペースがない** → 常に関数呼び出し（`a(x+1)`）
  - **スペースがある**:
    - シンボルが組込関数（`sin`, `cos`, `exp`, `sqrt` …）または宣言済み関数・演算子 → 関数呼び出し
    - それ以外（スカラー・未宣言・数値） → **乗算**（`a (x+1)` = `a*(x+1)`、`2 (x+1)` = `2*(x+1)`）
  - 迷ったときは `*` を明示すれば常に確実です。

  > 組込関数の表はバックエンドごとに異なります（Maxima は `conjugate`/`ceiling`、
  > Julia は `conj`/`ceil` など）。各バックエンドが認識する綴りのみが「スペースあり
  > でも関数呼び出し」になります。

  括弧を使わない積（`a b^2`、`m v` など）はスペースで問題ありません。
