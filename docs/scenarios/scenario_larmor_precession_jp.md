# 実践ループ サンプルシナリオ：スピンのラーモア歳差運動

**物理的テーマ:** 磁場中のスピン 1/2 の運動方程式（NMR・ESR の基礎）  
**バックエンド:** Julia（第二量子化セッション）  
**所要時間:** 約 15 分  
**検証目的:** Julia/QA の基本ワークフロー（演算子定義 → 交換子 → 運動方程式）の使い勝手確認

---

## 物理的背景

磁場 $B$ 中にあるスピン $S$ の Zeeman ハミルトニアン：

$$H = -\gamma B \, S_z$$

Heisenberg 運動方程式から歳差運動の方程式が導かれる：

$$\frac{dS_x}{dt} = 2\gamma B \, S_y, \quad \frac{dS_y}{dt} = -2\gamma B \, S_x, \quad \frac{dS_z}{dt} = 0$$

（QuantumAlgebra は Pauli 行列規約 $[S_x, S_y] = 2i S_z$ を使用するため係数 2 が入る）

最後に $[H, S_z] = 0$ で $S_z$ が保存量であることを確認する（ステップ 9）。

```

$\frac{dS_x}{dt} = i[H, S_x] = i(-2i\gamma B S_y) = 2\gamma B S_y$

**検証ポイント:**
- [ ] Heisenberg 方程式の書き方（`Sx_1 の Heisenberg 方程式 H`）が通るか

```

### ステップ 8：Heisenberg 方程式（Sz）

```
Sz_1 の Heisenberg 方程式 H を計算して
```

**期待する出力:** $\displaystyle\frac{dS_z}{dt} = 0$

$S_z$ は保存量（$H$ と可換）なので時間変化しない。

$[H, S_z] = -\gamma B [S_z, S_z] = 0$ — $S_z$ は確かに保存量。

## 既知の注意点

| 注意点 | 詳細 |
|---|---|
| **Pauli 規約** | QuantumAlgebra は $[S_x, S_y] = 2i S_z$ を使う（スピン 1/2 教科書は $i S_z$）。係数が 2 倍になる |
| **書法は最初の入力で決まる** | `Sz_1`（サフィックス）か `S^z_1`（上付き）のどちらで最初に入力するかで、セッション全体の表示スタイルが決まる。混在は非推奨 |
| **サイト指定** | `Sz_1`（サフィックス）または `Sz(1)`（括弧）のどちらでもよい。ただし書法は一貫させること |
| **`S_z_1` は使用不可** | アンダースコアを挟む形式 `S_z_1` はサポートされていない（`S_z` は `Sz` とは別の識別子になる） |
| **方程式でのサイト指定** | H-1 形式で `[H, S_x]` と書いた場合、`S_x`（サイト未指定）は Julia で `S(x)` と解釈されエラー。必ず `S_{x_1}` や `Sx_1` とサイトを明示する |
| **Heisenberg 方程式の表示** | `heisenberg_equation` の結果は `d(Op)/dt = RHS` 形式で表示（修正済み b2afc90） |
| **スカラーの宣言順序** | ステップ 2 を必ずステップ 3 より先に行う。未宣言のままハミルトニアンを登録すると警告が出る |
| **[H, Sz] = 0 は正しい** | $H$ は $S_z$ で書かれているので $[H, S_z] = 0$ は物理的に正確（保存量）|
| **Heisenberg 方程式の書き方** | `Sx_1 の Heisenberg 方程式 H` が通らない場合は `Sx_1 の Heisenberg 方程式 E3`（式番号）で試す |

## workflow 版リプレイ（S-z、C-Ext-5 `heisenberg_components`、2026-07-17 実施）

ステップ 4〜9（交換子2回＋Heisenberg方程式3回＋確認）を、C-Ext-5 の固定 workflow
`heisenberg_components`（NL トリガ「S の各成分のハイゼンベルク方程式」）**1指示**で
再現できるかを実機検証。ステップ 1〜3（S 定義・γ/B 宣言・H 登録）は手動のまま。

**正常系:** ステップ1〜3実施後に「heisenberg equations for all components of S」を
入力 → プラン P1（`Sx_1`/`Sy_1`/`Sz_1` の3ステップ）が実行され、結果は元の手動シナリオの
ステップ6〜8と**完全一致**：

| 成分 | workflow 版の結果 | 手動シナリオ（ステップ6〜8） |
|---|---|---|
| $dS_x/dt$ | `2B*gamma * Sy(1)` | $2\gamma B \cdot S_{y_1}$ ✓ |
| $dS_y/dt$ | `-2B*gamma * Sx(1)` | $-2\gamma B \cdot S_{x_1}$ ✓ |
| $dS_z/dt$ | `0` | $0$ ✓ |

**停止安全＋retry_plan の実操作確認:** 意図的にステップ1（S を演算子として定義）を
**後回し**にし、γ/B 宣言→H 登録（`Sz_1` 未宣言のまま warning 付きで登録される）→
workflow トリガ、という順で実行。結果は期待どおり：

- プラン P1 がステップ s1（`Sx_1` の Heisenberg 方程式）で
  `Undefined symbols: Sz. Please define them before computing.` により失敗、
  s2/s3 は `skipped`、`plan.status = "stopped"`（0/3 成功、途中結果は保持）。
  タイムライン UI にも ✗/⊘ の内訳が正しく表示された。
- その後「S を演算子として定義する」を実行して根本原因を解消し、
  `engine.retry_plan("P1")` を実行（UI ボタンが無いため、保存済みセッションに対し
  直接エンジン呼び出しで確認——後述の課題を参照）。`retry_plan` は**新しい別プラン
  P2**（`retried_from="P1"`、B-3 の設計どおり「不変履歴」）を生成し、3ステップとも
  成功。値は上表の workflow 版の結果と一致。P1 自身は `stopped` のまま不変で
  保存され続けることも確認。

**発見した課題（新規、open_items.md へ追記）:** `ui/timeline_serializer.py` は
`StepKind.plan_execution`（および `branch_fork`/`ambiguity_resolution`/
`assumption_remove`）を一切扱っておらず、固定 workflow 経由のプラン実行サマリは
**ページ再読み込み後にタイムラインから消える**（成功・失敗いずれの場合も）。
確認クリック直後のライブ描画（本セッションでの目視確認）は正しく機能するが、
`GET /timeline`（reload 時に使用）が生成する `entries` に該当ステップが含まれない
ため、`engine.plans`/`engine.steps` 自体にはデータが残っているにもかかわらず、
UI 上は「そのプランが実行された痕跡」が完全に消える。retry_plan 自体に
HTTP ルート／UI ボタンが未接続であることも同時に判明（現状はエンジンメソッドの
み——本検証も保存済みセッションへの直接呼び出しで実施）。

**修正確認済み（D-5、2026-07-17、同日）:** 上記2件は `ui/timeline_serializer.py`
への `plan_execution` 分岐追加、`POST /plan/retry/{plan_id}` ルート新設、UI への
🔁 再試行ボタン追加で修正した。本シナリオのブラウザ実機で確認：停止した P1 の
プランカードがページ再読み込み後も消えずに表示され続けること、および
新設の 🔁 再試行ボタンをクリックすると（`S` 定義後）`engine.retry_plan()` を
直接呼んだ場合と同じ結果（新プラン P2、3ステップとも成功、上表と同じ値）が
UI 経由で得られることの両方を確認した。詳細は open_items.md の実装済み項目
アーカイブ（D-5）を参照。
