### 物理的背景

$N$ 粒子の単原子理想気体。古典統計力学の分配関数から熱力学量を導出する。

$$Z_1 = \frac{V}{\lambda^3}, \quad \lambda = \sqrt{\frac{h^2}{2\pi m k_B T}} \quad \text{（de Broglie 熱波長）}$$

$$Z_N = \frac{Z_1^N}{N!} \quad \text{（区別不可能な粒子、Gibbs の補正）}$$

$$F = -k_B T \ln Z_N \quad \text{（Helmholtz 自由エネルギー）}$$

熱力学量の導出：
$$P = -\left(\frac{\partial F}{\partial V}\right)_T = \frac{Nk_BT}{V} \quad \text{（理想気体の状態方程式）}$$

$$U = -T^2\frac{\partial}{\partial T}\!\left(\frac{F}{T}\right) = \frac{3}{2}Nk_BT \quad \text{（内部エネルギー、Gibbs–Helmholtz 関係）}$$

$$C_V = \left(\frac{\partial U}{\partial T}\right)_V = \frac{3}{2}Nk_B \quad \text{（定積熱容量）}$$

**注:** $P,U,C_V$ の導出過程では $N!$ の $V,T$ 依存性がゼロなので、微分の過程で自動的に消える。
Stirling 近似（$\ln N!\approx N\ln N-N$）が必要になるのはエントロピー $S=-(\partial F/\partial T)_V$
を直接計算する場合のみで、本シナリオのチェックリストには含めていない。

### 一般操作での組み立て方（★このシナリオの肝）

CAS 構文を書かず、H-1 の式登録・E-id 参照連鎖・一般 differentiate 操作のみで、**物理的背景の
TeX 表記をそのまま**入力する：

1. $\lambda,Z_1,Z_N,F$ は H-1 の等式形式（`\lambda = \sqrt{h^2 / (2 * \pi * m * k_B * T)}` 等）で
   順に登録する。各式は前段の E-id を直接参照できる（`Z_1 = V / E1^3` の `E1` は $\lambda$ の
   定義）ので、Maxima 側で自動的にシンボル定義として束縛される（H-1 P2 機構）。後段の式では
   前段の値が自動的に展開される。
2. $\pi$ は Unicode でなく TeX コマンド `\pi` を使う（プロジェクト規約）。
3. $P=-\partial F/\partial V$ は「$F$ を V で偏微分して」→ 結果を `-` で符号反転した新しい式
   `P = -E6` として登録する（Maxima 構文 `diff(F,V)` を書く必要はない）。
4. $U=-T^2\,\partial(F/T)/\partial T$ は、まず `FoverT = F / T` で $F/T$ を新しい式として作り、
   それを T で偏微分してから `-T^2` を掛けた式として登録する。

## 確認された挙動・注意点

- **postfix の `!`（階乗）が SharedParser で完全に無視されていた（根本バグ、修正済み）。**
  `notebook/runtime/shared_parser.py` のトークナイザ正規表現 `_TOKEN_RE` に `!` の
  パターンが存在せず、`N!` は黙って `N` として字句解析されていた（エラーにならず**静かに
  数式が壊れる**、最も気づきにくい種類のバグ）。この壊れ方は「H-1 での直接登録」では
  表面化しない（登録時は生テキストがほぼそのまま Maxima に送られるため）が、**一般操作
  （`展開`・`微分` 等）はいったん SharedParser で式を再解析してから CAS コマンドを再生成する**
  ため、$Z_N$ を求めた直後は正しく $N!$ が表示されていても、その後 `F を展開して` を実行した
  瞬間に $N!$ が $N$ に化けるという形で発覚した。
  修正：`_T_BANG` トークンを追加し、`parse_primary` で後置の `!` を
  `FunctionCall(factorial, [operand])` に変換するようにした（`factorial` は
  `MaximaSemanticResolver` に既知関数として登録済みだったため、パーサー側の追加だけで
  前置・後置どちらの記法も同じ経路で解決される）。
- **添字1文字の記号（`k_B` 等）は宣言時に曖昧確認ダイアログの対象になる。** これは意図された
  挙動（`CLAUDE.md` Subscript Classification 参照）だが、非対話的な generator 実行との統合が
  未対応だった。`scripts/generate_scenario_examples.py` を拡張し、`needs_confirmation` を
  受け取ったら実際の UI の確認ボタン押下と同じ経路（`engine.run_operation(candidate.operation,
  candidate.args)` を直接呼ぶ）で「名前の一部」候補を選択するようにした。これにより `kB` の
  ような添字を消した回避名を使わずに済む。

**確認日:** 2026-07-02（実機 Maxima、generator 経由で全14ステップ完走。TeX 表記の
`k_B`・`\lambda`・`N!` をそのまま入力）。
