# 実践ループ サンプルシナリオ：フーリエ変換・畳み込み・Z変換

ガウス関数のフーリエ変換とその逆変換、ガウス関数同士の畳み込み、離散信号の Z 変換を
求める。

**バックエンド:** standard（Maxima）／**ドメイン:** 信号処理（signal_processing）。

## SCENARIO-MACRO の第5号 —— マクロ3つを削除し、primitive を1つ残した

**2026-08-14 に `fourier_transform_by_definition` / `inverse_fourier_by_definition` /
`convolve` を削除した**（open_items SCENARIO-MACRO）。3つとも中身は
`integrate(...)` の組み立てで、研究者が定積分として書ける。

**`z_transform_by_definition` は残した。** 中身は Maxima の `nusum`（無限和の閉形式）で、
**一般操作では書けない**——実測すると `\sum_{n=0}^{\infty}(1/2)^n z^{-n}` は
`sum(..., n, 0, inf)` のまま閉じない。起票が「本物の primitive 不足」と判定したとおりで、
第4号の `pure_nash_equilibria` に続く2件目の「残す」判断である。

**書き直しの本当の利点は、収束の仮定が研究者のものになったこと。** マクロは
`_positive_params_assume` で**式中の記号パラメータを全部正と仮定**してから積分し、
直後に忘れていた。これは「問題依存の判断を共有コードに焼き込まない」という規則
（CLAUDE.md の no-hardcoded-modeling-choices）に照らすと**隠れたモデリング選択**である。
一般操作で書けば、$a>0$ は段 5 の**明示的な仮定**になり、タイムラインに残る。

**この書き直しが掘り当てた欠陥（根治済み、別コミット）:** 畳み込みを $\tau$ について
書こうとして、`\int_{-\infty}^{\infty} f d\tau` が**生の pydantic ValidationError** を
返し、`\int_0^{2\pi} r\,dr\,d\theta`（**この系自身が印刷している綴り**）が黙って
**積**になることが分かった。測度を読む実装が2箇所にあり、片方だけが `d\theta` を
読めていた（open_items MEASURE-READ-TWICE）。**ギリシャ文字の積分変数は
dθ・dφ・dτ・dω と全部この形**なので、範囲は広い。

## 手順と期待値

| 段 | 入力（自然言語 / 数式） | 結果 |
|---|---|---|
| 1 | `$F = \int_{-\infty}^{\infty} e^{-t^2} e^{-i \omega t} dt$` | フーリエ変換を**定義そのまま**書く |
| 2 | `E1 の右辺を計算して` | $F = e^{-\omega^2/4}\sqrt{\pi}$ |
| 3 | `$f = \frac{1}{2\pi}\int_{-\infty}^{\infty} \sqrt{\pi} e^{-\frac{\omega^2}{4}} e^{i \omega t} d\omega$` | 逆変換も定義そのまま |
| 4 | `E3 の右辺を計算して` | $f = e^{-t^2}$ —— **往復が閉じる** |
| 5 | `a > 0 と仮定する` | **収束条件を研究者が明示する**（マクロは全パラメータを黙って正と仮定していた） |
| 6 | `$G = \int_{-\infty}^{\infty} e^{-a t^2} e^{-i \omega t} dt$` | パラメータ付きガウス関数 |
| 7 | `E5 の右辺を計算して` | $G = \dfrac{e^{-\omega^2/(4a)}\sqrt{\pi}}{\sqrt{a}}$ |
| 8 | `$C = \int_{-\infty}^{\infty} e^{-\tau^2} e^{-(t-\tau)^2} d\tau$` | 畳み込みも定義そのまま（$d\tau$ が読めるようになった） |
| 9 | `E7 の右辺を計算して` | $C = \dfrac{e^{-t^2/2}\sqrt{\pi}}{\sqrt{2}}$ —— **分散が2倍**になる |
| 10 | `(1/2)^n を定義に従ってZ変換して` | $\mathcal Z\{2^{-n}\}(z)=\sum_{n=0}^{\infty}2^{-n}z^{-n}=\dfrac{2z}{2z-1}$（**残した primitive**） |

## 確認された挙動・注意点

- **往復が閉じることが段 1〜4 の成果である。** $e^{-t^2}$ を変換して $e^{-\omega^2/4}\sqrt\pi$、
  それを逆変換して $e^{-t^2}$ に厳密に戻る。マクロでも同じ値は出ていたが、
  **定義の積分そのものがタイムラインに残る**ので、何を計算したのかが読める。
- **収束の仮定は段として残る。** 段 5 を省くと Maxima が $a$ の符号を問う対話質問を
  出し、操作は理由つきの失敗になる（永続アダプタは固まらない）。**問うのが正しい**
  ——$a<0$ ならこの積分は発散する。
- **Z 変換は残した primitive。** `nusum` を `limit(nusum(...,N),N,inf)` で包むと、
  記号的な底で Maxima が対話質問（"Is z-1 positive..."）を出して**永続アダプタが
  固まる**（実測記録あり）。素の `nusum` は固まらない代わりに記号底では境界項を
  残すことがあり、それは研究者自身の収束域の仮定で畳むべきものである。
  **この知識はマクロの docstring に残っている**——消していないので蒸発していない。
- **`\sum_{n=0}^{\infty}` と書いても閉じない。** 実測すると `sum(...,n,0,inf)` のまま
  返る。Maxima の `sum` は閉形式を作らないので、無限和の閉形式は `nusum` が要る
  ——これが「primitive 不足」の実体である。一般操作 `summation` を無限和まで
  伸ばせれば Z 変換も一般操作になるが、上記のアダプタ凍結の罠を越える必要がある。
