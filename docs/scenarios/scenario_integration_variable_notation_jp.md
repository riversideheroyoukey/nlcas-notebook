# 実践ループ シナリオ：積分変数を自分の記法で書く（θ・\theta・theta）

> 2026-08-03 実施。**ノートが表示したものを、そのまま書き戻せる**か——積分変数まわりの
> 綴りを3通り試し、結果が一致することを確認する。

**バックエンド:** Maxima／**ドメイン:** 電磁気（極座標の面積分）。

### なぜ確認するのか

ノートは結果を TeX で表示する。研究者は表示されたものを次の入力に書き戻す——それが自然な
使い方で、[docs/32](../developer_manuals/32_user_cas_boundary_repair_plan.md) の「利用者書式⇄CAS 書式」の
境界がやっていることでもある。ところが積分変数だけは、**3通りの書き方のうち通るのは1通りだけ**
だった時期が長い:

| 綴り | 2026-08-02 より前 | 現在 |
|---|---|---|
| `theta`（プレーン） | 通る | 通る |
| `\theta`（TeX、表示形そのもの） | パターンの `[A-Za-z_]\w*` に当たらず不一致 | 通る |
| `θ`（Unicode、そのままキーボードから） | ルールベース割り込みより後で正規化されるため不一致 | 通る |

Unicode の方は**変換器は存在して正しく動いていた**のに、呼ばれる場所が
`LLMSupervisor.interpret()` の冒頭＝ルールベース割り込みより後だった。正規化の入口を1つに
まとめて解決した（`interpret_common.normalize_request_greek`）——**綴り表を1つも増やさず**、
しかも Maxima と Julia が同時に直った。

### 物理・数学の筋

単位円板 $x^2+y^2\le1$ 上での $\iint (x^2+y^2)\,dx\,dy$（一様円板の極慣性モーメント $\times$ 面密度）。
極座標に変換すると被積分関数にヤコビアン $|J|=r$ が掛かって
$\int_0^{2\pi}\!\!\int_0^1 r^3\,dr\,d\theta = \pi/2$。

## 確認された挙動・注意点

**このシナリオを組む過程で silent-wrong を1件見つけた。**

変数変換を **`から`〜`へ` を省いて**書くと——`E1 を x = r cos(θ), y = r sin(θ) で変数変換して`
——単変数用の `change_variable` に流れ、範囲つき定積分の**表示専用オブジェクト**が
そのまま Maxima の `changevar` に渡っていた。結果は `_res_`（アダプタ自身の作業変数の名前）で、
それが**成功した式としてタイムラインに登録**され、後続から値のように参照できた。
ギリシャ文字とは無関係で、プレーン名でも `u,v` の一次変換でも同じだった。

範囲つき定積分は**設計上、表示専用**（入力時に CAS を呼ばない、INTEGRAL-COV）。その専用操作
（`change_variables_integral_form`・`evaluate_integral_form`）はエンジンのメソッドで
`run_operation` を通らないので、**そこに到達した時点で一般操作が絵を渡されている**。
`_reject_display_only_operands` を拡張し、正しい書き方を名指しして断るようにした（F-9 が
角運動量の表示専用状態に対して置いた同じガードの拡張）。

**アダプタ側に歯止めを置こうとして失敗した記録も残す。** 「自分の作業変数名が返るのは答えでは
ない」と考えて `_res_` をアダプタで弾いたところ、**通っていたテストが5件落ちた**——実測すると
`_res_` は単一式でないコマンドすべての通常の結果で、アプリの**宣言コマンドは全部その形**
（`errcatch(_res_:(declare(Delta, scalar); true))` は括弧内の区切りが `;` なので束縛されない）。
形だけを見た一般化が誤りだった。撤回し、同じ判断を繰り返さないよう
`maxima_adapter.py` に理由を書いた。

**もう1件、英語だけの silent-wrong も同時に出た。** 積分形が無い状態で
`evaluate this integral` と書くと、割り込みが降りて後段の alias 走査に拾われ、
**`evaluate` という語が積分変数として解釈された**式が成功として登録されていた
（日本語は中身が空の確認ダイアログ）。**2026-08-04 根治**——割り込みが降りるのをやめ、
理由付きの失敗を返すようにした（open_items アーカイブ EVAL-INTEGRAL-EN-FALLTHROUGH）。

**確認日:** 2026-08-03（実機 Maxima、ST-1〜5 完走・3綴り一致）。
