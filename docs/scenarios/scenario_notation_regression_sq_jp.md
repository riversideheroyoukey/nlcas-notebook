# 記法の回帰確認（第２量子化）：プライムとオペランドの綴り

## ねらい

[Maxima 側の回帰確認](scenario_notation_regression_jp.md)の**第２量子化版**。
バックエンドが違うと読む層も違うので、ファイルを分けてある（ドメインのカテゴリが
`second_quantization` なら Julia が主バックエンドになる）。

ここで確かめるのは2つの族である。

**① プライムは、演算子のときだけ随伴である。** `a'(k)` は生成演算子だが、
`t'`・`\sigma'`・`\mathbf r'` は**別の変数**を指す研究者の印で、これは
`latex_converter` が既にそう読んでいる。Julia の表示側だけが区別せず、
**語の後ろのプライムを全部短剣符に**していた（実測 2026-09-11。
`G(t, t')` が `G(t, t^{\dagger})` と出ていた）。判別子は**宣言**で、公開されて
いる Julia セッションを数えるとプライムの付く演算子の基底は全部
`kind == "operator"`、別変数の印である `sigma` はどこにも宣言されていない。

**② オペランドの綴りは1つの表で答える。** ハイゼンベルク一族が「演算子の
オペランドはどう書かれるか」に**3通りの自前クラス**で答えており、72通り
（語順7 × 形9 × 日英）のうち18が壊れていた——`c(k,u)` が `u)` に**黙って切れ**、
`c_{1\uparrow}` が当たらず、空白入りの `c(1, u)`（**Maxima の `tex1` が印刷する形**）
も当たらなかった。

## 並んでいる綴りと、それが確かめていること

| 綴り | 一度どうなっていたか | 起票 |
|---|---|---|
| `a'(k)`（宣言済みの演算子） | ——（正しく `a^{\dagger}(k)`） | PRIME-DISPLAY-DAGGER |
| `G(t, t')` | `G(t, t^{\dagger})` | PRIME-DISPLAY-DAGGER |
| `\sigma'` | `\sigma^{\dagger}` | PRIME-DISPLAY-DAGGER |
| `c(k,u)` をオペランドに | `u)` に黙って切れる | OPERAND-SPELLING |
| `c(1, u)`（空白入り） | どの語順でも当たらない | OPERAND-SPELLING |
| `c_{1\uparrow}` | 語順②③で当たらない | OPERAND-SPELLING |
| 光子の `\sum_\sigma`（spin 1） | 展開されず形式和のまま、4演算子の項が残る | OPERAND-BOUNDARY ③ |
| `a_{1,+}`（**系が印刷した綴りを打ち返す**） | 生の Julia `ParseError:` が研究者に返る | PROJECTION-ROUND-TRIP |
| `a_{1+}`（貼り付いた形） | 同上 | PROJECTION-ROUND-TRIP |

## 期待される読み

- `a'(k)` → 表示 `a^{\dagger}(k)`（**宣言済みの演算子**なので随伴）
- `G(t, t')` → 表示 `G(t, t')`（`G` は演算子として宣言していないので**プライムのまま**）
- `\sigma'` → 表示 `\sigma'`（同上。スピン添字のプライムは別の値を指す印）
- `c(k,u)` / `c(1, u)` / `c_{1\uparrow}` → **どれもオペランドとして丸ごと読まれる**
  （切れていれば時間発展は別の演算子について答えるか失敗する）
- 光子（spin 1、ヘリシティ $\pm1$）の $\sum_\sigma$ どうしの交換子 →
  **`- a^\dagger_{1+} a_{2+} - a^\dagger_{1-} a_{2-}`**。射影ごとに1項で、$\sum$ は
  残らない。整数スピンの綴りは $\pi^+\pi^0\pi^-$ と同じ上付き符号で、**電子の矢印と
  同じ扱い**になる（直す前は形式和のまま `\sum_{s,s_1}` の4演算子項が残っていた
  ——項は打ち消し合うので誤答ではないが、同じ指示が粒子によって別の形で返っていた）
- `a_{1,+} と a^\dagger_{1,+} の交換子` → **1**、`a_{1+} と a^\dagger_{1-}` → **0**。
  上の交換子が**印刷する綴り**（`a^\dagger_{1,+}`）をそのまま打ち返している——
  直す前は生の Julia `ParseError:` が返り、m=0 に至っては `b_{10}` と印刷されて
  **サイト10と見分けが付かなかった**。矢印は `\uparrow` がコマンド＝境界なので
  最初から通っており、**符号にだけ入力の綴りが無かった**
- `\lim_{x \to 0} \frac{\sin x}{x}` → **登録され、表示される**（Julia セッション）。
  極限は Symbolics.jl に無いので**計算はできない**が、このコードベースの方針は
  「書けて表示はできる、断るのは使用地点」である——直す前は、使おうとすると
  **「未定義の記号: lim, to」**が返っていた。`lim` も `to` も研究者は書いておらず、
  極限の正準綴りをばらした断片で、設計した断り（`julia_limit`）はその手前で
  一度も到達していなかった（REFUSAL-NOT-REACHED ①）
