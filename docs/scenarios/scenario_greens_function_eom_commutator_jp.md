# 実践ループ シナリオ：運動方程式の交換子を、演算子代数で実際に計算する

> 2026-08-21 実施。姉妹シナリオ
> [scenario_greens_function_from_hamiltonian](scenario_greens_function_from_hamiltonian_jp.md)
> （Maxima）の**1段だけ**を、演算子代数を持つバックエンドで計算する。

**バックエンド:** Julia full（QuantumAlgebra）／**ドメイン:** 物性（condensed_matter）。

### なぜ分けるのか（**この切り分けは 2026-07-30/31 に決定済み**）

役割分担は今回決めたことではなく、記録がある:

> **バックエンド選択の含意。** …凝縮系ドメインの既定は Julia でバックエンドは
> セッション作成時に固定（Core Principle #6）なので、**松原グリーン関数の代数を
> やるなら Maxima セッションを選ぶのが現状の正解**、演算子代数（Wick 収縮・
> 正規順序）が要る局面だけ Julia、という切り分けになる。
> ——[docs/33 §7](../developer_manuals/33_time_dependent_operators_and_green_functions.md)（2026-07-30）

そして本線は **SCALAR-HANDOFF**（Julia → Maxima、[docs/34 §5](../developer_manuals/34_field_operators_pair_representation_and_scalar_handoff.md)、
2026-07-31 決定・2026-08-02 実装）。実際に境界を越えるシナリオは
[S-c（BCS ギャップ方程式）](scenario_bcs_gap_equation_jp.md)で、`vacuum_expectation`
で c 数に落ちた**あと**に `E15 を Maxima セッションに渡して` で渡している。

**ここでは handoff を使えない**（実測 2026-08-21）。渡したいのは交換子の結果で、
それは演算子のままだからである:

> E2 には演算子（c, c'）が残っているため、スカラー CAS のセッションへは渡せません。
> 渡せるのは演算子を含まない式だけです（期待値・係数など、演算子代数が終わった
> あとの量）。

**逆向きも塞がっている**: 2時刻のグリーン関数 $c_{n}(t)c^\dagger_{m}(t')$ は
Julia 側で操作できない（時間の付いた演算子は QA に置けない——docs/33 §5、
open_items PAIR-REP は未実装）。したがってこの導出の境界は、**機構が運べる位置と
一致しない**——姉妹シナリオへの受け渡しがメモなのはそのためである。

### 分ける理由（物理側）

グリーン関数の運動方程式の芯は $[\hat c_{m\sigma}, \hat H]$ である。**Maxima には演算子
代数が無い**ので、あちらのセッションでは演算子の対を1つの名前として運び、この交換子
だけは計算していない（対角化・基底への移行・Dyson の形式解・フーリエ・代入は
すべてあちらで計算している）。**バックエンドはセッション開始時に固定され、
途中で切り替えられない**（Core Principle #6）ので、交換子はここで別セッションとして
計算し、結果を向こうへ書き写す——**どちらのセッションで何を計算したかが履歴に残る**
のが、書き写しの根拠である。

### 何が確認されるか

- **和を含むハミルトニアンとの交換子が計算できる**。$\sum_n \varepsilon_n c^\dagger_n c_n$
  との交換子で δ が縮約され、$-\varepsilon_m c_m$ が残る（和は消える）
- **4添字の相互作用**との交換子が、$V$ の添字を保ったまま2項に開く
- 添字付きスカラー $\varepsilon_n$・$V_{p,q,s,n}$ が、束縛された和の添字を走る
