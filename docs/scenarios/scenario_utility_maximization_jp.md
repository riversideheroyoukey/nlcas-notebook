# 実践ループ サンプルシナリオ：制約付き効用最大化と比較静学

コブ・ダグラス型効用関数 $U(x_1,x_2)=x_1^ax_2^b$ を予算制約 $p_1x_1+p_2x_2=m$ の下で
最大化し、需要関数と所得感応度（比較静学）を求める。

**バックエンド:** standard（Maxima）／**ドメイン:** 数理経済学（mathematical_economics）。

## SCENARIO-MACRO の第3号 —— 一般操作だけで書き直した

**2026-08-14 に、専用操作 `form_lagrangian` / `stationary_conditions` /
`implicit_derivative` を使う形から書き直した**（open_items SCENARIO-MACRO）。中身は
それぞれ「目的関数−乗数×制約」の組み立て、`differentiate` を変数ごとに呼ぶ繰り返し、
`-diff(F,p)/diff(F,x)` というテンプレート1本で、**どれも研究者が書ける式**だった。

**移した知識:** ラグランジアンの形も陰関数定理も、**研究者が打つ1つの段**になった
（段 6 と段 16）。どちらも経済学の内容であって、システムの持ち物ではない。乗数の
自動採番（`lambda_1`）も要らなくなった——**名前は研究者が付ける**。

**ついでに直ったこと:** 旧シナリオは `U = x1^a * x2^b` / `p1*x1 + p2*x2 = m` と
**CAS 構文**（`*` つき、添字なしの `x1`）で書かれていた。これは書き手の趣味ではなく、
**下記の宣言を迂回するための綴り**だったと考えられる。書き直しで $x_1,x_2,p_1,p_2$ と
本来の記法になった。

## 確認された挙動・注意点

- **段 16 と段 18 が一致することが、このシナリオの成果である。** 陰関数定理から得た
  感応度と、解いた需要関数を直接微分した感応度が同じ値になる。**マクロではできなかった
  検証**——`implicit_derivative` は答えを1つ返すだけで、比べる相手が無かった。
- **⚠ 段 17（解く）は段 13〜16 より後でなければならない。** 解いた結果 $x_1=\dots$ は
  H-1 として登録され、P2 によって **CAS 側で $x_1$ が束縛される**。その後で
  $F=am-(a+b)p_1x_1$ を書くと $F$ は恒等的に 0 に潰れ、$\partial F/\partial m=0$ という
  **正しく見える誤り**が出る（実測）。順序はこのシナリオの内容の一部である。
- **添字つきの名前は宣言が要る。** $x_1$ を宣言せずに使うと、操作時に**成分インデックス**
  `x(1)` として解決され、$U$ の項が微分に寄与せず $\partial L/\partial x_1=-p_1\lambda$
  という**誤った一階条件**が出る（実測）。これは CLAUDE.md が記す仕様どおりの挙動
  （「未宣言の添字は操作では index」）で、欠陥ではない。段 1〜4 の宣言はそのためにある。
- **乗数の名前は研究者が付ける。** マクロは `lambda_1` を自動採番して衝突を避けていたが、
  研究者が $\lambda$ と書けばその名前が使われる。システムが名前を作らないほうが素直である。
- **英語版の連立は `and` 区切りで書く。** `solve E6 and E7 and E8 for …`。
  英語で最も自然なコンマ列 `solve E6, E7 and E8 for …` は**単一方程式の solve に落ちて
  無関係な答えを成功として返す**（実測、open_items SOLVE-LIST-COMMA-EN）。
  `and` 区切りは回避策ではなく正規の英語なのでそのまま使っているが、コンマ列が通る
  ようになったらそちらへ書き換えること。
