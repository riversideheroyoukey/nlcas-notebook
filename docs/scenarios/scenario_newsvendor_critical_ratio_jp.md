# 実践ループ サンプルシナリオ：ニュースベンダーモデル（臨界比・一様需要の最適発注量）

実践ループ・シナリオメニュー **S-v（SCM・物流）** の詳細化。過小在庫費用 $c_u$・過大在庫費用
$c_o$ の下、需要が一様分布 $U[a,b]$ に従うときの期待費用最小化問題を**微分→限界分析→solve**
で解き、最適発注量 $Q^*$ を求める。

**バックエンド:** standard（Maxima）／**ドメイン:** SCM・物流（supply_chain_logistics）。

## モデルの背景

需要 $D$ が既知の分布に従うとき、発注量 $Q$ に対する期待費用は「過大在庫」（$D<Q$ のとき
余った分 $Q-D$ に単位費用 $c_o$）と「過小在庫」（$D>Q$ のとき不足分 $D-Q$ に単位費用
$c_u$）の期待値の和になる。一般に、この期待費用を $Q$ で微分してゼロとおくと
（限界分析）、需要の累積分布関数 $F$ を使った**臨界比**の公式

$$F(Q^*)=\frac{c_u}{c_u+c_o}$$

が得られる（分布に依存しない一般的な結果）。

需要が一様分布 $U[a,b]$（密度 $f=1/(b-a)$）のとき、期待費用は閉形式で書ける：

$$C(Q)=\underbrace{c_o\,\frac{(Q-a)^2}{2(b-a)}}_{\text{過大在庫（期待値）}}
      +\underbrace{c_u\,\frac{(b-Q)^2}{2(b-a)}}_{\text{過小在庫（期待値）}}.$$

$C$ を $Q$ で微分してゼロとおき解くと：

$$\frac{dC}{dQ}=\frac{c_o(Q-a)}{b-a}-\frac{c_u(b-Q)}{b-a}=0
\;\Longrightarrow\; Q^*=\frac{c_ub+c_oa}{c_u+c_o}
=a+(b-a)\frac{c_u}{c_u+c_o}.$$

（後者の形は臨界比の公式に一様分布の $F(Q)=(Q-a)/(b-a)$ を代入したものと一致する。）

## セッション設定・記号

- モード **standard（Maxima）**、ドメイン **SCM・物流**。
- $Q,a,b$ は自由変数。$c_u,c_o$（過小/過大在庫費用）は**単一アルファベットの添字**
  （`u`, `o`）を持つため、使用前に実数として宣言する（下記の注意点参照）。
- **積の記法:** `c_o (Q-a)^2` のようにシンボル直後にスペース+丸括弧を続けると
  パースエラーになる（`c_o` が既知の関数名でも宣言済みの呼び出し可能記号でもないため）。
  明示的な `*` を使う（`c_o * (Q - a)^2`）。

## 入力ステップ

### ステップ 1：費用係数の宣言（一括）

```
c_u, c_o を実数とする
```

**期待する出力:** 「$c_u, c_o$ の添字（$u, o$）の役割を選んでください（同じ選択が全員に
適用されます）」という確認ダイアログが出るので、名前の一部（デフォルトの選択肢）を選ぶと
$c_u$・$c_o$ の両方が正しく登録される。

> **注意（単一アルファベット添字の分岐）:** `c_u`, `c_o` は数字ではなくアルファベット
> 1文字の添字なので、「成分インデックス」か「名前の一部」かの確認ダイアログが出る
> （既存の subscript classification 規則どおり）。「名前の一部」を選ぶことで
> $c_u$・$c_o$ が固有の費用パラメータとして正しく扱われる。

### ステップ 2：期待費用関数の定義（H-1）

```
C = c_o * (Q - a)^2 / (2 * (b - a)) + c_u * (b - Q)^2 / (2 * (b - a))
```

**期待する出力:** E1 として登録。

### ステップ 3：$Q$ で全微分

```
E1 を Q で全微分して
```

**期待する出力:** E2 $=\dfrac{dC}{dQ}=\dfrac{(Q-a)c_o}{b-a}-\dfrac{(b-Q)c_u}{b-a}$。

### ステップ 4：$Q$ について解く（最適発注量）

```
E2 を Q について解いて
```

**期待する出力:** E3 $=Q^*=\dfrac{bc_u+ac_o}{c_u+c_o}$（$=a+(b-a)\,c_u/(c_u+c_o)$ と代数的に
同値 — 下記「確認ポイント」参照）。

## 確認ポイント

- E3 の $Q^*=(bc_u+ac_o)/(c_u+c_o)$ は、臨界比の一様分布特殊化 $Q^*=a+(b-a)c_u/(c_u+c_o)$
  と代数的に一致する（$a+(b-a)c_u/(c_u+c_o)=(a(c_u+c_o)+(b-a)c_u)/(c_u+c_o)
  =(ac_o+bc_u)/(c_u+c_o)$）。
- 微分→solve という一般操作だけで、需要分布に応じた閉形式の期待費用関数から
  直接最適発注量を導出できる（分布を変えても同じ手順で拡張可能）。

## 確認された挙動・注意点

- **単一アルファベット添字は宣言時に確認ダイアログが出る。** `c_u`, `c_o` の `u`, `o`
  は数字ではないため、既存の subscript classification 規則（doc の
  「Subscript Classification in Symbol Declaration」）により自動では決まらず、
  ユーザーに問い合わせる。数字添字（`a_1` 等）は常に「名前の一部」として自動解決される
  のと対照的（S-s 参照）。
- **複数記号を1コマンドで一括宣言すると、確認ダイアログが必要な記号は最初の1つしか
  処理されなかった（発見・根治済み・2026-07-05）。** `"c_u, c_o を実数とする"` の
  ように**2つ以上をカンマ区切りで一括宣言**すると、確認ダイアログの返答を適用しても
  `c_u` だけが正しく登録され、`c_o` は未登録のまま残っていた（微分結果に `c(o)` と
  いう関数呼び出し形の化けが残る）。原因は `notebook/runtime/backend_handler.py`
  `extra_pre_phase1` が確認ダイアログの選択を**最初の曖昧な記号1つにしか適用しない**
  設計だったこと。選択（成分インデックス／名前の一部）をリスト内の**全ての曖昧な記号**
  に一律適用するよう修正（`tests/test_batch_symbol_declaration.py`）。英語版の
  一括宣言バグ（J-4、カンマリストの先頭・末尾しか登録されない）とは**別の、確認ダイアログ
  を伴う宣言パス固有の不具合**だったが、こちらも同時に根治し、J-4・J-5 とも
  open_items.md から解消済み。
