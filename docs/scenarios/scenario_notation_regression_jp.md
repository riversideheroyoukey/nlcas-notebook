# 記法の回帰確認：一度壊れていた綴りを、毎回打ち直す

## ねらい

**このシナリオは研究の筋道ではなく、記法の一覧である。** ここに並ぶ綴りは
どれも「読めているつもりで読めていなかった」もので、直したあとに**同じ壊れ方へ
戻らないこと**を、実例の再生成が毎回確かめるために置いてある。

> **なぜ要るか（実測 2026-09-11）。** 実例の再生成は表示の退行を一番よく捕まえるが、
> **シナリオが使っていない綴りには構造的に届かない**。同じ日に3つの欠陥
> （プライムが全部短剣符／`\vec A(t)` がベクトル×時刻／`vec(A)_x` という綴りが
> CAS へ渡って生のエラー）を踏み、**96本の公開実例はどれも無傷**、5000件超の
> テストも静的走査も緑だった。見つけたのは打ってみたことだけである
> （handoff (reference omitted from the public snapshot) §5.11）。

**限界も書いておく。** これは**退行**を捕まえる網であって、**未発見の欠陥**を
捕まえる網ではない。指示コーパスが「動く指示」から作られるのと同じ性質で、
新しい欠陥の供給源は ①系自身の表から綴りを引く（`scripts/nl_spelling_coverage.py`）
②系が印刷した綴りを打ち直す ③実践ループ、のまま変わらない。

**読み方。** 大事なのは「エラーにならない」ことではなく、**何になったか**である。
`\vec{A}(t)` は壊れていたときも登録には成功しており、違っていたのは意味だった。
生成物（`.json` / `.tex`）には canonical と結果が入るので、意味が変われば差分に出る。

## 期待される読み

- `\psi_\sigma` → `psi_sigma`、**簡約した結果の表示が `\psi_{\sigma}`**
- `G(t, t')` → 簡約した結果の表示が `G\left(t , t'\right)`
  （プライムは**別変数の印**であって随伴ではない）
- `\mathbf r` → 簡約した結果の表示が `\mathbf{r}`（`vec(` を画面に出さない）

> **なぜ「簡約して」を挟むのか。** 登録しただけの式は**研究者が打った LaTeX を
> そのまま**表示に使うので、表示側の直しは公開物に出ない（書いた直後に気づいた
> ——この規則を自分で書いておきながら、最初の版は2族ぶん取りこぼしていた）。
> 操作を1つ通すと表示が**組み立てられる**ので、そこではじめて表示の退行が差分に出る。
- `\vec{A}(t)` → `vec(A(t))`（**包みは適用の外**。`\vec{A} (t)` と空書きすれば積のまま）
- `\nabla \times \vec{A}` / `\nabla \cdot \vec{A}` / `\nabla \vec{f}` → **計算される**
- `\vec{A} の回転を求めて` → **計算される**（英語の同義文 `the curl of \vec{A}` は**裸の冠詞**が別名の手前に立つため書いた式が登録されず、生の `Maxima evaluation error` を返していた。記法 `\nabla \times \vec{A}` と同じ値になることが読みどころ）
- `\lim_{x \to 0} \frac{\sin x}{x}` を簡約 → **1**
- `\lim_{x \to 0^+} \frac{1}{x}` を簡約 → **inf**（片側が CAS へ届いている証拠。
  両側なら `infinity`）
- `\lim_{t' \to t^+} G(t,t')` → `limit(G(t, t'), t', t, plus)` のまま保持
- `x^3` を3階微分 → **6**
- `2 m = 8` を `m` について解いたあとの `E61 を m で全微分して` → **`2*m`**。
  **解いた変数はまだ変数である**——解の結果は `defining_expr_id` を持つのに CAS には
  束縛しない（実測）ので、「値を持つ名前は変数ではない」という断りを**帳簿の述語で**
  書くと、この行が理由なく断られる。断るかどうかを決めるのは CAS のほうである
- `2 m = 8` を `m` について解いたあとの `E61 を m で積分して` → **`m^3/3+3*m+C_1`**。
  2a-sym の「この記号は操作の変数か」の guard が**枠の手書きの一覧**で grammar より狭く、
  積分・極限・留数・部分分数・変数変換・代入の綴りで**名前が式番号へ化けて**いた。
  **解く前には通る**のが読みどころで、この行は解いたあとに置いてある
- `E66 を \bar{y} で偏微分して` → **`2*y_bar`**、`E66 を t' で偏微分して` → **`1`**。
  式は `latex_to_canonical` を通るのに**変数は通っていなかった**ので、同じ名前が2つの
  CAS 対象になり `0` が返っていた。プライムは共有の `symbol` に `'` が無く、英語では
  **切り詰められて** `0`。`y = x^3` が上にあるので、**`\bar{y}` が `y` ではない**ことも
  この行が見せている
- `E66 を \bar{y} で積分して` → **`y_bar^3/3+t'*y_bar+C_2`**。微分はインターセプタが
  読むので直っていたが、**不定積分は別名走査**が欄を埋めており、そこには「素の識別子と
  `\alpha` だけ」という手書きの規則が在った。`x_1` も同じ穴に落ちていた——普通の変数である
- `E70 の r を u に変数変換して` → **`'integrate(u^2,u)`**。被演算子を下ろしておらず、
  しかも `changevar` は**積分の名詞**にしか効かない（Maxima は `integrate(...)` を先に
  評価する）。積分の無い式には断る——名前を置き換えたいだけなら `substitute` が在る。
  英語の同義文は**別の理由**で落ちていた: この筋書きは `u` を解いており、2a-sym の枠の表に
  英語の変数変換が無かった（日本語だけが持っていた）
- `E72 と E73 を \alpha と \beta について解いて` → **`\alpha = 2`・`\beta = 1`**。
  **読みどころは英語の対のほう**（`solve … in …`）で、そちらは `x = 3-y` の形、つまり
  連立に1本だけ答える silent-wrong を返していた。日本語はずっと1つの助詞表を3鍵で
  共有しており、英語だけが `in` を1鍵に直書きしていた
- 宣言済みの `f` の偏微分 → **`'diff(f,x,1)`**。`偏微分して` は語尾が落ちて
  `偏微分` になるが、別名表にあるのは `微分` だけだったので、**式番号を持たない
  宣言済みの名前のときだけ**どの規則にも当たらなかった（英語は `derivative` が
  別名なので通っていた）
- 宣言済みの `A` のノルム → **`sqrt(A_z^2+A_y^2+A_x^2)`**。宣言だけの対象は
  `defining_expr_id` を持たないので式番号に書き換えられず、以前は名前で渡せなかった
  （値を必要とする操作は、いまも**満たされていない条件を述べて**断る）
- `[4, 0; 0, 1]` の行列式 → **4**。手前の `D`（行列式 3）は**おとり**である
  ——英語側の `compute the determinant of …` は文頭の計算動詞のせいで書いた行列が
  登録されず、**D の行列式 3** を `completed` で返していた。おとりが無いと
  「失敗する」だけになって、この欠陥は見えない
- `p を q の共役運動量とみなす` → **正準対 (q, p) の登録**。続く
  `q と p のポアソン括弧を求めて` が **1** を返すことが、対が実際に登録された証拠で
  ある（登録されていなければポアソン括弧は「正準対が宣言されていない」で失敗する）。
  以前は語尾が `とみなす` というだけで総称の宣言に拾われ、**スカラー `p` が登録されて
  成功が返って**いた
- `x のラプラス変換を X と宣言する` → canonical が
  **`'integrate(x*exp(-(s)*(t)),t,0,inf)`**（定義そのもの）。以前は語尾が `と宣言する`
  というだけで**変換の計算**へ流れ、名前 `X` はどこにも結びつかなかった
- `E27 に E28 を置換して` → **`2*a*t+b`**。以前は「必要な引数が不足しています:
  ['lhs', 'rhs']」——`代入して` なら通るのに `置換して` だけが、**書いた文に無い欄**を
  要求して断られていた（式→式の枠が動詞表を共有していなかった）
- `E27 の v に 5 を置き換えて` → **`5*a+b`**。`substitute_into` は `入れ` にだけ活用を
  書いており、`置き換え`＋`て`——いちばん普通のテ形——が行末の錨に当たって落ちていた
- `u と z について E31 と E32 を解いて` → **u = 2, z = 1 の2式**。変数が先に来る語順に
  鍵が無く、日本語は落ち、**英語は別名走査が答えて1本目だけを解き `completed` を
  返していた**（`solve for x and y in E1 and E2` → `3-y`）。日英の割れでもある
- `E35 を x で2階偏微分して` → **`20*x^3`**（$\partial^2/\partial x^2$）。日本語は
  最初から正しく、**英語の同義文 `the second partial derivative of E1 with respect to x`
  が黙って1階を返していた**——序数と種別語を掛けると 64綴り中36がそうだった。
  英語側の対訳がそれを打つ
- **末尾でもう一度打つ `\nabla \times \vec{A}`** は、前に出てくる同じ綴りと
  **同じ値**に着地しなければならない。あいだに挟まっているのは `y = x^3` で、
  H-1 の P2 がこれを `y : x^3` として CAS へ送る。`nb_curl_*` は座標変数を関数の
  中に綴っているので `diff(A_z,y)` が「`x^3` で微分せよ」になり、研究者には
  **生の `Maxima evaluation error`** が返っていた——発散も勾配もラプラシアンも、
  日英そろって。`∇` が座標を束縛するのは `∑` が添字を束縛するのと同じで、
  研究者はその名前を書いていないから、呼び出しのあいだだけ守る
  （COORD-NAME-BOUND）。**位置が読みどころ**である——上にある同じ綴りでは
  捕まらない。そこではまだ座標名が束縛されていないからだ
- `B をベクトル場とする` → **宣言される**（上に `y = x^3` が在っても）。宣言は依存変数を
  綴るので、`y` の束縛が `depends([B_x,B_y,B_z],[x,y,z])` に届き、生の `Maxima evaluation error`
  が返っていた——前回は「宣言してから束縛」の順しか測っていなかった
- `\vec{A} と \vec{B} の内積を求めて` → **`A_z*B_z+A_y*B_y+A_x*B_x`**。以前は `\vec{A}` に
  成分名を**発明**して `\vec{A}_x` を CAS へ渡し、生の `Maxima evaluation error` を返していた。
  英語の同義文はさらに手前で、素の `dot` が**微分表示の切替**に取られ `confirmed` を返していた
  （英語だけ `notation` が任意だった。日本語は `記法` を必須にしている）
- `\nabla \times \vec{A} と \vec{B} の外積を求めて` → **計算される**（A の回転と B の外積）。
  以前はオペランドが空白で切られ `\nabla` × `\times` を `completed` で返していた。
  `y = x^3` より後ろに在ることも読みどころで、∇ をオペランドとして読むと積の中に `nb_curl_*`
  が入る——COORD-NAME-BOUND の**新しい出口**なので、∇ 側のオペランドだけを守っている
- `\nabla \cdot (\nabla \times \vec{A})` → **0**。入れ子の読み手は Unicode と名前しか知らず、
  LaTeX の綴り——研究者が書き、系が表示する綴り——は数式として登録されるだけだった
  （`∇·(∇×A)` なら 0 を返していた）
- `A の回転の回転を求めて` → **回転を2回**。日本語は最初から正しく、英語の同義文には連鎖の鍵が
  無かったので、別名走査が操作の語を1つと読んで**1回だけ**適用していた
- `\nabla s` → **`[5*x^4,0,0]`**。`s = x^5` で値を与えた名前は、記法の割り込み口が宣言の種類
  だけを見ていたので登録され、`s の勾配を求めて` だけが計算されていた
- `s のラプラシアンを求めて` → **`20*x^3`**。以前は `20*x^3 = 20*x^3`——`=` で値を与えた
  スカラーはすべて、組み立てが右辺でなく等式を読んでいた
- `2 P の回転を求めて` → **`[0,0,2]`**。オペランドの判定が演算子の記号しか数学と数えず、
  並置——この系の乗算——の `2 P` を名前1つと扱っていた。`P` だけが式番号へ書き換わり、係数は
  捨てられた（回転・発散・勾配・ラプラシアン・ノルム・行列式の6操作、日英とも）
- `P + 2 B の発散を求めて` → **`2*'diff(B_z,z,1)+…`**。ベクトルの値を持つ名前が型 `scalar` と
  記録され、型の検査がその既定値を宣言として読んでいた。型は値から、式の構造から読む（ベクトルの和はベクトル）
- `\vec{P} \times \vec{A} の発散を求めて` → **計算される**。外積の2つ目の名前以降が落ちていた。
  Maxima の `~` はリストの上で評価されないので、成分は系自身の `nb_cross` で取る
- `2 (\vec{P} \times \vec{Q}) の発散を求めて` → **`2*y-2*x`**。外積**だけ**のオペランドは通って
  いたが、式の中に埋まると「いちばん外側の `~` で2つに割る」という文字列の近似では読めず、
  理由付きで断っていた（CROSS-PRODUCT-INSIDE-OPERAND）。掛かり方は構文の問題なので、
  書き換えは構文木の上でやる
- `\vec{P} \times \vec{Q} + \vec{A} の発散を求めて` → **`(P×Q) + A` の発散**。
  ここが読みどころで、**括弧を書かなくても外積が先**である。文字列で `~` を割ると
  `P × (Q + A)` になり、別の量を `completed` で返す
- `K を簡約して` → **`[3*x^4,0,-(3*x)]`**。`K = 3 (\vec{P} \times \vec{Q})` は書けて
  表示もできたが、**一般の操作に入ると生の `Maxima evaluation error`** が返っていた——
  生成器が書く `~` を Maxima は評価できない（リストでも原子でも、実測）。簡約・展開・
  因数分解・微分・積分・代入の6操作がそうで、∇ の3操作だけが通っていた（成分の読みを
  経由するから）。**CAS へ渡す綴りだけ**を `nb_cross` × 成分のリストへ差し替え、
  研究者の綴り（canonical）は `~` のままである
- `a x^2 を x で全微分して` → **`2*a*x`**。英語の対（`differentiate a x^2 in x totally`）は
  微分の枠が前置詞を**手書き**で持っていたので `in` に当たらず、欄が位置で埋まって
  `differentiate(expr='x^2', var='a')` の **`0`** を `completed` で返していた（6前置詞中3）。
  共有の表（`def_integral[en]` が読んでいるもの）へ移して解決
- `a x^2 を x で積分して` → **`(a*x^3)/3+C`**。日本語は最初から正しく、**英語の対**
  （`integrate a x^2 over x`）が壊れていた——英語の微分には inline の枠が在り積分には
  無かったので、被積分関数が式として登録されず、欄が位置で埋まって
  `integrate(expr='x^2', var='a')` になっていた（係数が変数に、研究者が書いた `x` は
  捨てられる）。**対にして置いてあるのは、日英で同じ値に落ちることが読みどころ**だから

- `Sz_i Sz_j の隣接和を 4 サイト 周期境界で展開して` → **4本のボンド**。ここは日本語が
  正しく、**英語の対**（`expand the neighbour sum of …`）が壊れていた——和の名詞の表が
  日英で違う問いに答えており（日本語は「和の名詞」、英語は `nearest neighbou?r` という
  **形容詞だけ**）、`隣接和` の鏡がどこにも無かった。1D では大きな声で落ちる
- `Sz_i Sz_j のハニカム格子 3x3 の格子和を展開して` → **9本のボンド**。英語の対は
  前置詞 `in` を使う（`… sum of Sz_i Sz_j in a 3x3 honeycomb lattice`）。**2D では
  同じ穴が黙る**——本体が読めないと**英文まるごとが被和関数**になり、
  `3 Sz(8) Sz(9) Expand a neighbor of over sum the …` が `completed` で返っていた。
  日本語の境界は文法（助詞と字種）、英語の境界は語彙だという非対称そのものである

- `y'^3` を `y'` で微分して → **`3*y'^2`**。プライム付きの名前が
  `canonical_variables` の識別子走査に入っておらず、`y'^3` の変数が `{y}` と
  読まれていた。すると**記号が1つしかない式**に対して「偏微分か全微分か判別
  できません」と訊き返す（日英とも）。パーサは最初から `'` を識別子の一部として
  扱っている（`f'(x)`）——走査だけが知らなかった。**この上の `E66 を t' で偏微分して`
  が `偏` を書いているのは、この欠陥を避けて書いたから**である
