**バックエンド:** Julia（Symbolics.jl スカラー代数）／**ドメイン:** 凝縮系物理（condensed_matter）。

### 物理的背景

フリー電子モデルのエネルギー分散（化学ポテンシャル $\mu$ を基準）：

$$\xi_k = \frac{\hbar^2 k^2}{2m} - \mu$$

フェルミ面条件 $\xi_k = 0$ を解くと、フェルミ波数：

$$k_F = \frac{\sqrt{2m\mu}}{\hbar}$$

これを $\xi_k$ に代入すると恒等的に $\xi_{k_F} = 0$ になることが確認できる。

さらに有効質量 $m^*$ は分散の2階微分から：

$$\frac{1}{m^*} = \frac{1}{\hbar^2} \frac{d^2 \xi_k}{dk^2} = \frac{1}{m}$$

（フリー電子では $m^* = m$、裸の質量に一致する）

## 確認された挙動・注意点

- **H-1 式評価（`evaluate_formula_with_latex` / `_cas_value_and_latex`）が Maxima 専用の
  `tex1(...)` コマンドをバックエンドに関係なく直接発行していた（根本バグ、修正済み）。**
  `notebook/engine.py` の両メソッドは、CAS 結果を得たあとに表示用 LaTeX を取得するため
  **もう一度** `self._adapter.execute(f"tex1({value})")` を明示的に発行していた。しかし
  Maxima・Julia のどちらの `adapter.execute()` も、**最初の実行ですでに** `.latex` フィールドに
  表示用 LaTeX を含めて返している（Maxima は `tex1()` をコマンドに自動同梱、Julia はドライバ側で
  同様の tex 出力を自動生成）ため、この2度目の呼び出しは常に冗長であり、かつ Julia バックエンドでは
  `tex1` という関数自体が存在しないため `Sym tex1 is not callable` エラーになっていた
  （例外は握りつぶされ、代わりに未整形の canonical がそのまま LaTeX として使われていた——
  `m_star = \hbar^2 / E7` の結果が `m_star = m`（整形なし）と表示される形で発覚）。
  修正：両メソッドとも、最初の `execute()` が返す `result.latex` を優先して使い、それが空の場合の
  みフォールバックとして明示的な `tex1(...)` 呼び出しを行うようにした（Backend Encapsulation
  Rule に沿い、バックエンド判定を一切追加せず、`.latex` フィールドの有無だけで分岐する）。
- **二次方程式の solve は SymPy フォールバック。** `Symbolics.solve_for` は線形専用
  （`AssertionError: islinear`）。`_nb_solve_equation` が失敗を検知して SymPy.solve に
  切り替え、`sqrt` を含む解を返す（詳細はメモリ `project_scalar_subst_pitfalls`）。

**確認日:** 2026-07-02（実機 Julia、generator 経由で全8ステップ完走。TeX 表記の
`\xi_k`・`\hbar`・`\mu` をそのまま入力）。
