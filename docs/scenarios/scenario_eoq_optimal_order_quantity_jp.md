# 実践ループ サンプルシナリオ：EOQ（経済的発注量）最適化 — 微分→solve→代入

実践ループ・シナリオメニュー **S-t（生産最適化）** の詳細化。総費用 $C(Q)=KD/Q+hQ/2$
（$Q$：発注量）を $Q$ で微分し $0$ とおいて最適発注量 $Q^*=\sqrt{2KD/h}$ を求め、
それを $C$ へ代入して最小総費用 $C(Q^*)$ を得る。**微分→solve→代入**という CAS が
最も映える定番の最適化パターン。

**バックエンド:** standard（Maxima）／**ドメイン:** 生産最適化（production_optimization）。

## モデルの背景

在庫管理の基本モデル（Economic Order Quantity）。年間需要 $D$、1回あたり発注費用 $K$、
単位あたり保管費用 $h$ のとき、総費用は

$$C(Q)=\frac{KD}{Q}+\frac{hQ}{2}$$

（発注費用 $KD/Q$：発注回数 $D/Q$ に発注費用 $K$ を乗じたもの、と保管費用 $hQ/2$：
平均在庫量 $Q/2$ に保管費用 $h$ を乗じたもの、の和）。$C$ を $Q$ で微分してゼロと
おくと最適発注量が求まる：

$$\frac{dC}{dQ}=-\frac{KD}{Q^2}+\frac{h}{2}=0 \;\Longrightarrow\; Q^*=\sqrt{\frac{2KD}{h}}.$$

$Q^*$ を $C(Q)$ に代入すると最小総費用 $C(Q^*)=\sqrt{2KDh}$ が得られる。

## セッション設定・記号

- モード **standard（Maxima）**、ドメイン **生産最適化**。
- $K,D,h,Q$ は自由変数（Maxima は宣言なしでシンボルとして扱う。未定義シンボル警告が出る
  場合があるが Maxima セッションでは処理をブロックしない）。

## 入力ステップ

### ステップ 1：総費用関数の定義（H-1）

```
C = K D / Q + h Q / 2
```

**期待する出力:** E1 として登録。$C=\dfrac{KD}{Q}+\dfrac{hQ}{2}$。

### ステップ 2：$Q$ で全微分

```
E1 を Q で全微分して
```

**期待する出力:** E2 $=\dfrac{dC}{dQ}=\dfrac{h}{2}-\dfrac{DK}{Q^2}$。

> **「全微分」の明示が必要:** $C$ は $Q$ のみに依存する1変数関数だが、システムは
> 偏微分／全微分のどちらか判別できないため明示を要求する（「Q で微分して」だけでは
> 「偏微分か全微分か判別できません」というエラーになる）。1変数関数の最適化では
> 常に「全微分」を使う。

### ステップ 3：$Q$ について解く（H-9・最適発注量）

```
E2 を Q について解いて
```

**期待する出力:** 2つの解が登録される：$Q=-\sqrt2\sqrt{DK/h}$（E3・物理的に無意味な負根）
と $Q^*=$ E4 $=\sqrt2\sqrt{DK/h}\;\left(=\sqrt{2DK/h}\right)$（正の発注量）。

### ステップ 4：$Q^*$ を総費用へ代入

```
E1 に E4 を代入して
```

**期待する出力:** E5 $=C(Q^*)=\dfrac{\sqrt2\,DK}{\sqrt{DK/h}}$。

## 確認ポイント

- 微分→解の2根のうち**正の根**（E4）が最適発注量 $Q^*$ に対応する（負根 E3 は
  数学的には正しいが経済的には意味を持たない — 発注量は正でなければならない）。
- $Q^*$ を $C(Q)$ へ代入した E5 は、根号の形は違えど $\sqrt{2DK/h}\cdot h/\sqrt{DK/h}
  \cdot\sqrt{DK/h}=\sqrt{2DKh}$ と数学的に同値（下記「確認された挙動」参照）。

## 確認された挙動・注意点

- **Maxima の根号は自動では約分されない。** E5 の canonical は
  `(sqrt(2)*D*K)/sqrt((D*K)/h)`（$=\sqrt2\,DK/\sqrt{DK/h}$）のままで、
  教科書的な $\sqrt{2KDh}$ の形には自動整理されない（`ratsimp`／簡約では根号の
  分母有理化までは行わない）。数値的・代数的には同値（両辺を2乗すると
  $2D^2K^2/(DK/h)=2DKh$ で一致）。教科書形に寄せたい場合は根号専用の簡約操作
  （`radical_simplify`、BP-2 参照）が必要で、現状ルールベースの NL トリガーは
  未実装（LLM 経路のみ）。
- **「微分して」だけでは動かない。** 1変数関数でも偏微分／全微分の指定が必須
  （曖昧さ回避のための設計）。「Q で全微分して」と明示する。
