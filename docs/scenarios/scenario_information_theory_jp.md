# 実践ループ サンプルシナリオ：情報理論の3量（エントロピー・KL・相互情報量）

シャノンエントロピー、Kullback–Leibler ダイバージェンス、相互情報量を、
**普通の総和として書いて**求める。

**バックエンド:** standard（Maxima）／**ドメイン:** 情報理論（information_theory）。

## SCENARIO-MACRO の第2号 —— 一般操作だけで書き直した

**2026-08-14 に、専用操作 `shannon_entropy` / `kl_divergence` / `mutual_information`
を使う形から書き直した**（open_items SCENARIO-MACRO）。3つとも中身は
`sum(...)` のテンプレート1本で、研究者が総和記号で書けるものだった。

**書き直しは到達可能性そのものを改善した。** 旧シナリオはこの3操作を `@op:` という
**生成器専用のバックドア**で叩いていた——`p` や `lower` のような「値そのもの」を取る
必要フィールドを、位置ベースのフィールド割り当てが復元できないため、**自然言語の
トリガーが存在しなかった**。つまり研究者が UI から到達できない操作が公開実例に載って
いた。総和記号で書けば、その問題は消える。

**この書き直しが掘り当てた silent-wrong（根治済み）:** 公平なサイコロのエントロピーを
$-\sum_{x=1}^{6}\frac16\log\frac16$ と書くと **0** が返っていた（正しくは $\log 6$）。
`\frac{a}{b}` が `(a)/(b)` という**1つの単位でない形**で出ていたため、
`\log \frac{1}{6}` が `log(1)/6` と読まれていた（`log(1)=0`）。族として同型:

| 入力 | 従来の意味 |
|---|---|
| `\log \frac{1}{6}` | `log(1)/6` = **0** |
| `\sin \frac{\pi}{2}` | `sin(π)/2` = **0**（正しくは 1） |
| `\log \frac{p(x)}{q(x)}` | `log(p)/q` —— まさに KL の被和項 |
| `\frac{a}{b}^2` | `a/b²` |
| `x^\frac{1}{2}` | `x/2`（正しくは $\sqrt x$） |

**マクロがこの欠陥を隠していた**：3つのテンプレートは `log` の呼び出しを自分で組み立てる
ので、研究者の書いた綴りが変換器に届かなかった。**起票が言う「測定器が壊れる」の実例**
であり、マクロを外した瞬間に出た。

## 手順と期待値

| 段 | 入力（自然言語 / 数式） | 結果 |
|---|---|---|
| 1 | `$H = -\sum_{x=1}^{6} \frac{1}{6}\log_2 \frac{1}{6}$` | 公平なサイコロのエントロピー（定義そのまま、bit 単位） |
| 2 | `E1 の右辺を計算して` | $\dfrac{\log 6}{\log 2}$ ＝ $\log_2 6 \approx 2.585$ bit |
| 3 | `$H_b = -p\log p - (1-p)\log(1-p)$` | ベルヌーイ分布のエントロピー |
| 4 | `E3 を p で微分して` | $\dfrac{dH_b}{dp}=\log(1-p)-\log p$ |
| 5 | `E4 を p について解いて` | $\log p=\log(1-p)$ —— **CAS はここで止まる**（下記） |
| 6 | `$D = p\log \frac{p}{q} + (1-p)\log \frac{1-p}{1-q}$` | ベルヌーイ間の KL ダイバージェンス |
| 7 | `E6 の q に p を代入して` | $D=0$ —— **$D(p\Vert p)=0$ という性質の確認**になっている |
| 8 | `$I = \sum_{x=1}^{2}\sum_{y=1}^{2} p_{xy}(x,y)\log \frac{p_{xy}(x,y)}{p_x(x) p_y(y)}$` | 相互情報量の定義（二重和） |
| 9 | `$I_0 = \sum_{x=1}^{2}\sum_{y=1}^{2} p_x(x) p_y(y)\log \frac{p_x(x) p_y(y)}{p_x(x) p_y(y)}$` | 独立な場合（$p_{xy}=p_xp_y$）を代入した形 |
| 10 | `E9 の右辺を計算して` | $0$ —— **独立なら相互情報量は 0** |

## 確認された挙動・注意点

- **段 5 で CAS は $p=1/2$ まで行かない。** 返るのは $\log p=\log(1-p)$ で、
  対数の単射性を使う一歩を Maxima は踏まない。**これは正しい振る舞い**——
  システムが「たぶん $p=1/2$」と補うのではなく、成り立つ条件をそのまま返している。
  研究者はここから $p=1/2$ を読む。
- **段 7 と段 10 は定義の評価ではなく「性質の確認」になっている。** 旧シナリオの3段は
  どれも「定義に値を入れて表示する」だけだったが、一般操作で書くと `differentiate` や
  `substitute` と自然につながり、$D(p\Vert p)=0$ や「独立 ⇒ $I=0$」が**計算として**出る。
- **bit 単位で書けるようになった（2026-08-16）。** それまで `\log_2 6` は
  **`log(2) * 6`——2の対数×6** になっていた（≈4.16、正しくは ≈2.585）。未定義記号では
  なく**妥当な Maxima 式で値だけが違う**ので、エラーも警告も出ない silent-wrong だった。
  **このシナリオが nat 単位だったのはそのためであって選択ではなく**、回避策の
  $\log 6/\log 2$ をここに書かなかったのは、置けば直った後も誰も書き換えず恒久化する
  からである。いまは底つきの綴りがそのまま通る。
- **結果の表示は $\frac{\log 6}{\log 2}$ で、$\log_2 6$ には戻らない。** 底の変換は
  書き換え（`log(X)/log(b)`）であり、CAS が返すのはその形なので、`tex1` もその形を出す。
  **誤りではなく綴りの違い**で、表示された式はそのまま打ち直して計算できる（往復は
  閉じている）。$\log_2$ の形で読みたい場合は表示ブリッジが要る。
- **総和記号そのものは正しく働く**（B-10）。`\sum_{x=1}^{6}x` は 21、
  `\sum_{x=1}^{3}x^2` は 14 と実測済み。壊れていたのは被和項の分数だけだった。
