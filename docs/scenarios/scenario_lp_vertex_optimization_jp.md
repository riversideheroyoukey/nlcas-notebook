# 実践ループ サンプルシナリオ：2変数線形計画の頂点最適化（有効制約の交点 → 目的関数評価）

実践ループ・シナリオメニュー **S-s（経営工学・OR）** の詳細化。2変数の線形計画問題
$\max z=c_1x+c_2y$（制約 $a_1x+b_1y\le d_1,\ a_2x+b_2y\le d_2,\ x,y\ge0$）について、
**有効制約2本の交点（頂点）を `solve_system` で求め**、その頂点で目的関数 $z$ を評価する
（線形計画の最適解は実行可能領域の頂点で達成される、という標準的な事実に基づく）。

**バックエンド:** standard（Maxima）／**ドメイン:** 経営工学・OR（operations_research）。

> 連立 solve と代入だけで完結する最小サンプル。操作はすべてルールベース（LLM 不要）で
> 解釈される。

## モデルの背景

$$\max z=c_1x+c_2y \quad \text{s.t. } a_1x+b_1y\le d_1,\ a_2x+b_2y\le d_2,\ x,y\ge0.$$

最適解は実行可能領域の頂点（＝いずれかの制約が等号で成立する点）で達成される。
有効制約2本を等式として連立させ、その交点（頂点）の座標を求め、目的関数へ代入する：

$$a_1x+b_1y=d_1,\quad a_2x+b_2y=d_2 \;\Longrightarrow\; (x^*,y^*) \;\Longrightarrow\; z^*=c_1x^*+c_2y^*.$$

Cramer の公式に一致する：$x^*=\dfrac{d_1b_2-d_2b_1}{a_1b_2-a_2b_1}$、
$y^*=\dfrac{a_1d_2-a_2d_1}{a_1b_2-a_2b_1}$。

## セッション設定・記号

- モード **standard（Maxima）**、ドメイン **経営工学・OR**。
- $a_1,b_1,c_1,d_1,a_2,b_2,c_2,d_2$ は係数（実数）、$x,y$ は決定変数（自由変数、宣言不要）。
- **係数は添字付き記号（`a_1` 等）のため、使用前に「実数とする」と明示宣言する** — 未宣言のまま
  演算のソースに使うと `IndexedSymbol`（添字アクセス）として扱われる設計（doc の
  「Undeclared subscript in an OPERATION → index」規則）のため。宣言すれば通常の記号として
  解決される。
- **有効制約は「= 0」の形（`... - d_1 = 0`）で入力する** — `... = d_1`（RHS が裸の数値でない
  H-1 名前付き定義）の形で入れると、複合 LHS（`a_1 x + b_1 y` のような和）の場合に
  H-1 の RHS-only canonical 格納の対象になり、`solve_system` が LHS を復元できず空の解
  `[]` になる（下記「確認された挙動・注意点」参照）。

## 入力ステップ

### ステップ 1：係数を実数として宣言

```
a_1, b_1, c_1, d_1, a_2, b_2, c_2, d_2 を実数とする
```

**期待する出力:** 8個の係数が実数スカラーとして `SymbolContext` に登録される。

### ステップ 2：目的関数の定義（H-1）

```
z = c_1 x + c_2 y
```

**期待する出力:** E1 として登録。$z=c_1x+c_2y$。

### ステップ 3・4：有効制約2本（= 0 形）

```
a_1 x + b_1 y - d_1 = 0
a_2 x + b_2 y - d_2 = 0
```

**期待する出力:** E2 $=a_1x+b_1y-d_1=0$、E3 $=a_2x+b_2y-d_2=0$。

### ステップ 5：連立方程式を解く（H-9・頂点座標）

```
E2 と E3 の連立方程式を x と y について解いて
```

**期待する出力:** 2つの解が個別の式として登録される：

$$x^*=E4=-\frac{b_2d_1-b_1d_2}{a_2b_1-a_1b_2}\;\left(=\frac{d_1b_2-d_2b_1}{a_1b_2-a_2b_1}\right),
\qquad y^*=E5=\frac{a_2d_1-a_1d_2}{a_2b_1-a_1b_2}.$$

Cramer の公式と一致する（$E5$ は生の解集合ブラケットで内部的に消費され、表には出ない）。

### ステップ 6：$x^*$ を目的関数へ代入

```
E1 に E4 を代入して
```

**期待する出力:** E6 $=z=\dfrac{(a_1b_2-a_2b_1)c_2y-b_1c_1d_2+b_2c_1d_1}{a_1b_2-a_2b_1}$（$y$ が残る中間形）。

### ステップ 7：$y^*$ も代入 → 頂点での目的関数値

```
E6 に E5 を代入して
```

**期待する出力:** E7 $=z^*=\dfrac{(a_1c_2-b_1c_1)d_2+(b_2c_1-a_2c_2)d_1}{a_1b_2-a_2b_1}$。

展開すると $z^*=\dfrac{c_1(b_2d_1-b_1d_2)+c_2(a_1d_2-a_2d_1)}{a_1b_2-a_2b_1}$ となり、
$z^*=c_1x^*+c_2y^*$（頂点での目的関数評価）と一致する。

## 確認ポイント

- 有効制約2本の交点（頂点）が `solve_system` で正しく求まり、Cramer の公式と一致する。
- 求めた頂点座標を目的関数へ**2回連続で代入**（$x^*$→$y^*$）しても、係数記号が
  壊れずに保たれる（下記の SUBST-DIGIT-SUB 参照）。

## 確認された挙動・注意点

- **H-1 の RHS-only canonical 格納と `solve_system` の相性（設計どおりの回避策）。**
  制約を `a_1 x + b_1 y = d_1`（RHS が裸の数値でない）の形で入力すると、H-1 の
  「名前付き定義」パスに入り canonical が RHS のみ（`d_1`）になる。複合 LHS
  （`a_1 x + b_1 y`）は `_SIMPLE_LHS_RE` の対象外で `expr_lookup` へ復元されず、
  `solve_system` は空の解 `[]` を返す。制約を「`... = 0`」の形（RHS が裸の数値 `0`）で
  書けば H-1 自体がスキップされ（guard 8：RHS が裸の数値のときは Maxima 方程式として
  扱う）、canonical に完全な等式が保存されるので問題は起きない——本シナリオはこの形を採用。
- **SUBST-DIGIT-SUB（本シナリオで発見・根治済み・2026-07-05）。** 上記の回避策を
  適用しても、solve 結果（`a_1`, `b_2` などの添字付き係数記号を含む式）を
  別の式へ`代入して`すると、**添字が数字だけの記号（`a_1`, `b_2` 等）が
  `a(1)`, `b(2)` のような関数呼び出し形へ化ける**（表示だけでなく `canonical` 自体が
  壊れる＝数学的に別物になる）バグを発見した。宣言済み（実数と明示declare済み）の
  記号でも再現した。原因は `notebook/runtime/semantic_resolver.py` の
  `build_sub_name`（Subscript ノードを結合済みシンボル名として登録簿照合するヘルパー）が
  `Symbol` サブスクリプトのみを処理し、**数字サブスクリプトが `Number` ノードとして
  トークン化される**ケースを扱っていなかったため、登録簿照合が常に失敗し
  `IndexedSymbol`（関数呼び出し形）へフォールスルーしていたこと。`Number` ノードの
  ハンドリングを追加して根治（`tests/test_digit_subscript_resolution.py`）。
  影響範囲は本シナリオに限らず、「solve 結果を他の式へ代入する」という一般操作
  パターン全般（数字添字の係数を使うあらゆるシナリオ）。
- **付随して発見（別課題・未修正）:** 英語入力での複数記号一括宣言
  `"Declare a_1, b_1, ..., d_2 as real."` は、リストの**先頭と末尾の記号しか
  登録されない**（中間の記号がすべて無視される）カンマリスト解析のバグがある。
  本シナリオの英語版（`_en.md`）はこれを踏まないよう、記号ごとに個別の宣言文
  （`"a_1 is a real number."` 等）を用いる形で回避した。open_items.md に別課題として
  登録。
