# 実践ループ サンプルシナリオ：横磁場イジングモデルと平均場近似（Julia バックエンド検証）

> （2026-07-02: 横磁場イジングモデルの Julia バックエンド実用検証（探索的ログ）を、
> 一般操作（スピン演算子宣言・H-1・交換子・演算子置換）のみで再構成した。）

**バックエンド:** Julia（QuantumAlgebra.jl）／**ドメイン:** スピン系（spin_systems）。

### 物理的背景

2サイト横磁場イジングモデル：

$$H = -J\, S^z_1 S^z_2 - \Gamma \left( S^x_1 + S^x_2 \right)$$

SU(2) 交換関係より

$$[H,\, S^z_1] = -\Gamma\, [S^x_1,\, S^z_1] = 2i\Gamma\, S^y_1$$

サイト2のスピンを平均場（c-数）$m_z=\langle S^z\rangle$ に置き換える平均場近似：

$$S^z_2 \;\to\; m_z \quad\Longrightarrow\quad
H_{\rm MF} = -J\, m_z\, S^z_1 - \Gamma\left(S^x_1 + S^x_2\right)$$

---

### 一般操作での組み立て方（★このシナリオの肝）

1. $S$ は「スピン演算子として定義して」で宣言する（`Sx`,`Sy`,`Sz` が使用可能になる）。
2. $H$ は H-1 の等式形式で、成分表記 `Sz_1`（サフィックス添字スタイル）を使って直接登録する。
3. 交換子は式入力欄に `[E_n, Sz_1]` の形でそのまま入力する（一般操作としてブラケット記法が
   交換子に解決される）。
4. 平均場近似（特定サイトの演算子を c-数に置換）は「$E_n$ の $S^z_2$ を $m_z$ に置き換えて」
   という一般の代入文で表現する。$S^z_2$ のように**添字が整数**（サイトラベル）の場合は
   自動的に「そのサイトのみを置換する」（exact filter）と判定される。

## 確認された挙動・注意点

- **一般代入の短絡ルールが演算子のサイト添字を無視し、平均場近似が全サイト一律置換に
  なっていた（根本バグ、修正済み）。** `ui/interpret_pipeline.py` の「$E_n$ の $A$ を $B$ に
  置き換えて」という**汎用**代入ショートサーキット（コメント 2e4）は、LHS がスカラーか
  演算子かを区別せず一律に汎用 `substitute` 操作へディスパッチしていた。スカラーには
  正しいが、`S^z_2` のような**サイト添字つき量子演算子**に対しても同じ経路を通ると、
  Julia バックエンドはこれを「演算子全体の恒等置換」（`_nb_operator_identity`、添字非依存）
  として処理し、`mz` を**サイトごとの関数**として呼び出そうとして
  `Sym mz is not callable` エラーになっていた（＝そもそも失敗するため気づきやすいが、
  仮に `mz` がサイト関数として宣言されていた場合は**全サイトの $S^z$ が同じ $mz(i)$ に
  置換される**という、平均場近似の意図（特定サイトのみ）に反する結果を黙って返しうる
  設計だった）。修正：LHS が `SymbolContext` に演算子（`kind=="operator"`）として
  登録済みのシンボル名で始まる場合はこの汎用ルールをスキップし、添字を尊重する
  バックエンド固有の `operator_substitute`（整数添字＝サイト固有置換の自動判定つき）に
  処理を委ねるガードを追加（`ui/interpret_pipeline.py`）。BCS ハミルトニアン
  シナリオで見つけた「汎用代入インターセプトが添字つき演算子代入を横取りする」バグ
  （SUBST-DOUBLE-SHADOW）と同じ系統の問題。

**確認日:** 2026-07-02（実機 Julia、generator 経由で全6ステップ完走）。
